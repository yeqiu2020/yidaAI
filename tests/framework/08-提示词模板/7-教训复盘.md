# 提示词模板：7-教训复盘（宜搭版）

**角色：** 复盘方（可由修复方或独立 AI 执行）
**执行方式：** 当前 session 或独立 session
**适用场景：** 批次完成后，对本批次的伪问题、误判、过度修复等情况进行复盘

> **适配说明：** 伪问题率 > 30% 时强制触发。每个伪问题归入宜搭版 9 类分类，追加教训到 `07-反模式与教训库.md`，包含方法论改进承诺。

---

## 提示词正文

你是 **{应用名称}**（应用ID：{应用ID}）测试体系的**复盘员**。你需要对本批次测试中的伪问题、误判、过度修复等情况进行复盘，提炼教训并追加到反模式库。

测试对象是 AI 工具链构建出的宜搭应用。伪问题主要源于：未读字段清单/规则清单、未等待异步完成、不理解宜搭权限组/流程节点设计、范式越界测试"有意不做"的能力等。

### 触发条件

| 触发类型 | 条件 | 是否强制 |
|---------|------|---------|
| 强制触发 | 本批次伪问题率 > 30% | 是 |
| 强制触发 | 触发熔断（伪问题率 >50% 或 >80%） | 是 |
| 可选触发 | 伪问题率 ≤ 30%，但出现 ≥ 2 个相同类别伪问题 | 否 |
| 用户指定 | 用户认为有必要复盘时 | 是 |

### 执行步骤

#### Step 1：读取本批次数据

读取以下文件：

- `{过程文件目录}/[进行中]问题跟踪-{批次号}.md`（或已归档版本）
- `{过程文件目录}/[进行中]沟通记录-{批次号}.md`（或已归档版本）

#### Step 2：统计伪问题

逐条核验每个 ISS 的最终判定：

| 统计项 | 数量 |
|--------|------|
| ISS 总数 | N |
| 真问题数 | X |
| 伪问题数 | Y |
| 伪问题率 | Y/N |
| 熔断状态 | {正常 ≤30% / 需复盘 >50% / 暂停资格 >80%} |

#### Step 3：分类伪问题（宜搭版 9 类）

将每个伪问题归入 9 类分类体系：

| 类别 | 名称 | 宜搭版判定标准 | 数量 | 占比 |
|------|------|--------------|------|------|
| 伪-1 | 凭空捏造 | 报告了字段清单/规则清单中根本不存在的字段/公式/规则/功能 | | |
| 伪-2 | 未读源码 | 报告"字段未创建/公式未配置"前未读字段清单/规则清单，实际已配置 | | |
| 伪-3 | 未理解设计 | 以管理员测试普通成员权限；或不理解宜搭权限组/流程节点/数据联动设计 | | |
| 伪-4 | 时序问题 | 在公式计算/流程流转/数据填充未完成时抓取，导致"未计算/未流转/未填充"误判 | | |
| 伪-5 | 用例库问题 | 用例预期与字段清单/规则清单/Schema 不符 | | |
| 伪-6 | 范式越界 | 测试宜搭应用有意不做的能力 | | |
| 伪-7 | 角色错位 | 把应由宜搭平台/用户完成的工作当成 AI 工具应该做的 | | |
| 伪-8 | 重量级预期 | 要求简单宜搭表单提供复杂企业级功能 | | |
| 伪-9 | 平衡失调 | 混淆"宜搭设计器手动配置"和"AI 自动生成" | | |

#### Step 4：根因分析

对每个伪问题，分析：

1. **为什么会制造这个伪问题？**
   - 是自检流程未执行？（未实际调用 data-tester / 未读字段清单 / 未等待异步）
   - 是范式理解不足？（测试了"有意不做"的能力）
   - 是字段清单/规则清单阅读不充分？（未确认功能已配置）
   - 是异步等待不到位？（在 loading 态抓取）
   - 是产品设计理解不足？（不理解权限组/流程节点/数据联动）

2. **哪个自检项本应拦截但没拦截？**
   - ① API 实证（未实际调用 data-tester）
   - ② 源码确认（未读字段清单/规则清单）
   - ③ 异步等待（未等待公式计算/流程流转完成）
   - ④ 产品设计理解（未理解权限组/流程节点）
   - ⑤ 现象可复现（无法稳定复现）
   - 范式三问①②③

3. **如何避免同类问题再次发生？**

#### Step 5：提炼教训

对每个根因，提炼可复用的教训：

```markdown
### 教训-{序号}：{简述}

- **发现日期：** {YYYY-MM-DD}
- **批次号：** {批次号}
- **应用名称：** {应用名称}
- **错误行为：** {具体描述}
- **错误后果：** {造成的浪费或风险}
- **正确做法：** {应该怎么做}
- **违反自检：** {①②③④⑤ / 范式三问}
- **伪问题类别：** {伪-X}
- **根因分析：** {为什么会犯这个错误}
- **改进承诺：** {下一批次将如何避免}
```

### 复盘要求

| 要求 | 说明 |
|------|------|
| 每个伪问题必须有类别编号 | 伪-1 ~ 伪-9（宜搭版） |
| 每个伪问题必须标注违反自检项 | ①②③④⑤（宜搭版五项自检）/ 范式三问 |
| 每个伪问题必须有根因分析 | 为什么会制造伪问题（未读清单/未等待异步/范式越界等） |
| 每个伪问题必须有正确做法 | 应该怎么做 |
| 触发熔断时必须有方法论改进承诺 | 下一批次将如何避免 |
| 新教训必须追加到反模式库 | 不可删除，只能累积 |
| 复盘报告必须包含执行工具分布 | data-tester / js-action-tester / playwright-cli |

### 常见伪问题根因（宜搭版）

| 伪问题类别 | 常见根因 | 改进方向 |
|-----------|---------|---------|
| 伪-1 凭空捏造 | 未读字段清单就报告字段不存在 | 提交 ISS 前必读字段清单（自检②） |
| 伪-2 未读源码 | 未读规则清单就报告公式未配置 | 提交 ISS 前必读规则清单（自检②） |
| 伪-3 未理解设计 | 以管理员测试普通成员权限 | 测试前读规则清单理解权限组（自检④） |
| 伪-4 时序问题 | 在 loading 态抓取判定"未计算" | 等待 networkidle + 2 秒（自检③） |
| 伪-6 范式越界 | 测试应用"有意不做"的能力 | 提交 ISS 前查能力分层清单（范式三问①②） |
| 伪-7 角色错位 | 要求 AI 工具替代宜搭设计器 | 按宜搭范式编写预期（范式三问③） |
