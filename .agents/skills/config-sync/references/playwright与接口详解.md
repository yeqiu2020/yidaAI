## Playwright同步表单列表（推荐）

### 背景

宜搭平台的 `getFormList.json` API 经常返回404错误或无法访问，导致无法通过API获取表单列表。本方案使用 **Playwright** 模拟真实用户操作，从宜搭后台「部署运维」页面提取表单列表，更加稳定可靠。

### 工作原理

```
宜搭工作台 → 我的应用 → {应用名称} → 应用设置 → 部署运维 → 提取表单列表
```

**核心流程**：
1. 使用已有Cookie登录态（避免重复扫码）
2. 访问应用管理后台 `/{appId}/admin`
3. 点击"应用设置"菜单
4. 点击"部署运维"子菜单
5. 等待页面加载表格数据
6. 从DOM中提取表单列表（页面名称、类型、页面编码、流程Code）

### 功能特性

- ✅ **自动登录检测**：如果Cookie失效，会提示扫码登录
- ✅ **智能差异对比**：自动对比本地和线上表单列表，显示新增/删除的表单
- ✅ **自动删除本地多余表单**：删除平台已删除但本地仍存在的表单文件夹
- ✅ **自动创建新增表单**：创建平台新增但本地没有的表单文件夹
- ✅ **更新系统配置清单**：自动更新表单ID清单、统计信息、快速访问链接
- ✅ **验证应用编码**：核对页面上的应用编码与期望的是否一致
- ✅ **可视化模式**：显示浏览器窗口，高亮操作元素，彩色输出
- ✅ **数据导出**：生成 `forms_deploy_list.json` 供后续处理

### 稳定性评估

| 维度 | API方式 | Playwright方式 |
|-----|-------|---------------|
| 成功率 | ❌ 低（经常404） | ✅ 高 |
| 稳定性 | ❌ 不稳定（API变更） | ✅ 稳定（跟随页面） |
| 数据完整性 | ⚠️ 可能缺少流程Code | ✅ 完整（含流程Code） |
| 维护成本 | 高（API经常变更） | 低（页面结构稳定） |
| 执行速度 | 快 | 中等（需等待页面加载） |
| 本地文件夹同步 | ❌ 不支持 | ✅ 自动删除/创建 |

**结论**：Playwright方式更加稳定可靠，推荐作为首选方案。

## 核心API接口

### 1. 同步配置（主入口）

```javascript
// sync_config.js
syncConfig(options) -> {
  "appId": "APP_XXX",
  "appName": "应用名称",
  "forms": [...],
  "outputDir": "输出目录",
  "success": true,
  "message": "同步完成"
}
```

参数:
- `appId` (可选): 宜搭应用ID，不提供则从系统配置清单读取
- `outputDir` (可选): 输出目录，默认为 `./`
- `formDirs` (可选): 表单文件夹映射，用于确定组件ID清单输出位置

### 2. 获取应用信息

```javascript
fetchAppInfo(appId) -> {
  "appName": "应用名称",
  "appId": "APP_XXX",
  "baseUrl": "https://xxx.aliwork.com"
}
```

### 3. 获取表单列表

```javascript
fetchFormList(appId) -> [
  {
    "index": 1,
    "name": "表单名称",
    "type": "表单|流程",
    "formUuid": "FORM-XXX",
    "processCode": "TPROC-XXX"  // 仅流程表单
  }
]
```

### 4. 获取组件ID

```javascript
fetchComponents(appId, formUuid) -> [
  {
    "componentName": "TextField",
    "fieldName": "字段名称",
    "fieldId": "textField_xxx"
  }
]
```

## 编程调用

```javascript
const { syncConfig } = require('./scripts/sync_config');

// 方式1：从现有清单读取应用ID（自动检测是否已有分组）
const result = await syncConfig({
  outputDir: './进销存管理'
});

// 方式2：指定应用ID
const result = await syncConfig({
  appId: 'APP_YA1204PFH4K3MRARR1E3',
  outputDir: './进销存管理'
});

// 方式3：AI智能分组（已有分组时不创建，没有时自动创建）
const result = await syncConfig({
  appId: 'APP_XXX',
  outputDir: './项目名称',
  smartGroup: true  // 强制使用智能分组
});

// 方式4：指定表单目录映射
const result = await syncConfig({
  appId: 'APP_XXX',
  outputDir: './进销存管理',
  formDirs: {
    '产品信息': './02基础信息/产品信息「普通表单」',
    '库存信息': './03库存管理/库存信息「普通表单」'
  }
});
```

### 被其他Skill调用

```javascript
// 在form_creator中调用
const { syncConfig } = require('../config-sync/scripts/sync_config');

// 创建应用后自动同步
await syncConfig({
  appId: createdApp.appId,
  outputDir: projectDir,
  formDirs: formDirectoryMap
});
```

## 完整工作流程图

### 新建应用流程
```
1. 用户：创建一个项目
   ↓
2. form_creator：生成字段清单 → 生成原型 → 生成JSON
   ↓
3. form_creator：创建宜搭应用和表单
   ↓
4. form_creator：自动写入系统配置清单（包含应用ID和表单UUID）
   ↓
5. 用户：同步配置信息
   ↓
6. config-sync：从系统配置清单读取应用ID和表单UUID
   ↓
7. config-sync：同步表单结构和组件ID
   ↓
8. 完成：系统配置清单 + 组件ID清单 都已就绪
```

### 已有应用流程
```
1. 用户：同步【XXX】的配置信息，应用ID是 APP_XXX
   ↓
2. config-sync：使用指定应用ID获取表单列表
   ↓
3. config-sync：更新系统配置清单（写入应用ID和表单UUID）
   ↓
4. config-sync：同步表单结构和组件ID
   ↓
5. 完成：系统配置清单 + 组件ID清单 都已就绪
```

### 表单列表同步流程（v3.4.0新增）
```
1. 用户：同步表单列表
   ↓
2. config-sync：使用Playwright访问宜搭后台
   ↓
3. config-sync：获取平台表单列表
   ↓
4. config-sync：扫描本地表单文件夹
   ↓
5. config-sync：对比差异（新增/删除/不变）
   ↓
6. config-sync：删除本地多余的表单文件夹
   ↓
7. config-sync：创建新增表单的文件夹
   ↓
8. config-sync：更新系统配置清单.md
   ↓
9. 完成：本地与平台完全一致
```
