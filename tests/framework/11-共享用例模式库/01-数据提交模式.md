# 数据提交模式

> 能力域：数据提交
> 执行工具：data-tester
> 测试层级：宜搭 API

---

## P01：普通表单数据提交成功

**场景：** 向普通表单 {表单名称} 提交一条完整数据记录

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 数据提交 |

**占位符：**
- `{表单名称}` — 目标表单名（如"产品信息"）
- `{应用ID}` — APP_XXXXX
- `{表单UUID}` — FORM-XXXXX
- `{测试数据}` — AI 根据字段清单生成的完整 JSON 数据

**前置条件：**
- 登录态有效（Cookie 未过期）
- {表单名称} 已存在且可访问
- 关联表单（如有）已有数据

**操作步骤：**
1. AI 读取 {表单名称} 的字段清单，生成 {测试数据}（所有字段必须有值，除宜搭 API 不支持的6种类型）
2. 调用 `submitAIGeneratedData` 提交到宜搭
3. 记录 API 返回的 formInstId

**断言：**
- API 返回 `success: true`
- 返回的 formInstId 非空

**产品依据：** data-tester SKILL.md "场景1：AI生成数据并提交"

## P02：数据提交后字段值回查一致

**场景：** 提交数据后通过 API 回查，所有字段值与提交一致

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 数据提交 |

**占位符：**
- 同 P01

**前置条件：**
- P01 已通过（数据已成功提交）

**操作步骤：**
1. 使用 `searchFormDatas.json` 查询刚提交的记录
2. 逐字段对比提交值与回查值

**断言：**
- 每个字段（除宜搭 API 不支持的6种类型）的回查值与提交值一致
- 无空字段（发现空字段必须排查原因）

**产品依据：** data-tester SKILL.md "【强制】提交后回查验证"

## P03：系统字段（创建人/创建时间）写入验证

**场景：** 验证系统字段"创建人"和"创建时间"在提交后正确写入

| 属性 | 值 |
|------|-----|
| 优先级 | P1 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 数据提交 |

**占位符：**
- `{表单名称}` — 目标表单名
- `{创建人字段名}` — 如"创建人"/"录入人"
- `{创建时间字段名}` — 如"创建时间"/"录入时间"
- `{预期用户ID}` — 当前登录用户 ID
- `{预期时间段}` — 提交时间前后合理范围

**前置条件：**
- 表单中存在"创建人"和"创建时间"字段（自动识别名称含"创建人/创建者/录入人"和"创建时间/创建日期/录入时间"）

**操作步骤：**
1. 提交数据时为 {创建人字段名} 传入当前用户 ID，{创建时间字段名} 传入当前时间
2. 回查该记录，读取这两个字段的值

**断言：**
- {创建人字段名} 的值 = {预期用户ID}
- {创建时间字段名} 的值在 {预期时间段} 范围内

**特别说明：**
- 通过 API 提交时默认值公式（`USER()`、`TIMESTAMP(TODAY())`）不会自动触发，必须 AI 手动传入值
- 如果回查发现这两个字段已有值（可能是公式触发），可以跳过；如果为空，说明数据缺失

**产品依据：** data-tester SKILL.md v3.1.5 "关于默认值公式与API提交的关系"；form_creator SKILL.md "EmployeeField/DateField 默认公式"
