## ⚠️ 重要规则（必须遵守）

### 规则1：只生成提示词，不生成代码

**当用户明确要求"生成提示词"时，绝对禁止直接生成代码实现。**

- ✅ 只生成纯提示词文件（包含需求描述、字段ID清单、功能要求等），状态标记"⏳ 待生成"，等待用户确认后再生成代码
- ❌ 严禁在提示词文件中包含代码实现、自作主张生成代码文件、在对话框输出代码内容

### 规则2：区分"提示词"和"代码/公式"

| 用户指令        | 系统行为                                 |
| --------------- | ---------------------------------------- |
| "生成提示词"    | 本Skill生成提示词文件，不包含代码       |
| "生成代码"      | → 调用 code-expert 生成代码实现          |
| "编写/创建代码" | → 调用 code-expert 生成代码实现          |
| "帮我写公式"    | → 调用 formula-generator 生成公式实现    |
| "写提示词"      | 本Skill生成提示词文件                   |

### 规则3：必须使用模板（极其重要）

**生成提示词时，必须严格按照模板文件中的格式，绝对禁止自由发挥。**

模板文件位置（本技能目录内）：

- 公式类：`templates/formula-templates.md`
- 代码类：`templates/code-templates.md`

**必须包含的标准字段：**

1. 【应用场景】：明确标识类型（表单公式/表单动作代码/跨表单代码等）
2. 【需求描述】：详细描述功能需求、业务逻辑、触发时机
3. 【字段清单】：使用表格展示字段名称、字段ID、字段类型、说明
4. 【状态】：⏳ 待生成

**模板选择规则：**

| 需求类型       | 使用模板                                                                  |
| -------------- | ------------------------------------------------------------------------- |
| 表单字段公式   | formula-templates.md → 表单公式模板 → 根据场景选择子模板                |
| 报表公式       | formula-templates.md → 报表公式模板                                      |
| 自动化公式     | formula-templates.md → 自动化公式模板                                    |
| 单表操作代码   | code-templates.md → 表单动作代码模板 → 单表操作类/字段联动类/子表操作类 |
| 跨表单代码     | code-templates.md → 跨表单代码模板 → 跨表查询/校验/写入类               |
| 字段校验代码   | code-templates.md → 字段校验代码模板                                     |
| 自定义页面代码 | code-templates.md → 自定义页面代码模板                                   |
| 集成自动化代码 | code-templates.md → 集成自动化代码模板                                   |

**绝对禁止：**

- ❌ 不查看模板，自由发挥格式
- ❌ 遗漏【应用场景】【字段清单】【状态】等标准字段
- ❌ 使用非表格形式展示字段信息
- ❌ 在提示词文件中包含JavaScript代码块、公式代码、实现逻辑代码

## 功能概述

本 Skill 将自然语言需求转换为规范的宜搭提示词文件：简化用户输入（无需手动查ID）、自动从系统配置清单读取准确ID、统一提示词格式集中存储、每个提示词后强制添加字段ID核对警告。

## 工作流程

```
用户描述需求
    ↓
识别需求类型（公式/代码）
    ↓
读取系统配置清单 → 获取应用ID、表单UUID
    ↓
读取组件ID清单 → 获取字段ID
    ↓
匹配提示词模板 → 生成规范提示词
    ↓
保存到表单目录/功能提示词.md
    ↓
展示给用户确认
    ↓
用户确认后调用代码/公式生成 Skill
```

## 触发词

当用户说出以下任意一种表达时，自动触发本 Skill：

- "帮我设计一个提示词"、"生成提示词"、"创建提示词"、"编写提示词"
- "需要提示词"、"写提示词"、"设计提示词"、"做一个提示词"

## 使用场景

- **场景1（公式提示词）**："产品信息表，计算开始日期和结束日期的小时差" → 识别表单与需求类型（表单公式-日期计算）→ 读取组件ID清单找到日期字段 → 生成提示词并保存
- **场景2（代码提示词）**："采购入库单，提交时校验库存是否充足" → 识别表单与需求类型（跨表单代码-库存校验）→ 读取系统配置获取关联表单信息 → 生成提示词并保存

## 提示词分类体系（速查）

| 大类 | 类型 |
|------|------|
| 公式类 | 表单公式、报表公式、自动化公式、审批公式 |
| 代码类 | 表单动作代码、跨表单代码、字段校验代码、自定义页面代码、自动化脚本 |
| 表单类 | 字段联动、子表操作、表单布局、数据初始化 |
| 流程类 | 流程设计、条件分支、节点配置 |

### 文件位置（v2.3.0更新 - 每个公式/代码独立文件，序号命名，与实现文件一一对应）

| 文件类型 | 路径与命名格式 | 示例 |
|----------|----------------|------|
| 公式提示词 | `{项目目录}/{表单目录}/公式/{序号}.{公式名称}提示词.md` | `1.成员合并公式提示词.md` |
| 公式JSON | `{项目目录}/{表单目录}/公式/{序号}.{公式名称}.json` | `1.成员合并公式.json` |
| 代码提示词 | `{项目目录}/{表单目录}/代码/{序号}.{代码名称}提示词.md` | `1.库存校验提示词.md` |
| 代码JS文件 | `{项目目录}/{表单目录}/代码/{序号}.{代码名称}.js` | `1.库存校验.js` |

提示词文件内部的完整 markdown 骨架（提示词列表/统计信息/使用说明等区块）见 [references/output-file-structure.md](references/output-file-structure.md)。要点：

- 每条提示词必须含【状态】(⏳ 待生成/🔄 生成中/✅ 已完成/❌ 失败)、【创建时间】、实现文件链接
- 每条提示词末尾必须附警告：**⚠️ 请仔细核对以上字段ID是否正确！错误的ID会导致公式/代码生成失败或运行异常！**
- 跨表单代码必须含【跨表请求参数】表格（应用ID、表单名称、表单UUID + 目标表单字段）

## 实现步骤

### 步骤1：解析用户需求

1. 识别目标表单（从用户描述中提取）
2. 识别需求类型（公式/代码/表单/流程）
3. 识别具体功能（日期计算/库存校验等）
4. 识别涉及的字段（通过语义匹配）

### 步骤2：读取配置信息

1. **读取 `系统配置清单.md` 获取（极其重要）**：应用ID、表单UUID、表单类型（普通表单/流程表单）

   > ⚠️ **强制规则：获取到的应用ID和表单UUID必须直接填入提示词/代码中，严禁留占位符如 `{APP_ID}`、`{FORM_UUID}`、`FORM-XXX`、`需从系统配置获取` 等！**
   >
   > **查找方法**：从 `系统配置清单.md` 的「表单ID清单」表格中找到对应表单名称的那一行，提取表单UUID；从「应用信息」表格中提取应用ID。

2. 读取 `组件ID清单.md` 获取：字段名称、字段ID、字段类型、子表结构

### 步骤3：选择提示词模板和生成目录

#### 3.1 模板选择

根据需求复杂度自动选择：简单公式（1-3个字段）→ 简版模板；复杂公式（子表/多条件）→ 完整版模板；单表代码 → 表单动作代码模板；跨表代码 → 跨表单代码模板；字段校验 → 字段校验代码模板；自定义页面 → 自定义页面代码模板；集成自动化 → 集成自动化脚本模板。

#### 3.2 生成目录选择（⚠️ 极其重要）

**场景案例模式**（用于通用场景库）：

```
表单动作代码 → 【表单动作代码/通用场景案例/{分类}】
跨表单代码   → 【表单动作代码/通用场景案例/跨表操作】
字段校验代码 → 【字段校验代码/通用场景案例】
自定义页面   → 【自定义页面/通用场景案例/{分类}】
集成自动化   → 【集成自动化/通用场景案例/{分类}】
```

**项目案例模式**（用于具体项目）：所有代码类型 → 【{项目目录}/{表单目录}/代码/】

**选择逻辑**：

1. 用户指定了具体项目路径 → 项目案例模式
2. 用户说"生成场景案例"或"添加到案例库" → 场景案例模式
3. 默认按当前工作目录判断：项目目录下 → 项目案例模式；案例库目录下 → 场景案例模式

### 步骤4：匹配字段

使用模糊匹配算法（如"开始日期"→匹配含"开始/起始"的日期字段；"数量"→匹配含"数量/个数/件数"的数值字段）。完整匹配模式表见 [references/field-matching-and-errors.md](references/field-matching-and-errors.md)。

### 步骤5：生成提示词

1. 加载对应类型的提示词模板
2. 填充字段ID、表单ID等信息
3. **填写跨表单请求参数（极其重要）**：必须从 `系统配置清单.md` 读取真实的**应用ID**和**目标表单UUID**，直接填入提示词的「跨表请求参数」表格中，严禁留 `需从系统配置获取`、`{APP_ID}`、`{FORM_UUID}` 等占位符
4. 添加警告标识
5. 生成完整的提示词内容

### 步骤6：保存文件（v2.3.0更新 - 独立文件模式）

⚠️ **【强制】保存前必须遵守以下三条铁律，违反任何一条即为严重错误！**

#### 铁律1：严禁合并提示词到已有文件

- ❌ **禁止**：将新提示词追加到已有的提示词文件中；将多个提示词合并到一个"汇总文件"中
- ✅ **正确**：每个提示词创建一个独立的新文件
- **根因**：合并文件会导致已有文件被误删、内容混乱、编号冲突

#### 铁律2：严禁删除已有提示词文件

- ❌ **禁止**：删除已有的提示词文件或代码文件（除非用户明确要求）；因为"合并后冗余"而删除原有独立文件
- ✅ **正确**：新增提示词时只创建新文件，不触碰已有文件
- **根因**：误删会导致不可恢复的数据丢失

#### 铁律3：必须先扫描目录确定序号

- ❌ **禁止**：不扫描目录就直接用"1"作为新文件序号；多个文件使用相同的序号
- ✅ **正确**：先 `LS` 目标目录 → 找到最大序号 → 新序号 = 最大序号 + 1
- **根因**：序号冲突会导致文件管理混乱，无法一一对应

> **关于规则13（新提示词放最前面）的澄清**：
> 规则13仅适用于**同一个文件内**的提示词列表排序。由于每个提示词必须是独立文件（规则20），因此每个独立文件内的提示词编号就是"提示词-1"，**不存在跨文件重新编号的场景**。

**保存步骤（公式类/代码类通用）**：

1. 检查目标表单目录下的 `公式/`（或 `代码/`）文件夹是否存在，不存在则创建
2. **确定序号**：扫描目录找到最大序号，新序号 = 最大序号 + 1（如已有 `1.成员合并公式提示词.md`，新公式就是 `2.xxx提示词.md`）
3. **生成文件名**：`{序号}.{名称}提示词.md`
4. **写入文件**：将提示词内容写入独立文件
5. **关联实现文件**：公式生成后保存为 `{序号}.{名称}.json`；代码生成后保存为 `{序号}.{名称}.js`

### 步骤7：完成确认

1. 提示词已保存到文件，不在对话框重复输出公式和代码内容
2. 告知用户文件保存路径
3. 提醒用户核对字段ID
4. 等待用户确认或修改

## 字段匹配与错误处理

字段按语义关键词模糊匹配（日期/数值/文本三类模式表）；常见错误（找不到表单/找不到字段/字段类型不匹配/缺少必要信息）均需给出明确提示并列出候选项供用户确认。详见 [references/field-matching-and-errors.md](references/field-matching-and-errors.md)。
