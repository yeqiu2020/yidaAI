# 业务关联规则 — 高级函数速查与完整示例

> 配套 `business-rule` SKILL.md 使用。本文档聚焦四大高级函数的完整签名、条件函数、子表单操作、用量限制与进销存完整示例集合。
>
> ⚠️ 所有表单名/字段名在真实配置时都必须从设计器左侧列表**插入令牌**，本文中的中文名仅作可读展示。
>
> ⚠️ **配置入口因表单类型而异**：
> - **普通表单**：`表单设置 → 表单事件 → 公式执行 → 添加业务关联规则`
> - **流程表单**：`流程设计 → 全局设置 → 节点提交规则 → 添加规则 → 选择关联操作`（必须发布流程才生效）
>
> 🔴 **关键限制**：业务关联规则的高阶函数（INSERT/UPDATE/UPSERT/DELETE）**只能以普通表单作为目标**，目标表单不能是流程表单（宜搭平台限制，2026-07-17 实际验证）。如果目标表单是流程表单，请改用「集成自动化」（integration）实现。

## 1. 四大高级函数完整签名

### INSERT — 向目标表插入新实例
```text
INSERT(目标表, 目标列1, 目标值1, 目标列2, 目标值2, ...)
```
- `目标值` 可为：字符串常量 `"x"`、数字常量 `10`、来源字段令牌（如 `产品名称`）、或表达式（如 `库存信息.库存数量 + 入库数量`）。
- 示例（新增一条客户跟进）：
  ```text
  INSERT(客户跟进, 客户名称, 客户名称, 跟进日期, TODAY(), 跟进内容, "系统自动生成跟进")
  ```

### UPDATE — 更新满足条件的记录
```text
UPDATE(目标表, 主条件, 子条件, 目标列1, 目标值1, ...)
```
- 示例（将指定订单状态改为已发货）：
  ```text
  UPDATE(销售订单, EQ(销售订单.销售订单号, 销售订单号), "", 销售订单.订单状态, "已发货")
  ```

### UPSERT — 有则更新，无则插入（最常用）
```text
UPSERT(目标表, 主条件, 子条件, 目标列1, 目标值1, ...)
```
- 库存增减、状态汇总首选此函数。

### DELETE — 删除满足条件的记录
```text
DELETE(目标表, 主条件, 子条件)
```
- 示例：
  ```text
  DELETE(临时表, EQ(临时表.键, 键), "")
  ```

## 2. 条件函数（构造 主条件 / 子条件）

| 函数 | 说明 | 示例 |
|------|------|------|
| `EQ(A,B)` | 相等 | `EQ(库存信息.产品名称, 产品名称)` |
| `NE(A,B)` | 不等 | `NE(状态, "已取消")` |
| `GT(A,B)` / `GE(A,B)` | 大于 / 大于等于 | `GT(数量, 0)` |
| `LT(A,B)` / `LE(A,B)` | 小于 / 小于等于 | `LE(数量, 0)` |
| `AND(...)` | 多条件"与" | `AND(EQ(仓库名称,仓库名称), EQ(产品名称,产品名称))` |
| `OR(...)` | 多条件"或" | `OR(EQ(状态,"草稿"), EQ(状态,"待审核"))` |
| `ISNULL(A)` / `ISNOTNULL(A)` | 空值判断 | `ISNULL(供应商)` |

**条件规则（强制）**：
- 除 `AND()`、`OR()` 外，逻辑函数第一个参数必须是**目标表组件**，例如 `EQ(存货表.商品名, 商品名)`。
- 不要把当前表字段写在 `EQ()` 第一个参数，也不要在第一个参数里嵌套其他函数。
- `子条件` 不操作子表单时必须写 `""`，不能省略。

## 3. 子表单操作

`子条件` 用于定位目标表某条数据下的子表单明细行。`目标列` 必须是对应明细下的组件。

### 3.1 UPDATE/UPSERT 支持子表单操作

UPDATE 和 UPSERT 函数支持对子表单进行插入和更新操作：
- **UPSERT**：当子条件匹配不到记录时，自动**插入**新行到子表；匹配到时**更新**该行
- **UPDATE**：仅更新子条件匹配到的记录，不插入新行

示例（更新某出库单某产品明细的"已出库数量"）：
```text
UPDATE(销售出库,
  EQ(销售出库.出库单号, 出库单号),
  EQ(出库明细.产品名称, 产品名称),
  出库明细.已出库数量, 出库数量)
```

示例（UPSERT 子表单：规格不存在时插入，存在时更新单价）：
```text
UPSERT(目标表单,
  EQ(目标表单.名称, 名称),
  EQ(目标表单.产品规格.规格, 规格),
  目标表单.产品规格.规格, 规格,
  目标表单.产品规格.单价, 单价)
```

### 3.2 🔴 重要规则：目标表单是子表时的处理方式

**当目标表单包含子表单，需要向子表插入/更新数据时，必须分两条规则实现：**

1. **第一条规则**：UPSERT 主表记录（确保主表记录存在）
   ```text
   UPSERT(目标表单, EQ(目标表单.名称, 名称), "", 目标表单.名称, 名称)
   ```

2. **第二条规则**：UPSERT 子表记录（根据主表+子表条件匹配，插入或更新）
   ```text
   UPSERT(目标表单, EQ(目标表单.名称, 名称), EQ(目标表单.子表.字段, 来源字段), 目标表单.子表.字段, 来源字段, ...)
   ```

**原因**：
- 硬规则7限制：同一条规则不能同时写入目标表的主表字段和子表字段
- 子表操作依赖主表记录存在，第一条规则确保主表记录存在后，第二条规则才能正确操作子表

> ⚠️ 同一个高级函数内**不要同时更新普通组件和明细组件**，需拆成多条规则或多个函数。

### 3.3 🔴 来源子表字段自动逐行迭代（v3.8.0，2026-08-01 实战确认）

当公式中**引用了来源表（当前表）的子表字段**作为条件或值时，宜搭引擎会**自动对子表的每一行逐行迭代执行**整条公式。

**示例**：采购入库的入库明细有 3 行，公式引用了子表字段「产品名称」和「入库数量」：
```text
UPSERT(库存信息, AND(EQ(库存信息.仓库名称, 仓库名称), EQ(库存信息.产品名称, 产品名称)), "",
  库存信息.仓库名称, 仓库名称, 库存信息.产品名称, 产品名称,
  库存信息.库存数量, 库存信息.库存数量 + 入库数量)
```
→ 引擎自动执行 3 次，每次取一行的「产品名称」和「入库数量」，分别更新 3 个产品的库存。

**关键要点**：
- 公式只**触发一次**（提交/流程结束），但引擎内部对子表行自动迭代
- 不需要循环容器、不需要集成自动化
- 严禁以"子表有多行，一条公式只能处理一行"为由拒绝使用业务关联规则
- **严禁问用户"子表有几行"**：子表（TableField）的设计目的就是存储多行数据，子表必然是多行。引擎自动逐行迭代，行数多少不影响公式正确性，不需要用户告知

## 4. 用量限制

| 函数 | 目标表类型 | 用量限制 |
|------|-----------|---------|
| `INSERT` | 主表 | 批量导入无条数限制，建议单次 ≤1000 条 |
| `INSERT` | 子表单插入主表 | 免费版 ≤50 条；轻享/专业/专属版 ≤500 条 |
| `UPDATE` | 主表 | 单次最多更新 100 条，超出报错 |
| `UPDATE` | 子表单 | 免费版 ≤50 条；轻享/专业/专属版 ≤500 条 |
| `UPSERT` | 主表 | 单次最多 100 条，超出报错 |
| `UPSERT` | 子表单 | 免费版 ≤50 条；轻享/专业/专属版 ≤500 条 |
| `DELETE` | 主表 | 单次最多删除 100 条 |
| `DELETE` | 子表单 | 轻享/专业/专属版 ≤500 条 |

## 5. 进销存完整示例集合

目标表统一为 `库存信息`，业务键为 `仓库名称 + 产品名称` 组合。

> ⚠️ 以下示例中标注了每个表单的类型（普通表单/流程表单），请根据类型选择正确的配置入口。

### 5.1 销售出库 → 扣减库存（流程表单）

- **配置入口**：流程设计 → 全局设置 → 节点提交规则 → 添加规则 → 关联操作

```text
UPSERT(库存信息,
  AND(EQ(库存信息.仓库名称, 仓库名称), EQ(库存信息.产品名称, 产品名称)),
  "",
  库存信息.仓库名称, 仓库名称,
  库存信息.产品名称, 产品名称,
  库存信息.库存数量, 库存信息.库存数量 - 出库数量)
```

### 5.2 采购入库 → 增加库存（流程表单）

- **配置入口**：流程设计 → 全局设置 → 节点提交规则 → 添加规则 → 关联操作

```text
UPSERT(库存信息,
  AND(EQ(库存信息.仓库名称, 仓库名称), EQ(库存信息.产品名称, 产品名称)),
  "",
  库存信息.仓库名称, 仓库名称,
  库存信息.产品名称, 产品名称,
  库存信息.库存数量, 库存信息.库存数量 + 入库数量)
```

### 5.3 销售退货 → 增加库存（流程表单）

- **配置入口**：流程设计 → 全局设置 → 节点提交规则 → 添加规则 → 关联操作

```text
UPSERT(库存信息,
  AND(EQ(库存信息.仓库名称, 仓库名称), EQ(库存信息.产品名称, 产品名称)),

  库存信息.仓库名称, 仓库名称,
  库存信息.产品名称, 产品名称,
  库存信息.库存数量, 库存信息.库存数量 + 退货数量)
```

### 5.4 采购退货 → 减少库存（流程表单）

- **配置入口**：流程设计 → 全局设置 → 节点提交规则 → 添加规则 → 关联操作

```text
UPSERT(库存信息,
  AND(EQ(库存信息.仓库名称, 仓库名称), EQ(库存信息.产品名称, 产品名称)),
  "",
  库存信息.仓库名称, 仓库名称,
  库存信息.产品名称, 产品名称,
  库存信息.库存数量, 库存信息.库存数量 - 退货数量)
```

### 5.5 库存盘点 → 按实盘数量校准（普通表单）

- **配置入口**：表单设置 → 表单事件 → 公式执行 → 添加业务关联规则

```text
UPSERT(库存信息,
  AND(EQ(库存信息.仓库名称, 仓库名称), EQ(库存信息.产品名称, 产品名称)),
  "",
  库存信息.仓库名称, 仓库名称,
  库存信息.产品名称, 产品名称,
  库存信息.库存数量, 库存信息.库存数量 + (实盘数量 - 账面数量))
```

> ⚠️ 具体字段ID以 `组件ID清单.md` / `get-schema` 为准；`仓库名称`、`产品名称` 在库存信息主表为只读关联填充字段（值稳定，可作业务键），库存数量用可写数值字段。
> ⚠️ 流程表单的规则必须**发布流程**后才生效，仅保存不发布不会触发。

## 6. 常见错误速查

| 错误 | 原因 | 处理 |
|------|------|------|
| `该标识符不合法` | 手敲了表单名/字段名 | 从左侧列表点击插入令牌 |
| `Unexpected end of input` | 公式未闭合或必填参数缺失 | 检查括号、逗号、`子条件` |
| 规则未触发 | 配在错误事件或未保存表单/未发布流程 | 检查 `单据提交/删除/编辑` 与保存结果；流程表单需发布流程 |
| 流程表单规则不生效 | 在「表单设置→表单事件」配置而非「流程设计→节点提交规则」 | 流程表单必须走流程设计的节点提交规则入口 |
| 生成的是纯文本无法粘贴 | 只生成了文本公式，没有 marks/fieldId | 使用结构化公式数据格式（text + marks），参考 SKILL.md 第四节 |
| 更新结果过多 | 条件不精确或超出限制 | 收紧 `主条件`，必要时改用 `integration` |
