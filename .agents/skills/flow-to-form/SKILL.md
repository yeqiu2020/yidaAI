## 🔴 硬规则（绝对不可违反）

### 通用硬规则
1. **禁止通过API修改已有应用的表单字段内容** — 公式、代码、字段增删改只能复制粘贴（规则25）
2. **应用ID和表单UUID必须填真实值** — 从系统配置清单.md读取，严禁占位符（规则24）
3. **写入文件前必须校验** — 运行 `node scripts/ai-validator.js check-before-write <文件路径>` 确认不覆盖已有文件
4. **写入文件后必须校验** — 运行 `node scripts/ai-validator.js check-after-write <文件路径>` 确认内容合规
5. **Cookie必须使用根目录** — 严禁 process.cwd()，必须用 PROJECT_ROOT（规则26）

### 专属硬规则
1. **严格按流程图内容生成不能多也不能少** — 流程图有几个表单就生成几个，表单名称不能改
2. **基础档案vs业务数据严格区分** — 基础档案不包含库存/金额/余额等业务数据字段

# 流程图转宜搭表单 Skill

版本：v1.0.2

## 🚨 生成规则（每次调用时必须严格遵守）

1. **严格按照流程图里的内容生成表单，不能多也不能少，表单名字也不能改**
   - 只生成流程图中实际存在的表单（带📄或▶️图标的节点）
   - 表单名称必须与流程图中完全一致，禁止修改
   - 禁止根据主题进行泛化补充，即使你认为"这个系统应该还有XXX表单"，只要流程图中没有，就不能添加
   - 流程图中有几个表单，字段清单中就有几个表单，数量必须完全一致

2. **严格按照流程图主线顺序生成模块，不得打乱顺序**
   - **优先按照流程图中的中文大写序号排序**：如果流程图模块上有"一、二、三..."或"(一)(二)(三)..."等中文序号，严格按照序号顺序生成
   - **🚨 重要：识别流程图的排列方式（蛇形/S形顺序）**
     - 流程图通常采用蛇形（S形）排列，即：第一行从左到右，第二行从右到左，第三行从左到右，以此类推
     - **必须严格按照流程图的实际视觉布局顺序识别模块，不能简单地从左到右或从上到下**
     - 例如：如果流程图布局为：
       ```
       第一行：基础信息 → 库存管理
       第二行：采购管理 ← 销售管理 ← 客户管理
       第三行：财务管理 → 其他需求
       ```
       则正确的模块顺序是：基础信息→库存管理→客户管理→销售管理→采购管理→财务管理→其他需求
   - 如果没有中文序号，则按照流程图中最粗的线条（主线）顺序排列模块
   - 从中心节点开始，按顺时针或从左到右的顺序识别模块
   - 模块顺序必须与流程图视觉呈现的顺序一致
   - 例如：如果流程图显示顺序是"一、基础信息→二、库存管理→三、客户管理→四、销售管理→五、采购管理→六、财务管理→七、其他需求"，则必须按此顺序生成

   **中文大写序号排序规则**：
   | 序号类型 | 示例 | 排序依据 |
   |---------|------|---------|
   | 中文数字 | 一、二、三、四、五、六、七、八、九、十 | 按照中文数字顺序 |
   | 中文括号 | (一)(二)(三) | 按照括号内数字顺序 |
   | 阿拉伯数字 | 1. 2. 3. | 按照数字大小 |
   
   **注意**：如果流程图中同时存在多级序号（如"一、"下面有"(一)"），先按一级序号排序，再按二级序号排序
   
   **🚨 蛇形（S形）顺序识别要点**：
   - 仔细观察流程图的布局，确定每一行的排列方向
   - 第一行通常从左到右
   - 第二行通常从右到左（与第一行相反）
   - 第三行通常从左到右（与第一行相同）
   - 以此类推，形成S形走向
   - **禁止**简单地按照"从左到右、从上到下"的顺序读取，必须按照实际的蛇形路径读取

3. **严格按照流程图的模块分组生成，禁止自定义分组**
   - 流程图已经按照业务模块进行了分组（如"一、基础信息"、"二、库存管理"等），必须严格按照这些现成的模块分组
   - **禁止**根据"表单功能和属性"进行自定义分组（如"基础信息模块"、"业务管理模块"、"库存财务模块"等）
   - 表单必须放在流程图原有的模块下，不得跨模块移动或重新归类
   - 流程图中有几个模块，字段清单中就有几个模块，模块数量和名称必须与流程图完全一致
   - 如果流程图没有明确的模块分组（极少数情况），则每个表单独立成一节

4. **因为流程图里不会对字段进行过多记录，只有一些关键字段，将表单内的关键字段原样生成到表单内，并按照常规的情况进行字段的拓展添加**
   - 提取流程图中"关键字段"节点下的字段，原样保留
   - 在流程图字段基础上，根据业务逻辑合理拓展必要的字段
   - **所有字段必须标注宜搭组件类型**，不允许出现无类型标注的字段
   - 通过关联表单带出的字段统一标注为【单行文本】，在规则清单中说明数据填充来源

5. **其他内容都生成到规则清单内，规则清单可以进行拓展**
   - 状态流转、业务规则、自动化规则、消息提醒、聚合表、报表等全部放在规则清单
   - 规则清单可以根据业务常识进行合理拓展

## 🚨 核心概念辨析（新增 - 必须严格遵守）

### 基础档案 vs 业务数据

**这是最容易混淆的概念，必须严格区分！**

| 对比维度 | 基础档案（普通表单） | 业务数据（流程表单/业务记录） |
|---------|---------------------|------------------------------|
| **本质** | 静态主数据 | 动态业务记录 |
| **数据特点** | 相对稳定，变更少 | 频繁变动，随业务实时更新 |
| **典型示例** | 产品信息、客户信息、供应商信息、仓库信息、员工信息 | 采购订单、销售订单、入库单、出库单、库存记录、收款记录 |
| **包含字段** | 描述性属性（名称、规格、型号、联系方式等） | 交易数据（数量、金额、日期、状态等） |
| **更新方式** | 人工维护，直接修改 | 通过业务流程自动生成和更新 |

### 常见概念混淆组合

| 基础档案（❌ 不应包含库存/财务字段） | 业务数据（✅ 应独立管理） | 混淆后果 |
|-----------------------------------|------------------------|---------|
| **产品信息** | 库存信息/库存记录 | 无法管理多仓库库存，库存计算混乱 |
| **客户信息** | 客户账户/应收记录 | 财务数据与基础档案耦合，难以扩展 |
| **供应商信息** | 供应商账户/应付记录 | 同上 |
| **仓库信息** | 库存明细/库位记录 | 无法追踪具体库存分布 |
| **员工信息** | 考勤记录/薪资记录 | 人事档案与业务数据混淆 |

### 概念辨析检查清单（生成字段前必须完成）

对于每个基础档案表单（产品/客户/供应商/仓库/员工等），必须回答：

```
☐ 1. 这个表单是否包含"数量"、"金额"、"余额"、"库存"类字段？
    - 如果有 → ❌ 错误！这些字段不应该在基础档案中
    - 正确做法：通过聚合表计算，或创建独立的业务表单

☐ 2. 这个表单是否有字段表示"当前状态"且会频繁变更？
    - 如果是 → ⚠️ 需要确认：是描述性状态（如产品启用/停用）还是业务状态（如在库/借出）
    - 业务状态不应该在基础档案中

☐ 3. 这个表单是否有字段需要通过其他表单汇总计算？
    - 如果有 → ❌ 错误！基础档案不应该存储计算字段
    - 正确做法：通过聚合表或公式实时计算

☐ 4. 一个基础档案记录是否可能对应多个业务记录？
    - 如果是 → 基础档案中不应该包含业务数据
    - 示例：一个产品可以存放在多个仓库 → 产品信息不应该有"当前库存"字段

☐ 5. 流程图中是否有独立的业务模块来管理这类数据？
    - 如果有 → 严格按照流程图生成独立表单，不合并到基础档案
```

### 错误示例 vs 正确示例

#### ❌ 错误示例：产品信息表包含库存字段
```
产品信息表（错误）：
├─ 产品编号【流水号】
├─ 产品名称【单行文本】
├─ 规格型号【单行文本】
├─ 当前库存【数值】← ❌ 错误！产品信息不应该有库存字段
├─ 安全库存【数值】← ❌ 错误！这是库存管理范畴
├─ 存放仓库【关联表单】← ❌ 错误！产品可以存放在多个仓库
└─ ...
```

#### ✅ 正确示例：产品信息为纯基础档案
```
产品信息表（正确）：
├─ 产品编号【流水号】
├─ 产品名称【单行文本】
├─ 产品类别【下拉单选】
├─ 规格型号【单行文本】
├─ 单位【下拉单选】
├─ 参考采购价【数值】
├─ 参考销售价【数值】
├─ 产品状态【下拉单选：启用/停用】
└─ ...

库存信息表（独立表单，如流程图中有）：
├─ 库存编号【流水号】
├─ 仓库【关联表单-->仓库信息】
├─ 产品【关联表单-->产品信息】
├─ 当前库存【数值】
├─ 安全库存【数值】
└─ ...
```

### 业务规则生成原则

**🚨 重要：业务规则不应该更新基础档案的业务数据字段**

#### ❌ 错误示例
```
规则：采购入库更新产品库存
- 目标表单: 产品信息 ← ❌ 错误！不应该更新基础档案
- 操作内容: 当前库存 = 当前库存 + 入库数量
```

#### ✅ 正确示例
```
方案A：通过聚合表计算库存（推荐）
- 聚合表名称: 产品库存统计
- 数据源: 采购入库、销售出库、库存盘点等
- 计算逻辑: 当前库存 = SUM(入库数量) - SUM(出库数量) ± SUM(盘点差异)

方案B：独立的库存信息表（如果流程图中有）
规则：采购入库更新库存信息
- 目标表单: 库存信息 ← ✅ 正确！更新业务数据表
- 操作内容: 当前库存 = 当前库存 + 入库数量

方案C：记录业务流水（如果流程图中没有库存信息表）
规则：采购入库记录
- 目标表单: 入库记录（子表或独立表单）
- 操作内容: 记录入库仓库、产品、数量、单价等信息
- 说明: 库存通过聚合表实时计算
```

## 何时使用此 Skill

当用户上传业务流程图、思维导图或系统架构图时，使用本 Skill 自动解析并生成：
1. **表单字段清单** - 用于生成宜搭 JSON 表单配置
2. **业务规则清单** - 用于指导后续手动开发（公式、关联表单、业务规则、自动化规则、消息提醒、聚合表、报表等）

## 输入要求

用户需提供：
- 业务流程图/思维导图截图（PNG/JPG 格式）
- 系统名称（如：仪表管理系统、出入库管理系统等）
- 版本号（可选，默认 1.0.0）

## 📋 字段清单使用说明

### 一、可用字段类型

单行文本、多行文本、数值、日期、日期时间、下拉单选、下拉多选、关联表单、成员、部门、附件、图片、流水号

### 二、字段说明格式规范

**只有以下5类字段需要填写字段说明，其他字段留空或填"-"**

| 字段类型 | 字段说明格式 | 示例 |
|---------|-------------|------|
| **流水号** | `自动生成` | 自动生成 |
| **关联表单** | `关联-->目标表单名称` | 关联-->产品信息 |
| **关联带出** | `关联-->目标表单名称，关联带出` | 关联-->产品信息，关联带出 |
| **数值** | `X位小数，单位：XXX` | 2位小数，单位：元 |
| **下拉单选/多选** | `选项值1/选项值2/选项值3` | 启用/停用 |

#### 补充说明

- **公式计算字段**：填写 `公式计算` 或 `公式计算，计算逻辑`，如：`公式计算，数量×单价`
- **无特殊说明**：填写 `-` 或留空

### 三、字段状态

| 状态值 | 说明 | 默认值 |
|-------|------|--------|
| **普通** | 字段可编辑输入（对应宜搭NORMAL） | 大部分字段默认为普通状态 |
| **只读** | 字段不可编辑，仅用于展示（对应宜搭READONLY） | 关联带出字段、系统自动生成字段默认为只读状态 |
| **隐藏** | 字段在表单中不显示（对应宜搭HIDDEN） | 默认无隐藏字段，用户可根据需要设置 |

**字段状态自动判定规则**：
- **只读**：创建人、创建时间、关联带出字段、公式计算字段
- **普通**：流水号、其他所有字段

**⚠️ 重要**：流水号字段状态统一为"普通"（不是"只读"），便于测试时手动输入编号

**⚠️ 重要说明**：宜搭流程表单会自动记录审批相关信息（审批人、审批时间、审批意见等），**不需要在表单字段中添加审批相关字段**

### 四、是否必填

- **是**：该字段为必填项
- **否**：该字段为选填项（默认）

**默认值规则**：
- 所有字段默认**非必填**（便于前期测试数据）
- 流水号字段**永不必填**（系统自动生成）
- 创建人、创建时间等系统字段**永不必填**

### 五、表单类型标识

- 「普通表单」：基础数据维护，无审批流程
- 「流程表单」：需要审批流程的业务单据

**⚠️ 格式规范（重要！）：**
1. **使用 Markdown 标准语法**：使用 `##` 和 `###` 作为标题，**禁止**使用缩进（4个空格）
2. **禁止代码块样式**：缩进会被Markdown解析为代码块，导致预览时出现灰色背景框
3. **使用表格格式**：所有字段必须使用表格展示，包含字段名称、字段类型、字段说明、字段状态、是否必填五列
4. **表单类型标注**：每个表单后必须标注「普通表单」或「流程表单」
5. **所有字段必须标注类型**：不允许出现无类型标注的字段
6. **流程表单分主表和子表**：流程表单需要分别列出主表字段和子表明细

**⚠️ 重要标注规则**：
1. 每个表单后必须标注类型：「普通表单」或「流程表单」
2. 普通表单 = 文档图标 📄
3. 流程表单 = 播放图标 ▶️
4. **只列出流程图中实际存在的表单，禁止编造**

## 解析流程图的方法

### 步骤 1：识别模块结构

1. 识别图中的主要模块（通常用不同颜色或边框区分）
2. 每个模块对应一个业务功能单元
3. 记录模块间的关联关系（箭头指向）
4. **按照流程图主线顺序排列模块**：
   - **优先识别中文大写序号**：如果流程图模块上有"一、二、三..."等中文序号，严格按照序号顺序排列
   - 如果没有中文序号，找到流程图中最粗的线条（主线）
   - 从中心节点开始，按顺时针或从左到右的顺序识别模块
   - 模块顺序必须与流程图视觉呈现的顺序完全一致
   - 不得根据个人理解重新排序模块
   
   **中文大写序号识别**：
   - 一级序号：一、二、三、四、五、六、七、八、九、十
   - 二级序号：(一)(二)(三)(四)(五)
   - 三级序号：1. 2. 3. 或 ① ② ③
   - 排序时先按一级序号，再按二级序号，最后按三级序号
5. **根据表单功能和属性，将表单归纳到2~3个分组中**

### 步骤 2：识别表单类型（重要 - 必须严格执行）

**🚨 这是最容易出错的环节，必须逐个检查，禁止凭经验判断！**

#### 图标识别标准

| 表单类型 | 图标颜色 | 图标形状 | 用途说明 |
|---------|---------|---------|---------|
| **普通表单** | � 蓝色/灰色 | � 文档图标 | 基础数据维护、档案管理 |
| **流程表单** | 🟢 绿色 | ▶️ 播放图标（带三角形） | 业务审批、需要工作流 |

#### 标准识别流程（必须严格执行）

```
步骤1：逐个扫描所有表单节点
  ↓
步骤2：记录每个表单的图标特征
  - 颜色：蓝色/灰色 = 普通表单，绿色 = 流程表单
  - 形状：文档 = 普通表单，播放/三角形 = 流程表单
  ↓
步骤3：建立表单类型清单
  | 表单名称 | 图标颜色 | 判定结果 |
  ↓
步骤4：交叉验证
  - 统计普通表单数量
  - 统计流程表单数量
  - 检查是否有遗漏或误判
  ↓
步骤5：生成字段前最终确认
  - 逐个比对表单名称和类型
  - 确保与流程图完全一致
```

#### ⚠️ 重要规则（严格执行）

1. **只生成流程图中实际存在的表单，绝对禁止添加流程图之外的表单**
2. 只有带图标的节点才是表单
3. 不要编造流程图中不存在的表单
4. 每个表单必须在清单中标注类型：「普通表单」或「流程表单」
5. 表单名称必须与流程图中完全一致
6. **禁止根据主题进行泛化补充**：即使你认为"这个系统应该还有XXX表单"，只要流程图中没有，就不能添加
7. **严格一对一映射**：流程图中有几个表单，字段清单中就有几个表单，数量必须完全一致
8. **图标识别要点**：
   - 流程表单：绿色背景小方框 + 三角形播放图标
   - 普通表单：蓝色/灰色文档图标
   - **仔细观察每个表单节点的图标样式，不要凭经验判断**
   - **禁止根据业务类型推测表单类型（如"订单"不一定是流程表单，必须看图标）**

#### 🚨 防遗漏检查机制（新增 - 必须严格执行）

**步骤A：建立模块-表单映射表**

在识别每个模块时，必须建立以下表格：

```
模块名称：{模块名}
├─ 表单1：{表单名称} - {图标类型}
├─ 表单2：{表单名称} - {图标类型}
├─ 表单3：{表单名称} - {图标类型}
└─ ...
```

**步骤B：逐个模块扫描检查**

1. **从上到下扫描**：对于垂直排列的模块，必须从上到下逐一确认每个表单
2. **从左到右/从右到左扫描**：根据蛇形排列方向，按实际视觉顺序确认
3. **边界检查**：特别注意每个模块的第一个和最后一个表单
4. **数量核对**：统计每个模块的表单数量，与流程图实际数量对比

**步骤C：交叉验证清单**

| 验证项 | 操作方法 | 通过标准 |
|-------|---------|---------|
| 数量验证 | **只统计带📄或▶️图标的节点**（普通表单和流程表单） | 与生成清单数量完全一致 |
| 名称验证 | 逐个比对表单名称 | 100%匹配，无增删改 |
| 顺序验证 | 按流程图视觉顺序检查 | 与流程图呈现顺序一致 |
| 类型验证 | 检查每个表单的图标类型 | 普通/流程表单判定正确 |

**⚠️ 重要提醒**：流程图中包含多种节点类型（字段、流程、规则说明等），**只有带📄（文档图标）或▶️（播放图标）的节点才是表单**，其他节点不计入表单数量统计。

**步骤D：生成前最终确认**

在生成字段清单前，必须回答以下问题：
1. 流程图中共有多少个带📄或▶️图标的表单节点？____个
2. 我已识别的表单数量是多少？____个
3. 两者数量是否一致？是/否
4. 流程图中的字段节点、流程节点、规则说明节点是否被错误识别为表单？是/否
5. 是否有任何表单我还不确定？是/否
6. 如果答案都是"是/否/否"，则可以生成；否则必须重新检查流程图

#### 常见遗漏场景及预防措施

| 场景 | 原因 | 预防措施 |
|-----|------|---------|
| 垂直排列的顶部表单 | 视线被下方更突出的表单吸引 | 从上到下逐行扫描，不跳过任何节点 |
| 蛇形排列的反向行 | 惯性思维从左到右 | 先判断每行排列方向，再按实际方向读取 |
| 相邻相似表单 | 如"报价"和"订单"都是销售类 | 建立书面清单，逐个标记确认 |
| 小字体/次要位置的表单 | 视觉优先级低 | 放大查看，不遗漏任何带📄或▶️图标的节点 |
| 模块边界处的表单 | 处于两个模块之间 | 明确模块边界，确认归属 |

#### 流程表单字段说明

**⚠️ 重要**：宜搭流程表单会自动记录以下系统字段，**不需要在表单字段中添加这些字段**：
- 审批相关信息：审批人、审批时间、审批意见
- 流程状态：单据状态（草稿/进行中/已完成等）

流程表单只需关注业务字段，不需要添加任何审批或状态相关的系统字段。

1. 识别表单下的"关键字段"节点
2. 提取字段名称
3. 识别子表：带有【子表】前缀的节点
4. 识别选项字段：字段下有子节点的为下拉选项

**字段提取规则**：
- 提取流程图中"关键字段"节点下的字段，原样保留
- 在流程图字段基础上，根据业务逻辑合理拓展必要的字段
- 字段下的说明文字不提取到字段清单，整合到规则清单
- 选项值以下拉选项形式标注

## 常见问题与解决方案

### 问题1：表单类型识别错误（高频错误，必须避免）
**现象**：将流程表单识别为普通表单，或反之。
**根本原因**：
- 没有逐个仔细观察图标细节
- 凭经验判断（如认为"订单"就是流程表单）
- 没有建立书面识别记录
- 没有进行交叉验证

**预防措施**：
1. **必须建立表单类型识别表**，书面记录每个表单的图标特征
2. **逐个检查**，禁止批量判断
3. **只看图标，不看业务含义**（不要根据"这是订单所以是流程表单"来判断）
4. **交叉验证**：统计普通表单和流程表单数量，检查是否合理
5. **使用自检清单**，确保每个检查项都完成

**识别标准**：
| 图标特征 | 表单类型 |
|---------|---------|
| 🔵 蓝色/灰色 + 📄 文档图标 | 普通表单 |
| 🟢 绿色 + ▶️ 播放/三角形图标 | 流程表单 |

**解决**：
- 逐个检查每个表单节点的图标颜色和形状
- 绿色背景 + 三角形 = 流程表单
- 蓝色/灰色文档图标 = 普通表单
- 建立书面识别记录，禁止凭记忆判断

### 问题2：基础档案与业务数据混淆（新增 - 严重错误）
**现象**：
- 在产品信息表中添加"当前库存"、"安全库存"字段
- 在客户信息表中添加"预付款余额"、"已用额度"字段
- 业务规则直接更新基础档案的业务数据字段

**根本原因**：
- 混淆了"基础档案"和"业务数据"的概念
- 凭经验认为"产品表应该有库存字段"
- 没有理解业务流程中数据应该如何管理

**预防措施**：
1. **严格区分基础档案和业务数据**
   - 基础档案：静态属性（名称、规格、型号等）
   - 业务数据：动态交易数据（库存、金额、数量等）
2. **使用概念辨析检查清单**
   - 生成字段前完成检查清单
   - 确保基础档案不包含业务数据字段
3. **业务规则不更新基础档案的业务数据**
   - 库存数据通过聚合表计算
   - 或更新独立的业务表单（如库存信息表）

**识别标准**：
| 类型 | 特点 | 示例 |
|-----|------|------|
| 基础档案 | 静态、变更少、描述属性 | 产品信息、客户信息、供应商信息 |
| 业务数据 | 动态、频繁变更、记录交易 | 库存记录、订单、入库单、收款记录 |

**解决**：
- 从基础档案中移除业务数据字段
- 通过聚合表实时计算库存/财务数据
- 或创建独立的业务表单管理这类数据
- 更新业务规则，不直接修改基础档案

### 问题3：遗漏表单
**现象**：流程图中有某个表单，但生成的字段清单中没有。
**原因**：
- 没有仔细扫描所有模块下的表单节点
- 某些表单名称与已有概念混淆（如"产品类别"可能被误认为只是字段而非表单）
**解决**：
- 逐个模块检查，确保每个带图标的节点都被记录
- 不要假设某个节点不是表单，只要有图标就是表单

### 问题4：模块顺序错误
**现象**：生成的模块顺序与流程图不一致。
**原因**：
- 按照个人理解重新排序了模块
- 没有按照流程图主线（最粗的线条）顺序识别
- 忽略了流程图中的中文大写序号
**解决**：
- **优先按照流程图中的中文大写序号排序**（一、二、三...）
- 如果没有中文序号，严格按照流程图视觉呈现的顺序
- 从中心节点开始，按顺时针或从左到右的顺序记录
- 不得根据个人理解重新排序
- **自检**：生成前检查模块顺序是否与流程图序号一致

### 问题5：表单名称不一致
**现象**：生成的表单名称与流程图中不完全一致。
**原因**：
- 擅自修改了表单名称（如简写、增删字）
**解决**：
- 表单名称必须与流程图中完全一致
- 禁止修改、简写或增删任何字
