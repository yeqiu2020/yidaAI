# 坑位与约束（2026-10-01 实战沉淀，全部实测）

## 视口与加载

| 现象 | 规避 |
|------|------|
| card.dingtalk.com/editor 在 1400/1600px 直载**整页空白**（bodyLen=0，React 不挂载） | 先用 **818x710** 加载成功后，需要宽交互再调视口；若仍空白重 goto 一次 |
| 流程编辑器左侧节点面板常驻位 x≈-985（屏幕外） | 无视它——弹层放置协议（片段库 §3）不依赖面板可见性 |
| 节点「+」按钮 hover 显形链（opacity:0→1）合成事件打不断 | 不要尝试 hover；直接 fiber `onVisibleChange(true)` |

## 点击协议分层（从优到劣）

1. **React 事件处理器直调**（`__reactProps$` / `__reactEventHandlers$` 的 onClick/onChange）——对受控组件唯一可靠
2. **CDP cua.click/cua.move**（真实输入）——对画布节点、下拉选项、普通按钮可靠
3. **DOM dispatchEvent MouseEvent 序列**——对低代码引擎拖拽（lc-comp-snippet）有效，对宜搭流程画布拖拽无效（引擎自管 dnd，且拖拽拼流程被项目规则1禁止）
4. 原生 `el.click()` —— 对 next-switch 有时无效

## 弹窗与状态陷阱

- **残留 alertdialog 会吞掉一切点击**：点击无效时第一步清弹窗（片段库 §6）
- toast 与 dialog 元素常驻 DOM 不消失（"保存失败"文案可能是旧的）——判定成败以**画布内容/列表状态**为准，不以 toast 为准
- 设计器 SPA 会拦截 goto（ERR_ABORTED）：换新 tab 打开目标 URL，别硬闯
- 内嵌浏览器会话独立过期：SSO 跳 login.dingtalk.com 需用户扫码，无法静默续期（API cookie 仍可用，见 integration CLI）

## 平台限制（宜搭侧，非自动化问题）

- 流程表单 SerialNumberField **不在流程变量列表**——卡片映射/匹配条件引用不到单号
- 发送卡片到**当前群**：定时触发无群上下文不支持；发指定群需表单在该群发起
- 卡片上不能渲染报表图表组件；≤3 指标用循环指标卡，≥3 用循环渲染容器
- 卡片样式改动需重新触发发送（钉钉侧有消息卡片缓存）
- `updateCard`（更新卡片节点）可刷新已发卡片内容，键 `updateCardRules`

## 自动化配置的已知残缺（人工微调点）

- **更新数据节点匹配条件的字段切换**：面板内部 `onParamSelect` 读 `option.dynamicOperators` 崩溃，无法经 onChange 换字段。占位匹配可保存发布（不命中即跳过无副作用）；精准匹配请引导用户在设计器手改为「实例ID 等于 触发实例ID」
- **自定义卡片设计器**（card.dingtalk.com）：拖组件、文本组件 `$` 变量选择器（6试1中）不稳定——官方模板+节点映射是稳妥路线
- 发送卡片节点的面板保存曾出现静默失败：**保存后必须回读画布**确认节点显示 `发送卡片: <模板名>` 再走流程保存

## 验证链（缺一不可）

1. `integration-list.js list <appType>` → 状态=启用
2. 列表页 alert「本月累计执行次数」应 +N
3. 行内「运行日志」→ 状态=执行成功（记实例ID与耗时）
4. 用户钉钉侧肉眼确认卡片（AI 无法读钉钉客户端）
