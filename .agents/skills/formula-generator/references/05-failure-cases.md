## 一、常见失败案例分析（必读）

### 案例1：SUMPRODUCT函数参数不足错误

**需求**：统计子表中"苹果"出现的次数

**错误公式**：
```
SUMPRODUCT(IF(EQ(子表.产品,"苹果"),1,0))
```

**错误原因**：
- **SUMPRODUCT参数不足**：宜搭的SUMPRODUCT函数**必须至少2个参数**，不能单独使用
- 错误提示："函数 SUMPRODUCT 的必需参数个数为 2"

**正确方案**：
```
// 方案1：使用两个数组相乘（推荐）
SUMPRODUCT(IF(EQ(子表.产品,"苹果"),1,0), 1)

// 方案2：使用SUM函数替代
SUM(IF(EQ(子表.产品,"苹果"),1,0))
```

**经验教训**：
- SUMPRODUCT在宜搭中**必须至少2个参数**
- 如果只需要条件计数，可以用 `SUM(IF(EQ(...),1,0))` 替代
- SUMPRODUCT适合多数组相乘后求和的场景

### 案例2：商机名称自动生成（子表字段处理）

**需求**：将客户名称和子表中的产品名称组合成"客户简称-产品1&产品2"

**失败原因**：
1. **函数大小写错误**：`GETARRAYITEM` → 应为 `GetArrayItem` 或 `ARRAYGET`
2. **混淆函数用途**：子表字段应该用 `ARRAYGET`，不是 `GetArrayItem`
3. **数组索引起始错误**：使用了0-based索引，宜搭是1-based
4. **COUNT函数误用**：`COUNT(子表.字段)` 不能统计子表行数

**正确方案**：
```javascript
// 公式文本中使用显示名
CONCATENATE(客户名称,"-",ARRAYGET(意向产品.产品名称,1),...)

// fields配置
fields: [
  { displayName: "客户名称", fieldId: "textField_mmdeymds" },
  { displayName: "意向产品.产品名称", fieldId: "textField_mmdeymdz" }
]
```

**经验教训**：
- 子表字段在主表公式中返回数组，用 `ARRAYGET` 获取
- 公式文本用**显示名**，marks用**字段ID**
- 宜搭数组索引**从1开始**
- `COUNT` 只用于统计表单提交数，不用于子表

## 二、建议转 JS 实现的话术模板

当判断需求超出公式能力时，使用以下话术：

> **⚠️ 功能超出公式能力范围**
>
> 经过分析，您需要的【具体功能】**无法通过宜搭公式实现**，原因如下：
> - 【原因1：如"需要循环遍历数组"】
> - 【原因2：如"需要正则表达式匹配"】
>
> **建议方案**：使用 **JS 代码** 实现此功能。
>
> 虽然 JS 代码相对复杂，但可以实现公式无法完成的逻辑。我可以为您编写对应的 JS 代码，您看是否需要？
>
> ---
> **公式 vs JS 对比**：
> | 方式 | 优点 | 缺点 | 适用场景 |
> |------|------|------|---------|
> | 公式 | 易读、易维护、性能好 | 功能有限 | 简单计算、条件判断 |
> | JS 代码 | 功能强大、灵活 | 复杂、需调试 | 复杂逻辑、循环、API调用 |
