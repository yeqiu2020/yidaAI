# 公式与联动模式

> 能力域：公式与联动
> 执行工具：data-tester（API层）/ js-action-tester（UI层）
> 测试层级：宜搭 API / UI E2E

---

## P04：数值公式计算正确

**场景：** 含数值公式的字段在数据提交后计算结果正确

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 公式与联动 |

**占位符：**
- `{表单名称}` — 目标表单名
- `{公式字段名}` — 含公式的字段名（如"小计"/"合计金额"）
- `{公式字段ID}` — 公式字段的组件 ID
- `{公式表达式}` — 宜搭公式表达式（如 `数量*单价`）
- `{输入字段值}` — 公式中引用的字段输入值
- `{预期值}` — AI 根据公式推导的计算结果

**前置条件：**
- {表单名称} 中 {公式字段名} 配置了公式 {公式表达式}
- 登录态有效

**操作步骤：**
1. 构造测试数据，设置 {输入字段值}，不设置 {公式字段名} 的值（公式自动计算）
2. 提交数据到宜搭
3. 回查该记录，读取 {公式字段ID} 的值

**断言：**
- 回查的 {公式字段名} 值 = {预期值}（数值类型，容差 ±0.01）

**特别说明：**
- 宜搭公式在提交时由服务端计算，不需要手动传入公式字段的值
- 但如果公式依赖关联字段的值，需确保关联字段数据正确

**产品依据：** data-tester SKILL.md "多维度结果验证 → 验证公式计算结果"

## P07：字段联动规则触发

**场景：** 当源字段值变化时，目标字段按联动规则自动更新

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | UI E2E |
| 执行工具 | js-action-tester |
| 能力域 | 公式与联动 |

**占位符：**
- `{表单名称}` — 目标表单名
- `{源字段名}` — 联动触发的字段（如"部门"）
- `{目标字段名}` — 被联动的字段（如"负责人"）
- `{源字段值}` — 触发联动的值
- `{预期目标值}` — 联动后目标字段的预期值

**前置条件：**
- {表单名称} 配置了 {源字段名} → {目标字段名} 的联动规则
- js-action-tester 可访问应用

**操作步骤：**
1. 打开表单新建页面
2. 设置 {源字段名} = {源字段值}
3. 等待联动触发（宜搭联动有异步延迟）
4. 读取 {目标字段名} 的值

**断言：**
- {目标字段名} 的值 = {预期目标值}

**产品依据：** js-action-tester SKILL.md "功能概述 → 字段联动"

## P09：被填充字段值与关联记录一致

**场景：** 选择关联表单后，被填充字段的值来自关联记录的实际数据

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 公式与联动 |

**占位符：**
- `{关联字段名}` — 关联表单字段（如"选择仓库"）
- `{被填充字段名列表}` — 被自动填充的字段（如"仓库名称,仓库地址,负责人"）
- `{关联记录instanceId}` — 选中的关联记录 ID
- `{关联记录formData}` — 该记录的完整 formData

**断言：**
- 每个 {被填充字段名} 的值 = {关联记录formData} 中对应字段的值

**特别说明：**
- API 提交时数据填充规则不会自动触发，AI 必须手动填入被填充字段的值
- 被填充字段的值必须来自关联记录的 formData，不能 AI 编造

**产品依据：** data-tester SKILL.md "【强制·v3.1.4】被填充字段必须从关联记录的formData中获取真实值"
