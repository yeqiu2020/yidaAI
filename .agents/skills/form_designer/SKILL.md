## 🔴 硬规则（绝对不可违反）

### 通用硬规则
1. **禁止通过API修改已有应用的表单字段内容** — 公式、代码、字段增删改只能复制粘贴（规则25）
2. **应用ID和表单UUID必须填真实值** — 从系统配置清单.md读取，严禁占位符（规则24）
3. **写入文件前必须校验** — 运行 `node scripts/ai-validator.js check-before-write <文件路径>` 确认不覆盖已有文件
4. **写入文件后必须校验** — 运行 `node scripts/ai-validator.js check-after-write <文件路径>` 确认内容合规
5. **Cookie必须使用根目录** — 严禁 process.cwd()，必须用 PROJECT_ROOT（规则26）

### 专属硬规则
1. **只更新文档不创建表单** — 本Skill只修改字段清单.md和表单清单.md，不创建宜搭表单
2. **字段清单.md始终在01需求梳理/目录下** — 路径规则：项目根目录/01需求梳理/字段清单.md

## 功能概述

本Skill用于**在指定目录下设计表单字段结构**，在正式创建宜搭表单之前，先更新项目文档：

1. **新增表单**：在指定目录的字段清单.md中添加新表单的字段描述
2. **更新表单**：修改字段清单.md中已有表单的字段
3. **生成表单清单**：自动在表单清单.md中添加/更新表单条目
4. **字段智能识别**：根据描述自动判断字段类型

**重要：本Skill只更新文档，不创建宜搭表单！**

## 与form\_creator的配合

```
设计表单需求
    ↓
调用 表单设计（本Skill）
    ↓
更新 字段清单.md + 表单清单.md
    ↓
用户确认（可多次修改，再次调用表单设计）
    ↓
确认后调用 form_creator
    ↓
生成JSON + 创建宜搭表单
```

## 使用场景

### 场景1：在指定目录下设计新表单

**触发词**：

- "在xxx目录下设计一个表单"
- "在d:\项目\进销存目录下设计一个库存预警表单"
- "在跨表单测试目录下设计一个报工表单"

**执行逻辑**：

1. 在指定目录下创建/读取 `字段清单.md` 和 `表单清单.md`
2. 根据用户描述，在字段清单末尾添加新表单的字段描述
3. 在表单清单中添加新表单条目
4. 显示更新后的内容预览

**命令**：

```powershell
node .agents/skills/form_planner/scripts/update_field_list.js "<目录路径>" "<表单名称>" "<表单类型>" "<字段描述>"
```

**示例**：

```powershell
# 在指定目录下设计表单
node .agents/skills/form_planner/scripts/update_field_list.js "./跨表单测试/01需求梳理" "报工登记" "普通表单" "包含提交部门、提交日期、提交人、工序等字段"
```

### 场景2：更新现有表单的字段

**触发词**：

- "更新xxx目录下的库存盘点表单，添加盘点类型字段"
- "修改xxx目录下的产品信息表单，增加规格型号字段"

**执行逻辑**：

1. 读取指定目录下的 `字段清单.md`
2. 找到指定的表单
3. 根据用户描述添加/修改字段
4. 显示更新后的内容预览

**命令**：

```powershell
node .agents/skills/form_planner/scripts/update_field_list.js "<目录路径>" "<表单名称>" --update "<更新描述>"
```

### 场景3：从自然语言描述生成字段

**触发词**：

- "在xxx目录下设计一个请假申请表单，包含请假类型、开始日期、结束日期、请假事由"
- "在xxx目录下设计一个报销表单，需要报销类型、金额、发票、审批人"

**执行逻辑**：

1. 解析用户的自然语言描述
2. 智能识别字段名称和类型
3. 生成标准格式的字段清单条目
4. 更新文档

## 字段清单格式规范

生成的字段清单遵循以下标准格式：

```markdown
### (一) 表单名称「表单类型」

| 字段名称 | 字段类型 | 字段说明 | 字段状态 | 是否必填 |
|---------|---------|---------|---------|---------|
| 字段1 | 单行文本 | 说明 | 普通 | 是 |
| 字段2 | 数值 | 2位小数，单位：元 | 普通 | 否 |

**子表：明细**

| 字段名称 | 字段类型 | 字段说明 | 字段状态 | 是否必填 |
|---------|---------|---------|---------|---------|
| 子字段1 | 单行文本 | 说明 | 普通 | 是 |
```

### 字段清单文件处理逻辑

脚本对 `字段清单.md` 的处理逻辑：

| 场景 | 处理方式 |
|------|---------|
| **文件已存在** | 直接读取现有文件，在末尾追加新表单内容 |
| **文件不存在** | 创建新文件（兼容老应用同步场景） |

**路径规则：**
- 字段清单.md 始终位于 `01需求梳理/字段清单.md`
- 支持两种传入方式：
  - 传入项目根目录（如 `d:\项目\客户管理`）
  - 传入 01需求梳理 目录（如 `d:\项目\客户管理\01需求梳理`）

**示例：**
- 用户传入：`d:\项目\客户管理`
- 实际字段清单路径：`d:\项目\客户管理\01需求梳理\字段清单.md`
- 实际表单清单路径：`d:\项目\客户管理\表单清单.md`

## 核心脚本说明

### update\_field\_list.js

主脚本，负责更新字段清单和表单清单。

**用法**：

```powershell
node update_field_list.js <目录路径> <表单名称> <表单类型> [描述]
```

**参数**：

- `目录路径`：目标目录路径（如 "./跨表单测试/01需求梳理"）
- `表单名称`：表单名称
- `表单类型`：普通表单/流程表单
- `描述`：可选，字段描述（自然语言）

**选项**：

- `--update`：更新模式，修改现有表单
- `--module`：指定模块名称
- `--fields`：直接指定字段JSON

**示例**：

```powershell
# 在指定目录下新增表单
node update_field_list.js "./跨表单测试/01需求梳理" "报工登记" "普通表单" "包含提交部门、提交日期、提交人、工序等字段"

# 更新指定目录下的表单
node update_field_list.js "./跨表单测试/01需求梳理" "库存盘点" --update "添加盘点类型字段"
```

## 注意事项

1. **只更新文档**：本Skill只修改 `字段清单.md` 和 `表单清单.md`，不创建宜搭表单
2. **确认后再生成**：用户需要确认字段清单内容后，再调用 form\_creator 生成实际表单
3. **可多次修改**：在生成之前可以多次调用本Skill修改字段定义
4. **备份建议**：重要修改前建议备份字段清单文件
5. **字段清单文件处理**：
   - 字段清单.md 始终位于 `01需求梳理/字段清单.md`
   - **文件存在**：直接追加新表单内容到现有文件
   - **文件不存在**：自动创建新文件
6. **标准项目结构**：所有应用的表单字段清单都统一放在 `项目根目录/01需求梳理/字段清单.md`
