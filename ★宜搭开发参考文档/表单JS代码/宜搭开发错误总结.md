# 宜搭开发错误总结

本文档汇总了在多销售订单合并成采购订单功能开发过程中遇到的所有错误及其解决方案，为后续宜搭开发提供参考。

## 一、语法兼容性错误

### 1.1 ES6+语法不支持

**错误表现**：
- 编译错误提示"请检查页面 JS 中的相关代码"
- 代码在本地测试正常，但在宜搭环境中无法运行

**具体错误示例**：
```javascript
// ❌ 错误：可选链操作符不支持
const errorMsg = detailResult?.message || '获取失败';

// ❌ 错误：箭头函数不支持
selectedOrders.forEach(order => { ... });

// ❌ 错误：模板字符串不支持
console.log(`订单ID: ${orderId}`);

// ❌ 错误：解构赋值不支持
const { orderNo, detailList } = result;

// ❌ 错误：const/let声明不支持
const selectedOrders = this.$(fieldId).getValue();
```

**解决方案**：
```javascript
// ✅ 正确：传统判断方式
var errorMsg = (detailResult && detailResult.message) ? detailResult.message : '获取失败';

// ✅ 正确：传统for循环
for (var i = 0; i < selectedOrders.length; i++) {
  var order = selectedOrders[i];
  // ...
}

// ✅ 正确：字符串拼接
console.log('订单ID: ' + orderId);

// ✅ 正确：传统赋值
var orderNo = result.orderNo;
var detailList = result.detailList;

// ✅ 正确：var声明
var selectedOrders = this.$(fieldId).getValue();
```

**经验总结**：
- 宜搭平台仅支持ES5语法，所有现代JavaScript特性都不支持
- 开发前必须确认平台语法支持范围
- 建议使用ES5兼容版本作为开发基础

if (order && order.value) {

## 三、API参数错误

### 3.1 参数类型错误

**错误表现**：
- "参数校验失败pageSize"错误（code: 500）
- 明细数据无法加载

**错误原因**：
不同接口对参数类型要求可能不同，大多数接口使用数值类型，少数可能使用字符串类型。

**排查方法**：
1. 先尝试不传`pageSize`和`currentPage`，使用接口默认值
2. 如需传参，**优先尝试数值类型**：`pageSize: 100`
3. 如果数值类型报错，再尝试字符串类型：`pageSize: '100'`

**错误代码**：
```javascript
// ❌ 错误：参数类型不匹配
that.dataSourceMap.getSalesOrderDetail.load({
  pageSize: '100',    // 可能是数值类型
  currentPage: '1'    // 可能是数值类型
});
```

**正确代码（优先使用数值类型）**：
```javascript
// ✅ 方案1：不传分页参数，使用默认值（推荐）
that.dataSourceMap.getSalesOrderDetail.load({
  // 不传 currentPage 和 pageSize
});

// ✅ 方案2：数值类型（大多数接口适用）
that.dataSourceMap.getSalesOrderDetail.load({
  pageSize: 100,
  currentPage: 1
});

// ✅ 方案3：字符串类型（少数接口需要）
that.dataSourceMap.getSalesOrderDetail.load({
  pageSize: '100',
  currentPage: '1'
});
```

### 3.2 参数值超出限制

**错误表现**：
- "参数校验失败pageSize"错误（code: 500）
- 参数类型正确但错误依然存在

**错误原因**：
宜搭跨表单查询API的`pageSize`参数有**最大值限制**，不同接口限制不同：

| 接口 | pageSize最大值 | 说明 |
|-----|---------------|------|
| `searchFormDatas.json` | 100 | 查询表单实例详情列表 |
| `listTableDataByFormInstIdAndTableId.json` | 50 | 查询子表单数据 |

**常见错误**：设置`pageSize: 1000`超出限制

**错误代码**：
```javascript
// ❌ 错误：pageSize超出最大值限制
this.dataSourceMap.crossFormQuery.load({
  pageSize: 1000  // 错误：超出100限制
});
```

**正确代码**：
```javascript
// ✅ 正确：符合接口限制
this.dataSourceMap.crossFormQuery.load({
  pageSize: 100   // 正确：不超过100
});
```

## 七、特殊组件查询条件处理

### 7.1 部门选择组件查询问题

**问题表现**：
- 使用部门选择组件作为查询条件时，明明有匹配数据却返回 `totalCount: 0`
- 控制台显示查询条件为对象格式，而非预期的标识值

**错误代码示例**：
```javascript
// ❌ 错误：直接使用部门对象作为查询条件
var departmentObj = this.$('departmentSelectField_xxx').getValue();
// departmentObj = {text: "生产部", value: "123456", key: "123456"}

var searchConditions = {};
searchConditions['departmentSelectField_xxx'] = departmentObj;  // ❌ 传入对象，查询失败
```

**正确做法**：
```javascript
// ✅ 正确：提取部门标识后再查询
var departmentObj = this.$('departmentSelectField_xxx').getValue();

// 提取部门ID（优先尝试value、key、label字段）
var deptId = null;
if (departmentObj) {
  if (typeof departmentObj === 'object') {
    deptId = departmentObj.value || departmentObj.key || departmentObj.label;
  } else {
    deptId = departmentObj;
  }
}

var searchConditions = {};
searchConditions['departmentSelectField_xxx'] = deptId;  // ✅ 传入标识值

// 添加调试日志确认提取正确
console.log('部门对象:', departmentObj);
console.log('提取的部门ID:', deptId);
```

**关键要点**：
| 要点 | 说明 |
|-----|------|
| 不要直接使用对象 | `departmentObj` 是对象，包含text/value/key等属性 |
| 提取标识字段 | 优先尝试 `value`、`key`、`label` 字段 |
| 查询格式 | 部门选择组件使用**数字或字符串**（不是数组） |
| 调试方法 | 使用 `console.log` 输出提取的 `deptId` 确认正确 |

## 八、跨表单数据查询常见问题

### 8.1 部门选择器值格式问题（跨表查询）

**问题表现**：
- 跨表查询时返回 `totalCount: 0`，明明目标表有匹配数据
- 控制台显示部门值被传递为 `[{value: "-1", text: "..."}]` 数组对象格式

**错误原因**：
部门选择器 `getValue()` 返回的是数组对象，而查询条件需要传递 `value` 属性的字符串值

**错误代码**：
```javascript
// ❌ 错误：直接使用部门对象数组
var department = this.$('departmentSelectField_xxx').getValue();
// department = [{value: "-1", text: "生产部"}]

var searchConditions = {};
searchConditions['departmentSelectField_xxx'] = department;  // ❌ 传入数组对象，查询失败
```

**正确做法**：
```javascript
// ✅ 正确：提取数组中第一个对象的value值
var department = this.$('departmentSelectField_xxx').getValue();

var departmentValue = '';
if (Array.isArray(department) && department.length > 0) {
  // 如果是数组，取第一个元素的value属性
  if (department[0] && department[0].value !== undefined) {
    departmentValue = department[0].value;
  } else {
    departmentValue = department[0];
  }
} else if (typeof department === 'object' && department !== null) {
  // 如果是对象，取value属性
  departmentValue = department.value || '';
} else {
  // 如果是字符串或其他类型，直接使用
  departmentValue = department;
}

var searchConditions = {};
searchConditions['departmentSelectField_xxx'] = departmentValue;  // ✅ 传入 "-1"
```

### 8.2 API返回数据结构层级问题

**问题表现**：
- 查询成功返回数据，但提取字段值时都是 `undefined`
- 控制台显示 `formDataKeys` 可用，但直接访问字段ID获取不到值

**错误原因**：
宜搭跨表查询API返回的数据结构通常是 `{formData: {字段ID: 值}}`，而不是直接的 `{字段ID: 值}`

**错误代码**：
```javascript
// ❌ 错误：直接从sourceData读取字段
var employee = sourceData['employeeField_xxx'];  // undefined
```

**正确做法**：
```javascript
// ✅ 正确：从formData属性中读取字段
var formData = sourceData.formData || sourceData;
var employee = formData['employeeField_xxx'];  // 正确获取值
```

### 8.3 成员字段格式问题（子表填充）

**问题表现**：
- 子表其他字段都填充正确，但成员字段列显示为空
- 数据已正确查询到，但成员组件无法识别成员数据

**错误原因**：
宜搭成员字段需要特定的对象格式 `{emplId: "工号", name: "姓名"}`，而从API返回的数据可能格式不匹配

**错误代码**：
```javascript
// ❌ 错误：直接使用API返回的成员数据
var employee = formData['employeeField_xxx'];
rowData['employeeField_xxx'] = employee;  // 格式可能不匹配，无法显示
```

**正确做法**：
```javascript
// ✅ 正确：格式化成员字段数据
function formatEmployeeField(employee) {
  // 如果已经是对象且有emplId，直接返回
  if (employee && typeof employee === 'object' && employee.emplId) {
    return employee;
  }

  // 如果是数组，取第一个元素
  if (Array.isArray(employee) && employee.length > 0) {
    var firstEmployee = employee[0];
    if (firstEmployee && typeof firstEmployee === 'object' && firstEmployee.emplId) {
      return firstEmployee;
    }
    // 如果是字符串数组
    if (typeof firstEmployee === 'string') {
      return {
        emplId: firstEmployee,
        name: firstEmployee
      };
    }
  }

  // 如果是字符串
  if (typeof employee === 'string') {
    return {
      emplId: employee,
      name: employee
    };
  }

  // 其他情况，尝试直接返回
  return employee;
}

// 使用格式化函数
var employee = formData['employeeField_xxx'];
rowData['employeeField_xxx'] = formatEmployeeField(employee);  // ✅ 格式正确，可以显示
```

**关键要点**：
| 问题 | 原因 | 解决方案 |
|-----|------|---------|
| 部门查询无结果 | 部门值格式为数组对象 | 提取 `array[0].value` |
| 字段值为undefined | 数据在formData属性中 | 使用 `sourceData.formData` |
| 成员字段不显示 | 缺少emplId属性 | 格式化成员对象结构 |

### 8.4 人员选择组件数据格式问题（子表填充）

**问题表现**：
- 通过API查询员工工资表数据后，将人员信息填充到子表时，人员选择组件左侧列表不显示选中状态
- 点击人员选择组件，左侧组织架构中人员未被选中（没有蓝色选中标记）
- 数据联动无法触发，依赖数据联动的字段（如出勤天数）无法自动获取

**错误原因**：
宜搭人员选择组件需要特定的数据格式 `{label: "姓名", value: "用户ID", key: "用户ID", avatar: ""}`，但从API返回的数据只包含姓名，不包含用户ID。真实的用户ID存储在 `employeeField_xxxxxx_id` 字段中。

**API返回数据结构**：
```javascript
{
  "employeeField_mght567j": ["瞿观平"],              // 只有姓名
  "employeeField_mght567j_id": ["17724690495265646"]  // 用户ID在这里！
}
```

**错误代码**：
```javascript
// ❌ 错误：只使用姓名字段，缺少用户ID
var employeeValue = formData['employeeField_mght567j'];
detailItem['employeeField_xxx'] = {
  label: employeeValue[0],
  value: employeeValue[0],  // ❌ 错误：value应该是用户ID，不是姓名
  key: employeeValue[0]     // ❌ 错误：key应该是用户ID，不是姓名
};
// 结果：左侧列表不显示选中状态，数据联动不触发
```

**正确做法**：
```javascript
// ✅ 正确：同时读取姓名字段和ID字段
var employeeValue = formData['employeeField_mght567j'];      // 姓名
var employeeIdValue = formData['employeeField_mght567j_id']; // 用户ID

// 提取姓名
var employeeName = '';
if (employeeValue && Array.isArray(employeeValue) && employeeValue.length > 0) {
  employeeName = String(employeeValue[0]);
}

// 提取用户ID
var employeeId = '';
if (employeeIdValue && Array.isArray(employeeIdValue) && employeeIdValue.length > 0) {
  employeeId = String(employeeIdValue[0]);
}

// 构造完整的人员选择组件格式
if (employeeName || employeeId) {
  detailItem['employeeField_xxx'] = {
    label: employeeName || employeeId,  // 显示名称
    value: employeeId || employeeName,  // 用户ID
    key: employeeId || employeeName,    // 用户ID（与value相同）
    avatar: ''                          // 头像URL（可选）
  };
}
// 结果：左侧列表正确显示选中状态，数据联动正常触发
```

**关键要点**：
| 要点 | 说明 |
|-----|------|
| 人员字段有两个 | `employeeField_xxx` 存储姓名，`employeeField_xxx_id` 存储用户ID |
| 必须同时读取 | 不能只读姓名字段，必须同时读取 `_id` 后缀的字段获取用户ID |
| 正确格式 | `{label: "姓名", value: "用户ID", key: "用户ID", avatar: ""}` |
| value和key | 必须是真实的用户ID，不能是姓名，否则左侧列表无法显示选中状态 |
| 数据联动 | 只有使用正确的用户ID，数据联动才能正常触发 |

**调试方法**：
1. 在控制台输出完整的formData对象，查看人员字段的实际数据结构
2. 确认是否存在 `employeeField_xxx_id` 字段
3. 检查构造的数据格式是否正确（label/value/key/avatar）
4. 测试人员选择组件点击后左侧列表是否显示选中状态
