# 通用硬规则（绝对不可违反）

> 本文件是所有 skill 共用的「通用硬规则 1-5」唯一来源。各 SKILL.md 只引用本文件、不再逐字复制，
> 以避免多点维护导致规则漂移。修改通用硬规则时，只需在此处修改一次。

1. **禁止通过API修改已有应用的表单字段内容** — 公式、代码、字段增删改只能复制粘贴（规则25）
2. **应用ID和表单UUID必须填真实值** — 从系统配置清单.md读取，严禁占位符（规则24）
3. **写入文件前必须校验** — 运行 `node scripts/ai-validator.js check-before-write <文件路径>` 确认不覆盖已有文件
4. **写入文件后必须校验** — 运行 `node scripts/ai-validator.js check-after-write <文件路径>` 确认内容合规
5. **Cookie必须使用根目录** — 严禁 process.cwd()，必须用 PROJECT_ROOT（规则26）
6. **集成自动化（逻辑流）只允许通过 integration skill 的 CLI 创建/修改，保存后必须回读体检** — 禁止手写 processJson/viewJson、禁止直调 saveProcess.json；保存成功 ≠ 配置正确。权威源：`.agents/skills/integration/references/集成自动化硬规则.md`（改完跑 `node scripts/sync-hard-rules.js` 同步到 Trae/Cursor/AGENTS.md/CLAUDE.md）

## 校验脚本说明

- 校验脚本位于仓库根目录：`scripts/ai-validator.js`（真实存在，可直接运行）。
- 相关命令：
  - `node scripts/ai-validator.js check-before-write <文件路径>` — 写入前校验是否覆盖已有文件
  - `node scripts/ai-validator.js check-after-write <文件路径>` — 写入后校验文件内容是否合规
  - `node scripts/ai-validator.js check-fill-rule-syntax <文件路径>` — 校验关联表单填充规则语法（=号、分隔符）
- 说明：语法校验只能发现格式问题；字段语义正确性（目标表单是否存在、填充目标字段是否匹配）仍需人工逐条核对。
- 校验失败时命令以非零退出码结束（v1.8.0+），可直接接入 shell/CI 判断。

## 硬规则3-4的自动触发（不依赖人工记忆）

除 AI 按规则手动执行外，以下确定性触发点会自动运行校验并拦截违规：

- **git pre-commit 钩子**：每次 `git commit` 自动对暂存区业务产出物（字段清单/规则清单/序号提示词文件）执行 check-after-write 等校验，失败则中断提交。
  钩子源文件：`scripts/git-hooks/pre-commit`，由 `npm install`（prepare）或 `npm run hooks:install` 自动安装到 `.git/hooks/`。
- **npm 脚本 / CI**：`npm run validate:write` 全量扫描工作区业务产出物（含被 gitignore 的业务目录）；`npm run validate:staged` 只查暂存区。
- 逃生口：`SKIP_YIDA_VALIDATE=1` 可跳过钩子校验，但仅限用户明确批准后使用（同 `--force-save` 约束）。
