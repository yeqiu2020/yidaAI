## P16：关联表单字段6步闭环

**场景：** 关联表单字段完整走通6步闭环流程

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 关联与填充 |

**占位符：**
- `{源表单名称}` — 含关联字段的表单（如"库存信息"）
- `{关联字段名}` — 关联表单字段（如"选择仓库"）
- `{目标表单名称}` — 关联指向的表单（如"仓库信息"）
- `{目标表单UUID}` — 目标表单 UUID
- `{数据标题字段}` — 目标表单的数据标题字段

**前置条件：**
- {目标表单名称} 已有至少 1 条数据

**操作步骤（6步闭环）：**
1. **识别关联关系**：从字段清单找到 {关联字段名} → {目标表单名称}
2. **查询目标表单完整数据**：调用 `searchFormDatas.json`（带s）查询 {目标表单名称} 的所有记录
3. **建立映射表**：`instanceId → title`（title 从 formData 中提取 {数据标题字段} 的值）
4. **选取关联对**：从映射表中选取一条记录，获取 instanceId 和真实 title
5. **提交前自查**：instanceId 来自映射表？title = 映射表[instanceId]？被填充字段值来自关联记录 formData？
6. **提交后回查验证**：解析双重 JSON 字符串，验证 title 与 instanceId 指向的真实记录名称一致

**断言：**
- 第2步：查询结果非空
- 第3步：映射表中每条记录的 title 非空
- 第5步：自查 4 项全部 ✅
- 第6步：回查的 title 与映射表中该 instanceId 的真实名称一致

**产品依据：** data-tester SKILL.md "关联表单字段数据生成流程（6步闭环）"

## P17：关联字段 instanceId-title 一致

**场景：** 提交后回查关联字段，instanceId 与 title 指向同一条记录

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 关联与填充 |

**占位符：**
- 同 P16

**操作步骤：**
1. 提交含关联字段的数据（使用对象格式 `{instanceId, title}`）
2. 回查该记录
3. 找到 `{关联字段名}_id` 字段，双重 JSON.parse 解析
4. 对比解析出的 title 与映射表中该 instanceId 对应的真实名称

**断言：**
- 解析出的 instanceId = 提交时使用的 instanceId
- 解析出的 title = 映射表中该 instanceId 的真实名称
- 严禁 title 是 AI 编造的名称

**产品依据：** data-tester SKILL.md "【强制·v3.1.4】提交后必须通过API回查，验证关联字段的title与instanceId指向的真实记录名称是否一致"

## P20：多表单依赖顺序提交

**场景：** 多个表单按关联依赖顺序提交，确保关联字段有数据可填

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 关联与填充 |

**占位符：**
- `{表单列表及依赖顺序}` — 如"产品信息 → 仓库信息 → 客户信息 → 供应商信息 → 库存信息"
- `{关联字段映射}` — 哪个表单的哪个字段关联哪个表单

**操作步骤：**
1. 分析字段清单，找出所有关联字段，建立依赖关系图
2. 拓扑排序：被关联的表单在前
3. 按顺序逐个生成数据并提交
4. 当前表单提交成功后，才处理依赖它的表单

**断言：**
- 每个表单的关联字段都能查到目标表单的数据
- 无空关联、无伪造 instanceId

**产品依据：** data-tester SKILL.md "【强制·v3.1.3】表单依赖分析与顺序生成流程"；project_memory.md "正确数据生成顺序"
