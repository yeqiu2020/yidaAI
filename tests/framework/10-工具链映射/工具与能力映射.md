## 一、五方角色与工具映射

### 1.1 角色定义

| 角色 | 职责 | Session 要求 | KPI 互斥 |
|------|------|-------------|---------|
| **发起方** | 启动测试任务，定义测试目标和应用范围 | 主 Session | 与修复方互斥 |
| **用例编写方** | 从应用配置中提取测试用例，定义预期和断言 | 独立 Session | 与测试方互斥 |
| **测试方** | 执行测试用例，记录四元结果，发现 ISS | 独立 Session | 与修复方互斥 |
| **修复方** | 分析根因，分层修复，生成回归用例 | 主 Session | 与测试方、核验方互斥 |
| **核验方** | 独立验证修复效果，判定伪问题 | 与测试方同 Session | 与修复方互斥 |

### 1.2 工具到角色的映射

| 工具/Skill | 主要角色 | 次要角色 | 能力范围 |
|-----------|---------|---------|---------|
| **AI 主助手**（Trae IDE） | 发起方 | 修复方（工具链层） | 任务分发、Session 管理、工具链脚本编辑 |
| **data-tester** | 测试方 | — | 宜搭 API 数据提交测试、公式验证、流程审批、业务规则测试 |
| **js-action-tester** | 测试方 | — | 宜搭表单 JS 动作代码测试（字段联动、条件显示等 UI 交互） |
| **playwright-cli** | 测试方 | — | 通用浏览器自动化测试（自定义页面、报表、复杂 UI 场景） |
| **app-tester** | 测试方 | 核验方 | E2E 应用测试、回归测试 |
| **formula-generator** | 修复方 | — | 生成修复公式（应用配置层修复产物） |
| **code-expert** | 修复方 | — | 生成修复代码（表单动作、字段校验等） |
| **business-rule** | 修复方 | — | 配置业务关联规则（INSERT/UPDATE/DELETE/UPSERT） |
| **form_designer** | 修复方 | — | 设计/更新表单字段结构 |

| **data-clean** | 修复方 | — | 清理测试产生的脏数据 |
| **Jest**（`npm test`） | 测试方 | 核验方 | 工具链单元测试、回归测试 |

## 二、测试方工具能力清单

### 2.1 data-tester（宜搭 API 测试）

**能力域覆盖：**
- 数据提交（普通表单、流程表单）
- 公式计算验证
- 校验规则触发
- 业务规则自动化
- 关联表单数据填充
- 子表单数据完整性
- 流程审批流转

**执行方式：**
- API 模式：直接调用宜搭 Web API，速度快，适合批量测试
- 浏览器模式：模拟真实用户操作，适合测试前端交互

**关键约束：**
- 所有字段必须生成数据（除宜搭 API 不支持的6种类型）
- 关联字段必须走6步闭环流程
- 批量提交必须按依赖顺序
- 提交后必须 API 回查验证

**测试数据规范：**
- 公司名：城市+核心词+行业词+后缀（如"武汉华信电子科技有限公司"）
- 产品名：真实市场产品（如"iPhone 15 Pro Max 256GB"）
- 人名：常见中文名（如"张伟"）
- 地址：真实行政区划
- 测试数据前缀：`E2E_`（便于清理）

### 2.2 js-action-tester（UI 交互测试）

**能力域覆盖：**
- 字段联动规则
- 条件显示逻辑
- 表单动作代码
- 字段事件绑定（onChange 等）

**执行方式：**
- 通过 API 自动创建测试表单（专用测试应用）
- 通过 Playwright 上传 JS 代码并绑定事件
- 自动执行测试并生成报告

**关键约束：**
- 只操作专用测试表单，严禁在业务表单上执行测试
- 测试完成后提供清理测试表单功能
- 受规则25约束，不修改已有应用的表单字段

### 2.3 playwright-cli（通用浏览器自动化）

**能力域覆盖：**
- 自定义页面交互
- 报表数据统计验证
- 复杂 UI 场景（多步骤、跨页面）
- 权限越权拦截测试

**执行方式：**
- Playwright 脚本驱动浏览器
- 支持截图、DOM 状态捕获、控制台日志收集

### 2.4 Jest（工具链单元测试）

**能力域覆盖：**
- AI 工具链核心模块（`lib/core/`）
- AI 工具链特性功能（`lib/features/`）
- 公式 marks 计算
- 危险操作校验
- Cookie 脱敏
- 路径注入防护

**执行命令：**
- `npm test`：全部测试 + 覆盖率
- `npm run test:core`：仅核心模块
- `npm run test:features`：仅特性模块

**覆盖率要求：**
- `lib/core/chalk.js`：statements ≥ 80%
- `lib/core/error.js`：statements ≥ 90%
- `lib/core/spawn.js`：statements ≥ 80%
- `lib/core/utils.js`：statements ≥ 55%
- `lib/core/http.js`：statements ≥ 25%
- `lib/core/login-manager.js`：statements ≥ 15%

## 三、修复方工具能力清单

### 3.1 三层修复与工具映射

| 修复层级 | 适用场景 | 修复工具 | 修复方式 | 规则25约束 |
|---------|---------|---------|---------|-----------|
| **工具链层** | AI 工具链 Skill 脚本缺陷 | AI 主助手直接编辑 | 编辑 `.js` 文件 + 更新 FW 编号 | 不适用 |
| **应用配置层** | 宜搭应用公式/代码/字段/规则问题 | formula-generator / code-expert / business-rule / form_designer / flow-settings | 本地生成修复产物 + 粘贴指引 | **强制**：用户手动粘贴 |
| **数据层** | 数据本身问题（关联错配、空字段、重复数据） | data-tester / data-clean | 重新提交或清理 | 不适用 |

### 3.2 formula-generator（公式修复）

**修复范围：**
- 表单字段公式
- 报表计算公式
- 自动化公式

**修复产物：**
- 公式 JSON 文件（含精确计算的 marks）
- 粘贴指引（用户手动粘贴到宜搭表单设计器）

**关键约束：**
- marks 必须通过脚本精确计算，不能估算
- 公式中涉及的函数必须有来源（文档或官方）

### 3.3 code-expert（代码修复）

**修复范围：**
- 表单动作代码
- 字段校验规则代码
- 跨表单代码
- 集成自动化代码

**修复产物：**
- JS 代码文件
- 粘贴指引（用户手动粘贴到宜搭 JS 面板）

### 3.4 business-rule（业务规则修复）

**修复范围：**
- 业务关联规则（INSERT/UPDATE/DELETE/UPSERT）
- 跨表增删改
- 提交后联动

**修复产物：**
- 规则配置说明
- 粘贴指引（用户手动在表单设置→表单事件→公式执行中配置）

### 3.5 data-clean（数据清理）

**修复范围：**
- 清理测试产生的脏数据
- 清理关联错配的记录
- 清理重复提交的数据

**执行方式：**
- 通过 API 批量删除指定表单的数据记录
- 保留表单结构，仅删除数据

## 四、多工具协作工作流

### 4.1 标准测试-修复-验证流程

```
1. 发起方（AI 主助手）接收用户测试需求
   ↓
2. 用例编写方（独立 Session）提取测试用例
   - 读取字段清单、规则清单、系统配置清单
   - 输出 [进行中]提取用例-{批次号}.md
   ↓
3. 测试方（独立 Session）执行测试
   - data-tester：API 层测试
   - js-action-tester：UI 交互测试
   - playwright-cli：复杂 UI 场景
   - Jest：工具链单元测试
   - 输出 [进行中]沟通记录-{批次号}.md
   ↓
4. 修复方（主 Session）分析根因并修复
   - 工具链层：直接编辑 Skill 脚本
   - 应用配置层：生成修复产物 + 粘贴指引（规则25）
   - 数据层：data-tester 重新提交 / data-clean 清理
   - 输出 [进行中]问题跟踪-{批次号}.md
   ↓
5. 核验方（与测试方同 Session）验证修复效果
   - API 回查 / UI 复测 / Jest 回归
   - 判定伪问题（9类）
   - 更新问题跟踪文档
   ↓
6. 归档门禁检查
   - 核心 Smoke 100% PASS
   - 负面 Smoke 100% PASS
   - 工具链 npm test PASS
   - SKIP 率 ≤ 20%
   - 任何 FAIL 不得归档
   ↓
7. 归档（修复方协助用户）
   - 输出 [已归档]沟通记录-{批次号}.md
   - 输出 [已归档]问题跟踪-{批次号}.md
   - 更新能力覆盖矩阵
   - 更新 Smoke 回归集
```

### 4.2 工具调度示例

**场景：测试一个进销存应用的"库存信息"表单**

```
发起方：AI 主助手
├── 用例编写方（独立 Session）
│   └── 读取 进销存/01需求梳理/字段清单.md
│       输出提取用例文档
│
├── 测试方（独立 Session）
│   ├── data-tester
│   │   ├── 提交测试数据（按依赖顺序：仓库→产品→库存）
│   │   ├── 验证关联字段6步闭环
│   │   ├── 回查所有字段是否成功写入
│   │   └── 验证公式计算结果
│   ├── js-action-tester
│   │   └── 测试字段联动和条件显示
│   └── Jest (npm test)
│       └── 确认工具链本身健康
│
├── 修复方（主 Session）
│   ├── [工具链层] 编辑 submitter.js（如发现关联字段提取缺陷）
│   ├── [应用配置层] formula-generator（如发现公式错误）
│   │   └── 生成修复公式 + 粘贴指引
│   ├── [应用配置层] code-expert（如发现 JS 动作代码错误）
│   │   └── 生成修复代码 + 粘贴指引
│   └── [数据层] data-clean（如发现测试数据污染）
│       └── 清理 E2E_ 前缀的测试数据
│
└── 核验方（与测试方同 Session）
    ├── data-tester（API 回查）
    ├── js-action-tester（UI 复测）
    └── Jest（回归测试）
```

## 五、工具健康检查

### 5.1 工具链健康检查（每次归档前必做）

| 检查项 | 命令 | 通过标准 | 失败处理 |
|--------|------|---------|---------|
| 工具链单元测试 | `npm test` | 所有测试 PASS，覆盖率达标 | 修复工具链问题后重试 |
| 核心模块测试 | `npm run test:core` | 所有测试 PASS | 修复 lib/core 问题后重试 |
| 特性模块测试 | `npm run test:features` | 所有测试 PASS | 修复 lib/features 问题后重试 |

### 5.2 Skill 健康检查

| Skill | 检查方式 | 关键文件 |
|-------|---------|---------|
| data-tester | 提交一条测试数据并回查 | `scripts/batch-submitter.js`、`scripts/submitter.js` |
| js-action-tester | 创建测试表单并上传代码 | `scripts/test-runner.js`、`scripts/login-handler.js` |
| formula-generator | 生成一个公式并验证 marks | `scripts/generate_formula.js` |
| code-expert | 生成一段代码并验证语法 | — |

### 5.3 环境健康检查

| 检查项 | 检查方式 | 通过标准 |
|--------|---------|---------|
| Cookie 有效性 | 读取 `.cookies.json` 并调用宜搭 API | API 返回非 401 |
| 应用 ID 有效性 | 从系统配置清单.md读取并验证 | 应用存在且可访问 |
| 表单 UUID 有效性 | 从系统配置清单.md读取并验证 | 表单存在且可访问 |
| Node.js 版本 | `node --version` | v16+ |
| Playwright 安装 | `npx playwright --version` | 已安装 |
