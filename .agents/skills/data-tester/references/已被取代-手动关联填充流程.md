# 【已被取代】手动关联字段填充流程（v3.1.3~v3.4.0 旧流程）

> ⚠️ **本流程已被 v3.5.0 的 `submitAllWithAutoAssociations`（一键自动关联提交）取代。**
> 按 v3.6.0"防翻车三原则"，**严禁自行预解析标题**（自行 `searchFormDatas` 查 instanceId 再填值会撞上宜搭搜索索引延迟窗口，产生"空关联"假数据）。
> 本文件仅作历史参考，供理解函数内部机制或极特殊场景（不涉及批量提交、目标数据早已存在且索引稳定）使用。

---

## 旧流程：关联字段处理（在调用 submitAllAIGeneratedData 前完成）

1. 先为无依赖的表单生成数据（产品、仓库、客户、供应商）
2. 调用 `searchFormDatas` 查询已提交的关联目标数据，`buildTitleMap` 建立映射
3. 从映射表中选取 instanceId 和 title，填入关联字段（如库存信息的选择仓库、选择产品）
4. 将所有表单数据一起传给 `submitAllAIGeneratedData`

**关联字段对象格式示例**（旧做法，需手动查询 instanceId）：

```javascript
const formDataMap = {
  // 关联字段的数据在提交前查询获取
  "库存信息": [
    { "选择仓库": {instanceId:"FINST-xxx",title:"武汉光谷中心仓"}, "选择产品": {instanceId:"FINST-yyy",title:"iPhone"}, ... },
  ],
};
```

**【强制】如果关联目标表单还没有数据**：
- **严禁跳过关联字段**：必须等待目标表单的数据生成完成
- **严禁提交空关联**：关联字段必须有有效的instanceId和title
- **正确做法**：先提交无依赖的表单，查询到数据后再为有依赖的表单填写关联字段

## 旧流程：关联表单字段数据生成6步流程（v3.1.4）

1. 读取字段清单，找出所有"关联表单"字段及其目标表单
2. 调用 `searchFormDatas(appId, formUuid)` 查询目标表单的完整数据（含formData）
3. 调用 `buildReverseTitleMap(records)` 建立 title → instanceId 反向映射（v3.4.0 前需手动翻转 `buildTitleMap` 的正向结果，这是高频踩坑点）
4. 从映射表中选取 instanceId 和对应的**真实 title**，组装 `{instanceId, title}` 对象填入关联字段。**严禁推断title！**
5. 需要被填充字段值时用 `findRecordByTitle(records, title)` 一次获取 instanceId + formData
6. 提交后用 `verifyAssociationField(record, fieldId, titleMap)` 验证关联字段的 title 与 instanceId 指向的真实记录名称是否一致

## 为什么被取代

- 每步都要写内联 Node.js 脚本 + 调试 PowerShell 引号问题，4次脚本调用导致 20+ 分钟耗时（v3.5.0 根因分析）
- 基础数据刚提交时宜搭搜索索引有数秒延迟，预解析会查到空结果并产生"显示成功但关联为空"的假数据（v3.6.0 根因分析）
- 现在 `submitAllWithAutoAssociations` 内置：索引等待与轮询重试、自动查找 instanceId、被填充字段自动抄写（v3.7.1）、EmployeeField 自动填充（v3.7.2）、fail-fast 保护
