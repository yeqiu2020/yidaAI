# 原型页面菜单按分组渲染

## Context（背景）

**问题**：当前 `form-to-prototype` skill 生成的原型页面，左侧导航菜单把所有表单扁平地放在一个 `业务表单` 分组下（见用户截图 `aside` 元素），没有按照本地已同步的分组结构（如 `基础信息`、`销售管理`、`采购管理` 等）来组织。这与宜搭平台实际的分组展示不一致，也让用户难以从菜单路径感知表单所属模块。

**根因**（已通过代码审查确认）：
1. `renderMenu()`（[prototype_generator.js:3176](file:///d:/宜搭AI编程/宜搭AI助手V2.0.1/.agents/skills/form-to-prototype/scripts/prototype_generator.js#L3176)）客户端动态渲染菜单时，**只遍历 `FormConfig.staticConfigData` 的 key 输出扁平 `<a>` 列表**，没有按分组输出 `<div class="menu-group">`。
2. 运行时拿不到 `group` 字段：
   - `loadFormListFromConfig()`（[L1260](file:///d:/宜搭AI编程/宜搭AI助手V2.0.1/.agents/skills/form-to-prototype/scripts/prototype_generator.js#L1260)）从 `系统配置清单.md` 第5列读到 `group` 后，**只用于构建 `formPaths`，没保存到 `staticConfigData` / `FormConfigData`**。
   - `generateStaticConfigData()`（[L2091](file:///d:/宜搭AI编程/宜搭AI助手V2.0.1/.agents/skills/form-to-prototype/scripts/prototype_generator.js#L2091)）和 `generateFormConfigDataJs()`（[L2345](file:///d:/宜搭AI编程/宜搭AI助手V2.0.1/.agents/skills/form-to-prototype/scripts/prototype_generator.js#L2345)）生成时也没写入 `group`。
3. 4 个静态 HTML 模板（index/list/form/guide）都硬编码了 `<nav><div class="menu-group"><div class="menu-group-title">业务表单</div><div id="menuItems"></div></div></nav>` 这层包裹，导致 `renderMenu` 只能在 `#menuItems` 内部塞扁平项，无法生成多个并列的 `.menu-group`。

**目标**：以后生成的原型页面，左侧菜单按 `系统配置清单.md` 第5列「所属分组」组织，每个分组一个 `.menu-group` 块，标题为分组名，组内为该分组的表单链接。与宜搭平台分组保持一致，路径也更准确（分组路径已在 v2.12.0/v2.12.1 修复）。

## 改动范围

只改 1 个文件：`d:\宜搭AI编程\宜搭AI助手V2.0.1\.agents\skills\form-to-prototype\scripts\prototype_generator.js`

外加 1 个文件版本号更新：`.agents/skills/form-to-prototype/SKILL.md`

## 实施步骤

### 步骤 1：让运行时配置数据携带 `group` 字段

**1.1 `generateStaticConfigData()`（约 L2091-2097）**
在 `formConfigData[form.name] = { formName, formUuid, fields }` 中追加 `group: form.module || ''`。

**1.2 `generateFormConfigDataJs()`（约 L2345-2350）**
同上，在 `formConfigData[form.name] = { formName, formUuid, fields }` 中追加 `group: form.module || ''`。该函数生成 `form-config-data.js` 静态兜底文件。

**1.3 `loadFormListFromConfig()`（约 L1330-1351）**
两处创建新表单条目的地方都要补 `group`：
- 约 L1333：`this.staticConfigData[form.name] = { formName, formUuid, fields: [], group: form.group || '' }`
- 约 L1345：`window.FormConfigData[form.name] = { formName, fields: [], group: form.group || '' }`

> 注意：已存在的表单条目（由静态 JS 兜底文件预填）已带 `group`，无需覆盖；只对缺失的表单补 `group`。但要额外处理一种情况——静态 JS 兜底文件是旧版生成的（没有 `group` 字段），动态加载后应该**回填**已有条目的 `group`。所以在 L1330 的循环里改为：无论条目是否存在，都 `this.staticConfigData[form.name].group = form.group || ''`（同时保留原有 fields）。对 `window.FormConfigData` 同理。

### 步骤 2：修改 `renderMenu()` 按分组渲染（L3176-3189）

新逻辑：
1. 遍历 `FormConfig.staticConfigData`，读取每个表单的 `group` 字段，按分组聚合（用数组保序，不依赖对象 key 顺序）。
2. 没有分组字段的表单归入兜底分组 `业务表单`（保持向后兼容）。
3. 先输出 `开发引导` 作为独立的第一个菜单项（保留 `.guide-menu-item` 样式，不归属任何分组，视觉上置于顶部）。
4. 然后按分组顺序，每个分组输出：
   ```html
   <div class="menu-group">
     <div class="menu-group-title">{分组名}</div>
     <div>
       <a href="..." class="menu-item" data-form="...">{表单名}</a>
       ...
     </div>
   </div>
   ```
5. 流程表单的 `▸` 标记（`.menu-item.process`）保留原有逻辑。

伪代码：
```js
function renderMenu(containerId, linkPrefix) {
  const container = document.getElementById(containerId);
  if (!container || typeof FormConfig === 'undefined') return;

  // 1. 聚合分组（保序）
  const groupOrder = [];
  const groupMap = {};
  for (const name of Object.keys(FormConfig.staticConfigData)) {
    const cfg = FormConfig.staticConfigData[name];
    const g = (cfg && cfg.group) ? cfg.group : '业务表单';
    if (!groupMap[g]) { groupMap[g] = []; groupOrder.push(g); }
    groupMap[g].push(name);
  }

  // 2. 开发引导（独立首项，不进分组）
  let html = '<a href="' + linkPrefix + 'guide.html" class="menu-item guide-menu-item" data-form="__guide__">📋 开发引导</a>';

  // 3. 按分组输出
  for (const g of groupOrder) {
    html += '<div class="menu-group"><div class="menu-group-title">' + g + '</div><div>';
    for (const name of groupMap[g]) {
      const cfg = FormConfig.staticConfigData[name];
      const isProcess = cfg && cfg.fields && cfg.fields.some(f => f.componentType === '子表单' || f.componentType === 'TableField');
      // 注：原有 renderMenu 并未根据 process 加 class，process 标记来源于 generateMenuHtml（静态）
      // 这里用 formPaths 中的「流程表单」字样判断更可靠
      const path = FormConfig.formPaths[name] || '';
      const processClass = path.includes('「流程表单」') ? ' process' : '';
      html += '<a href="' + linkPrefix + 'list.html?form=' + encodeURIComponent(name) + '" class="menu-item' + processClass + '" data-form="' + name + '">' + name + '</a>';
    }
    html += '</div></div>';
  }

  container.innerHTML = html;
}
```

> 说明：原 `renderMenu` 没有给流程表单加 `.process` 类，是静态 `generateMenuHtml` 才加。这次顺手在动态渲染里补上，让流程表单的 `▸` 绿色标记也能在动态菜单中显示，与宜搭视觉更一致。判断依据用 `formPaths` 中的 `「流程表单」` 字样（最可靠，因为路径就来自系统配置清单）。

### 步骤 3：简化 4 个静态 HTML 模板的菜单结构

把硬编码的：
```html
<nav class="menu" id="mainMenu">
  <div class="menu-group">
    <div class="menu-group-title">业务表单</div>
    <div id="menuItems">
      <!-- 菜单项由JavaScript动态生成 -->
    </div>
  </div>
</nav>
```
改为：
```html
<nav class="menu" id="mainMenu">
  <div id="menuItems">
    <!-- 菜单（含分组）由JavaScript动态生成 -->
  </div>
</nav>
```

涉及 4 个生成函数：
- `generateIndexHtml()`（约 L420-424）
- `generateListTemplateHtml()`（约 L545-551）
- `generateFormTemplateHtml()`（约 L766-770）
- `generateGuideHtml()`（约 L982-985）

### 步骤 4：可选改进 - `renderQuickLinks()`（L3207-3226）

`index.html` 主内容区的快速链接卡片目前硬编码显示 `业务表单 - {typeDesc}`。改为显示 `{分组名} - {typeDesc}`，让首页卡片也体现分组信息。从 `FormConfig.staticConfigData[name].group` 读取，无 group 时回退 `业务表单`。

### 步骤 5：清理死代码（可选）

`generateMenuHtml()`（L241-262）是旧的静态菜单生成函数，现在 `menuHtml` 变量在 `generateIndexHtml`/`generateListTemplateHtml` 中被赋值但未注入模板，属于死代码。本次改动中**保留不动**，避免扩大改动面（如果用户后续要回退到静态菜单，这个函数还有用）。

## 风险与回退

- **风险**：旧版生成的原型页面（已存在的项目）不会自动应用新菜单结构，需要重新生成 `form-config.js` / `form-config-data.js` / 4 个 HTML 模板。可用 `--form-config-only` 参数部分更新（但 4 个 HTML 模板需要完整重新生成）。
- **回退**：所有改动集中在 1 个 .js 文件和 1 个 .md 文件，git 回退即可。
