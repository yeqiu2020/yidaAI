## 🔴 硬规则（绝对不可违反）

### 通用硬规则
1. **禁止通过API修改已有应用的表单字段内容** — 公式、代码、字段增删改只能复制粘贴（规则25）
2. **应用ID和表单UUID必须填真实值** — 从系统配置清单.md读取，严禁占位符（规则24）
3. **写入文件前必须校验** — 运行 `node scripts/ai-validator.js check-before-write <文件路径>` 确认不覆盖已有文件
4. **写入文件后必须校验** — 运行 `node scripts/ai-validator.js check-after-write <文件路径>` 确认内容合规
5. **Cookie必须使用根目录** — 严禁 process.cwd()，必须用 PROJECT_ROOT（规则26）

### 专属硬规则
1. **每个提示词必须是独立文件** — 严禁修改/覆盖/删除已有提示词文件，只能新建（规则20/22）
2. **新文件序号 = 目录最大序号 + 1** — 生成前必须运行 `node scripts/ai-validator.js scan-dir <目录>` 获取正确序号
3. **生成前必须运行前置校验** — `node scripts/ai-validator.js check-prompt <目录> <文件名>` 确认文件可安全创建
4. **公式函数必须有来源** — 严禁编造不存在的函数
5. **只生成提示词不生成代码/公式** — 说"写代码"→code-expert，说"写公式"→formula-generator（规则12）

## ⚠️ 重要规则（必须遵守）

### 规则1：只生成提示词，不生成代码

**当用户明确要求"生成提示词"时，绝对禁止直接生成代码实现。**

正确做法：

- ✅ 只生成纯提示词文件（包含需求描述、字段ID清单、功能要求等）
- ✅ 提示词中标记状态为"⏳ 待生成"
- ✅ 等待用户确认提示词后，再生成代码

错误做法（严禁）：

- ❌ 在提示词文件中包含代码实现
- ❌ 自作主张直接生成代码文件
- ❌ 在对话框中输出代码内容

### 规则2：区分"提示词"和"代码/公式"

| 用户指令        | 系统行为                                 |
| --------------- | ---------------------------------------- |
| "生成提示词"    | 本Skill生成提示词文件，不包含代码       |
| "生成代码"      | → 调用 code-expert 生成代码实现          |
| "编写/创建代码" | → 调用 code-expert 生成代码实现          |
| "帮我写公式"    | → 调用 formula-generator 生成公式实现    |
| "写提示词"      | 本Skill生成提示词文件                   |

### 规则3：必须使用模板（极其重要）

**生成提示词时，必须严格按照模板文件中的格式，绝对禁止自由发挥。**

## 功能概述

本 Skill 用于帮助用户将自然语言描述的需求转换为规范的宜搭提示词文件。主要解决以下问题：

1. **简化用户输入**: 用户只需描述需求，无需手动查找字段ID、表单ID
2. **确保准确性**: 自动从系统配置清单读取准确的ID信息
3. **规范管理**: 统一提示词格式，集中存储在表单目录下
4. **降低错误**: 每个提示词后强制添加字段ID核对警告

## 工作流程

```
用户描述需求
    ↓
识别需求类型（公式/代码）
    ↓
读取系统配置清单 → 获取应用ID、表单UUID
    ↓
读取组件ID清单 → 获取字段ID
    ↓
匹配提示词模板 → 生成规范提示词
    ↓
保存到表单目录/功能提示词.md
    ↓
展示给用户确认
    ↓
用户确认后调用代码/公式生成 Skill
```

## 使用场景

### 场景1：生成公式提示词

**用户说**: "产品信息表，计算开始日期和结束日期的小时差"

**系统执行**:

1. 识别表单：产品信息
2. 识别需求类型：表单公式 - 日期计算
3. 读取组件ID清单，找到日期字段
4. 生成提示词并保存

### 场景2：生成代码提示词

**用户说**: "采购入库单，提交时校验库存是否充足"

**系统执行**:

1. 识别表单：采购入库
2. 识别需求类型：跨表单代码 - 库存校验
3. 读取系统配置，获取关联表单信息
4. 生成提示词并保存

## 实现步骤

### 步骤1：解析用户需求

1. 识别目标表单（从用户描述中提取）
2. 识别需求类型（公式/代码/表单/流程）
3. 识别具体功能（日期计算/库存校验等）
4. 识别涉及的字段（通过语义匹配）

### 步骤2：读取配置信息

1. **读取 `系统配置清单.md` 获取（极其重要）**：

   - 应用ID
   - 表单UUID
   - 表单类型（普通表单/流程表单）
   
   > ⚠️ **强制规则：获取到的应用ID和表单UUID必须直接填入提示词/代码中，严禁留占位符如 `{APP_ID}`、`{FORM_UUID}`、`FORM-XXX`、`需从系统配置获取` 等！**
   > 
   > **查找方法**：从 `系统配置清单.md` 的「表单ID清单」表格中找到对应表单名称的那一行，提取表单UUID；从「应用信息」表格中提取应用ID。

2. 读取 `组件ID清单.md` 获取：

   - 字段名称
   - 字段ID
   - 字段类型
   - 子表结构

### 步骤3：选择提示词模板和生成目录

#### 3.1 模板选择

根据需求复杂度自动选择模板：

- **简单公式**（1-3个字段）→ 简版模板
- **复杂公式**（子表/多条件）→ 完整版模板
- **单表代码** → 表单动作代码模板
- **跨表代码** → 跨表单代码模板
- **字段校验** → 字段校验代码模板
- **自定义页面** → 自定义页面代码模板
- **集成自动化** → 集成自动化脚本模板

#### 3.2 生成目录选择（⚠️ 极其重要）

根据使用场景动态选择生成目录：

**场景案例模式**（用于通用场景库）：

```
表单动作代码 → 【表单动作代码/通用场景案例/{分类}】
跨表单代码   → 【表单动作代码/通用场景案例/跨表操作】
字段校验代码 → 【字段校验代码/通用场景案例】
自定义页面   → 【自定义页面/通用场景案例/{分类}】
集成自动化   → 【集成自动化/通用场景案例/{分类}】
```

**项目案例模式**（用于具体项目）：

```
所有代码类型 → 【{项目目录}/{表单目录}/代码/】
```

**选择逻辑**：

1. 如果用户指定了具体项目路径 → 使用项目案例模式
2. 如果用户说"生成场景案例"或"添加到案例库" → 使用场景案例模式
3. 默认根据当前工作目录判断：
   - 如果在项目目录下 → 项目案例模式
   - 如果在案例库目录下 → 场景案例模式

### 步骤4：匹配字段

使用模糊匹配算法：

- 用户说"开始日期" → 匹配包含"开始"、"起始"的日期字段
- 用户说"产品名称" → 匹配包含"产品"、"名称"的文本字段
- 用户说"数量" → 匹配包含"数量"、"个数"、"件数"的数值字段

### 步骤5：生成提示词

1. 加载对应类型的提示词模板
2. 填充字段ID、表单ID等信息
3. **填写跨表单请求参数（极其重要）**：
   - 必须从 `系统配置清单.md` 读取真实的**应用ID**和**目标表单UUID**
   - 直接填入提示词的「跨表请求参数」表格中，严禁留 `需从系统配置获取`、`{APP_ID}`、`{FORM_UUID}` 等占位符
4. 添加警告标识
5. 生成完整的提示词内容

### 步骤6：保存文件（v2.3.0更新 - 独立文件模式）

⚠️ **【强制】保存前必须遵守以下三条铁律，违反任何一条即为严重错误！**

#### 铁律1：严禁合并提示词到已有文件

- ❌ **禁止**：将新提示词追加到已有的提示词文件中
- ❌ **禁止**：将多个提示词合并到一个"汇总文件"中
- ✅ **正确**：每个提示词创建一个独立的新文件
- **根因**：合并文件会导致已有文件被误删、内容混乱、编号冲突

#### 铁律2：严禁删除已有提示词文件

- ❌ **禁止**：删除已有的提示词文件或代码文件（除非用户明确要求）
- ❌ **禁止**：因为"合并后冗余"而删除原有独立文件
- ✅ **正确**：新增提示词时只创建新文件，不触碰已有文件
- **根因**：误删会导致不可恢复的数据丢失

#### 铁律3：必须先扫描目录确定序号

- ❌ **禁止**：不扫描目录就直接用"1"作为新文件序号
- ❌ **禁止**：多个文件使用相同的序号
- ✅ **正确**：先 `LS` 目标目录 → 找到最大序号 → 新序号 = 最大序号 + 1
- **根因**：序号冲突会导致文件管理混乱，无法一一对应

> **关于规则13（新提示词放最前面）的澄清**：
> 规则13仅适用于**同一个文件内**的提示词列表排序。由于每个提示词必须是独立文件（规则20），因此每个独立文件内的提示词编号就是"提示词-1"，**不存在跨文件重新编号的场景**。

根据提示词类型，保存到独立的文件：

#### 6.1 公式类提示词保存（新规范）

⚠️ **【v2.3.0新规范 - 每个公式独立文件】**

保存步骤：

1. 检查目标表单目录下的 `公式/` 文件夹是否存在，不存在则创建
2. **确定序号**：扫描 `公式/` 目录，找到最大的序号，新公式序号 = 最大序号 + 1
   - 例如：已有 `1.成员合并公式提示词.md`，新公式就是 `2.xxx提示词.md`
3. **生成文件名**：`{序号}.{公式名称}提示词.md`
   - 例如：`1.成员合并公式提示词.md`
4. **写入文件**：将提示词内容写入独立文件
5. **关联公式JSON**：公式生成后保存为 `{序号}.{公式名称}.json`
   - 例如：`1.成员合并公式.json`

**文件命名规范**：

| 文件类型   | 命名格式                       | 示例                        |
| ---------- | ------------------------------ | --------------------------- |
| 提示词文件 | `{序号}.{公式名称}提示词.md` | `1.成员合并公式提示词.md` |
| 公式JSON   | `{序号}.{公式名称}.json`     | `1.成员合并公式.json`     |

**文件路径示例**：

```
{项目目录}/{表单目录}/公式/
├── 1.成员合并公式提示词.md
├── 1.成员合并公式.json
├── 2.年龄计算公式提示词.md
├── 2.年龄计算公式.json
└── ...
```

#### 6.2 代码类提示词保存（新规范）

⚠️ **【v2.3.0新规范 - 每个代码独立文件】**

保存步骤：

1. 检查目标表单目录下的 `代码/` 文件夹是否存在，不存在则创建
2. **确定序号**：扫描 `代码/` 目录，找到最大的序号，新代码序号 = 最大序号 + 1
3. **生成文件名**：`{序号}.{代码名称}提示词.md`
   - 例如：`1.库存校验提示词.md`
4. **写入文件**：将提示词内容写入独立文件
5. **关联代码文件**：代码生成后保存为 `{序号}.{代码名称}.js`
   - 例如：`1.库存校验.js`

**文件命名规范**：

| 文件类型   | 命名格式                       | 示例                    |
| ---------- | ------------------------------ | ----------------------- |
| 提示词文件 | `{序号}.{代码名称}提示词.md` | `1.库存校验提示词.md` |
| 代码JS文件 | `{序号}.{代码名称}.js`       | `1.库存校验.js`       |

**文件路径示例**：

```
{项目目录}/{表单目录}/代码/
├── 1.库存校验提示词.md
├── 1.库存校验.js
```

## 错误处理

### 常见错误及处理

1. **找不到表单**

   - 提示："未找到名为'XXX'的表单，请确认表单名称是否正确"
