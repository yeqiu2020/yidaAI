## 目录结构规范

### 源文件与生成目标分离

为了避免误删用户源文件，采用**源文件目录**和**生成目标目录**完全分离的结构：

| 目录类型 | 路径 | 用途 |
|---------|------|------|
| **源文件目录** | `流程及字段梳理/项目名称/` | 存放用户提供的Markdown字段表、流程图等源文件 |
| **生成目标目录** | `项目/项目名称/` | 存放生成的宜搭表单JSON文件 |

### 源文件目录结构

```
AI编写宜搭字段V1.1/                      # 项目根目录
├── 流程及字段梳理/                        # 源文件根目录
│   ├── 出入库管理/                       # 项目文件夹
│   │   └── 出入库管理.md                  # 字段表源文件（Markdown格式）
│   ├── 进销存管理/
│   │   └── 进销存管理.md
│   └── 下单管理/
│       └── 下单管理流程图.drawio
└── ...
```

### 输出文件结构

**重要规则：优先使用用户指定的输出目录！**

#### 情况1：用户指定了输出目录（推荐）

如果用户明确说"生成到xxx目录"或提供了输出路径，**直接使用该目录**：

```
{用户指定目录}/                       # 用户指定的输出目录
├── 基础信息/                         # 模块文件夹
│   ├── 产品类别「普通表单」.json
│   ├── 产品信息「普通表单」.json
│   └── 仓库信息「普通表单」.json
├── 库存管理/
│   ├── 采购入库「流程表单」.json
│   ├── 销售出库「流程表单」.json
│   └── 库存盘点「普通表单」.json
└── 表单清单.md                       # 自动生成的表单清单
```

**关键规则：模块目录与 01需求梳理 在同一层级**
- 字段清单位置：`{项目目录}/01需求梳理/字段清单.md`
- 表单输出位置：`{项目目录}/`（直接输出到项目目录，不创建额外子目录）
- 业务模块目录（如 02基础信息、03库存管理）直接放在项目目录下

#### 情况2：用户未指定输出目录（默认）

- 项目模式默认输出到 `03项目交付物/{项目名称}/`
- 单表模式输出到 `02宜搭场景案例库/宜搭表单/`（独立参考案例，不参与项目工作流）
- 模块文件夹根据字段清单中的模块划分自动创建

### 目录层级规则（重要！）

**正确的目录结构：**
```
进销存管理/                    # 项目根目录
├── 01需求梳理/                # 源文件目录
│   ├── 字段清单.md
│   └── 规则清单.md
├── 02基础信息/                # ✅ 业务模块与 01需求梳理 同级
│   └── 产品信息「普通表单」/
├── 03库存管理/
│   └── 库存盘点「流程表单」/
└── 表单清单.md
```

**错误的目录结构（禁止）：**
```
进销存管理/
├── 01需求梳理/
│   └── 字段清单.md
└── 03-表单配置/               # ❌ 禁止创建额外子目录
    ├── 02基础信息/
    └── 03库存管理/
```

**核心原则：**
1. 业务模块目录（02基础信息、03库存管理等）直接放在项目目录下
2. 与 01需求梳理 目录保持同一层级
3. **禁止**自动创建 `03-表单配置` 或其他额外子目录
4. 如果用户指定了输出目录，直接使用该目录，不添加任何子目录

## 项目名称提取规则

**不要**使用文件名作为项目名称，而是**从文件内容的第一行标题提取**。

### 提取步骤

1. **读取Markdown文件第一行**，格式通常为：
   ```markdown
   # 出入库管理 - 表单字段清单
   # 进销存管理
   # 资产评估项目管理系统 - 字段表
   ```
2. **提取系统名称**：去掉 `#` 符号，提取 `-` 或空格之前的部分作为项目名称
3. **示例**：

   | Markdown第一行 | 提取的项目名称 |
   |---------------|--------------|
   | `# 出入库管理 - 表单字段清单` | `出入库管理` |
   | `# 进销存管理` | `进销存管理` |
   | `# 资产评估项目管理系统 - 字段表` | `资产评估项目管理系统` |
   | `# 下单管理系统流程图` | `下单管理系统` |

> ⚠️ 提取的项目名称仅用于本地目录命名与文档展示。宜搭**应用名称**必须使用本地项目文件夹名（专属硬规则4），严禁将字段清单标题中的系统名称传入 create_from_markdown.js。

### 重要注意事项

- **绝不修改源文件目录下的任何文件！绝不删除源文件目录！**
- 项目模式输出到 `{项目目录}/`，业务模块与 01需求梳理 同级
- 如果目标目录已存在，只覆盖其中的JSON文件，保留其他文件

## 单表模式 vs 项目模式

| 模式 | 输出位置 | 说明 |
|------|----------|------|
| **单表模式** | `02宜搭场景案例库/宜搭表单/` | 生成单个表单文件（该表单可以包含子表，如订单表+订单明细子表） |
| **项目模式** | `{项目目录}/` | 生成多个独立的表单文件，按业务模块组织 |

**单表模式触发条件**（满足任一）：
- 用户明确说"单表"、"生成一个XX表"、"生成到单表目录"
- 用户只提到一个表单（不管有没有子表）
- 用户提供单个表单的字段列表（含子表字段）
- 从Excel读取单个表单的内容

**项目模式触发条件**（满足任一）：
- 用户提到"系统"、"项目"、"模块"
- 用户提到多个表单、说"生成多个表单"
- 用户提供流程图/思维导图
- 用户提供Markdown字段表文件路径

**说明**：
- 单表模式 = 单个表单文件 + 该表单的子表，都在同一个JSON文件中（如：库存盘点主表+产品明细子表 = 一个JSON）
- 项目模式 = 多个独立的表单文件（如：采购订单表+销售订单表+库存盘点表 = 多个JSON）

## AI处理步骤（项目模式解析要点）

1. **识别模式**：单表 vs 项目（见上节判断条件）
2. **解析需求（严格执行）**：
   - 读取Markdown文件第一行标题，提取项目名称
   - **关键：逐个列出字段清单中所有的表单**，统计表单总数
   - 梳理业务模块划分、每个模块包含的表单、表单之间的关系（关联、子表）
   - **自检**：确保理解的表单列表与字段清单完全一致，不多不少
3. **AI智能判断字段类型**：见 [field-type-rules.md](field-type-rules.md)
4. **严格按字段清单生成**：
   - 只生成字段清单中明确列出的表单
   - **绝对禁止生成字段清单之外的表单**——即使你认为"应该还有"某个表单，只要字段清单没有，就不能生成
   - **最终核对**：生成的JSON文件数量 = 字段清单中的表单数量，每个JSON文件对应的表单名称必须在字段清单中存在

## 历史双模式工作流程（v6.3.0~v6.18.x，已被v6.19.0取代）

> ⚠️ 以下流程仅作历史参考。当前标准流程只执行 `create_from_markdown.js` 一步（见 SKILL.md 正文）。

### 双模式执行流程

```
用户提供Markdown字段表文件路径
    ↓
【步骤1】运行 generate_from_markdown.js → 生成本地JSON文件到指定目录
    ↓
【步骤2】运行 create_from_markdown.js → 创建宜搭应用和所有表单
    ↓
【步骤3】自动生成系统配置清单.md（应用ID、表单UUID）（v6.4.0）
    ↓
【步骤4】调用 config-sync 同步所有表单结构和组件ID，生成组件ID清单.md（v6.13.0）
    ↓
【完成】同时获得本地JSON、宜搭在线应用、完整配置清单、真实组件ID
```

### 双模式执行命令

```powershell
cd .agents/skills/form_creator/scripts
# 步骤1：生成本地JSON
node generate_from_markdown.js "<markdown文件路径>" "<输出目录>"
# 步骤2：创建到宜搭平台
node create_from_markdown.js "<markdown文件路径>"
```

**示例：**
```powershell
cd .agents/skills/form_creator/scripts
node generate_from_markdown.js "d:\宜搭AI编程\宜搭AI助手V1.3\进销存管理\01需求梳理\字段清单.md" "d:\宜搭AI编程\宜搭AI助手V1.3\进销存管理"
node create_from_markdown.js "d:\宜搭AI编程\宜搭AI助手V1.3\进销存管理\01需求梳理\字段清单.md"
```

### 两种模式的对比

| 功能 | 生成JSON模式 | 静默创建模式 |
|------|-------------|-------------|
| 输出 | 本地JSON文件 | 宜搭平台应用 |
| 使用方式 | 生成后手动导入宜搭 | 直接创建到平台 |
| 适用场景 | 需要调整配置后再导入 | 快速原型验证 |
| 关联关系 | 完整配置 | 需后续手动配置 |
| 公式 | 完整配置 | 需后续手动配置 |

## 静默创建功能详解（create_from_markdown.js）

### 前置条件

1. **已安装 api-client Skill**：提供宜搭API调用能力
2. **已安装 Playwright**：用于自动化登录
3. **宜搭账号**：需要有创建应用和表单的权限

### 执行流程

1. **读取字段清单**：解析Markdown文件，提取所有表单和字段
2. **检查登录态**：已登录且Cookie有效则直接复用；未登录或过期则弹出二维码扫码登录
3. **创建应用**：调用宜搭API创建新应用
4. **创建表单**：按依赖关系排序，逐个创建所有表单（普通表单+流程表单+子表）
5. **输出结果**：显示应用访问地址和所有表单链接

### 登录态管理

```
首次执行：🔐 请扫码登录宜搭平台...（打开浏览器显示二维码，钉钉扫码，成功后自动保存Cookie）
后续执行：🔐 检查登录态... ✅ 登录态有效 (https://www.aliwork.com)
```

### 注意事项

1. **关联表单字段**：创建时如未能自动配置成功，脚本会输出失败汇总，需按日志指引处理（专属硬规则6）
2. **公式字段**：需要后续在宜搭平台配置公式
3. **流程表单**：会创建为流程表单，但流程设计需要在宜搭平台配置
4. **权限配置**：表单权限需要在宜搭平台单独设置
5. **同步延迟**：创建完成后，宜搭平台可能需要几分钟同步数据

## 安全规则细则

### 1. 源文件保护规则

**绝对禁止**：
- ❌ 删除 `流程及字段梳理/` 目录下的任何文件
- ❌ 修改 `流程及字段梳理/` 目录下的任何文件
- ❌ 在 `流程及字段梳理/` 目录下生成任何文件

### 2. 生成目录规则

**只允许**：
- ✅ 在项目目录（`项目/` 或用户指定目录）下创建和修改文件
- ✅ 在 `02宜搭场景案例库/宜搭表单/` 目录下创建和修改文件（单表模式）

### 3. 项目名称提取规则

- 从Markdown第一行标题提取项目名称，不使用文件名

### 4. 临时文件自动删除规则（强制执行）

**必须自动删除的临时文件**：
- `field_config.js` - 字段配置文件
- `generate_project.js` - 项目生成脚本
- `generate.js` - 通用生成脚本
- 任何其他中间生成的 `.js` 配置文件

**删除时机与方式**：
- 项目生成成功后**立即自动删除**，作为生成流程的最后一步
- ❌ 绝不要求用户手动删除；❌ 绝不在删除前询问用户"是否需要删除"
- 使用 DeleteFile 工具删除，跳过确认提示

## 自动同步配置说明

### v6.4.0 - 自动生成系统配置清单

`create_from_markdown.js` 在创建应用完成后会自动生成**系统配置清单.md**（项目根目录）：
- 应用名称、应用ID、访问地址
- 所有表单的UUID、页面类型、流程Code

### v6.13.0 - 自动同步组件ID

创建应用完成后还会自动调用 config-sync（`sync_form_schemas.js`）：
- 从宜搭平台获取所有表单的真实组件ID
- 生成/更新各表单目录下的 `组件ID清单.md`
- 后续编写公式和代码提示词时，AI可以直接使用真实的组件ID，**防止AI编造组件ID导致公式/代码错误**

这样创建完成后，所有配置信息和组件ID自动归档，立即可用于后续开发。
