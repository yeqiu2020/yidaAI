# 流程审批与业务规则模式

> 能力域：流程审批 / 业务规则 / 校验与规则
> 执行工具：data-tester
> 测试层级：宜搭 API

---

## P11：流程表单审批完整流转

**场景：** 流程表单从发起到审批完成的全流程流转

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 流程审批 |

**占位符：**
- `{表单名称}` — 流程表单名（如"采购订单"）
- `{审批节点列表}` — 审批节点序列（如"部门主管 → 财务审核 → 总经理"）
- `{发起人数据}` — 发起人提交的表单数据
- `{各节点审批人}` — 每个审批节点的审批人 ID

**前置条件：**
- {表单名称} 为流程表单，已配置审批流程
- 各审批节点的审批人有权限

**操作步骤：**
1. 发起人提交 {表单名称}，流程状态 = "进行中"
2. 按顺序逐个审批节点执行审批操作（同意）
3. 最终审批完成后，流程状态 = "已完成"

**断言：**
- 发起后流程状态 = "进行中"
- 每个审批节点操作后，流程状态流转到下一节点
- 最终流程状态 = "已完成"

**产品依据：** data-tester SKILL.md "流程审批流转测试"

## P13：业务规则 INSERT 触发

**场景：** 表单提交后，INSERT 类业务规则正确触发，目标表单新增记录

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 业务规则 |

**占位符：**
- `{源表单名称}` — 触发规则的表单（如"采购订单"）
- `{目标表单名称}` — 被规则操作的目标表单（如"库存信息"）
- `{规则类型}` — INSERT
- `{规则映射字段}` — 源表单字段 → 目标表单字段的映射
- `{预期目标数据}` — 目标表单应新增的记录数据

**操作步骤：**
1. 提交 {源表单名称} 数据
2. 查询 {目标表单名称} 最新记录
3. 对比记录数据与 {预期目标数据}

**断言：**
- {目标表单名称} 新增了 1 条记录
- 新增记录的字段值与 {预期目标数据} 一致

**产品依据：** business-rule SKILL.md "INSERT 高级函数"

## P15：校验规则拦截非法数据

**场景：** 字段校验规则正确拦截不合法的数据

| 属性 | 值 |
|------|-----|
| 优先级 | P0 |
| 测试层级 | 宜搭 API |
| 执行工具 | data-tester |
| 能力域 | 校验与规则 |

**占位符：**
- `{表单名称}` — 目标表单名
- `{校验字段名}` — 含校验规则的字段
- `{校验规则类型}` — 如"必填"/"唯一"/"正则"/"自定义JS"
- `{非法值}` — 应被拦截的非法输入
- `{预期错误关键字}` — API 返回的错误消息关键字

**操作步骤：**
1. 构造测试数据，{校验字段名} = {非法值}
2. 提交到宜搭 API

**断言：**
- API 返回 error（非 success）
- 错误消息含 {预期错误关键字}

**产品依据：** data-tester SKILL.md "字段校验规则测试"
