> 版本: 1.0.0
> 创建日期: 2026/03/09
> 用途: 记录实际生成过程中的错误案例，作为反面教材避免重复犯错

---

## 案例一：表单归属模块错误

### 错误描述
**项目**: 进销存管理系统
**错误内容**: 将"供应商信息"表单放到了"基础信息"模块，但流程图中实际属于"采购管理"模块

### 流程图实际结构
```
一、基础信息
├─ 产品类别
├─ 产品信息
└─ 仓库信息

五、采购管理
├─ 供应商信息  ← 实际在这里！
├─ 预付款申请
├─ 采购订单
├─ 采购入库
├─ 采购退货
└─ 采购对账单
```

### 错误生成结果
```
一、基础信息
├─ 产品类别
├─ 产品信息
├─ 供应商信息  ← ❌ 错误！不该在这里
└─ 仓库信息
```

### 错误原因
1. **凭经验主义**: 认为"供应商信息"属于基础档案，应该和"产品信息"放在一起
2. **未严格按流程图**: 没有仔细查看流程图中"供应商信息"的实际位置
3. **主观判断**: 根据个人理解重新组织了模块结构

### 正确做法
**必须严格按照流程图的模块归属，无论个人经验如何判断**

## 案例二：擅自修改表单名称

### 错误描述
**项目**: 进销存管理系统
**错误内容**: 将流程图中的表单名称擅自修改

### 被修改的表单

| 模块 | 流程图原名 | 错误改成 | 正确做法 |
|------|-----------|---------|---------|
| 四、销售管理 | 报价单 | 销售报价 | 保持"报价单" |
| 五、采购管理 | 预付款申请 | 采购申请 | 保持"预付款申请" |

### 错误原因
1. **标准化思维**: 认为"销售报价"比"报价单"更规范
2. **经验主义**: 凭以往项目经验使用"标准命名"
3. **不尊重原始需求**: 没有意识到流程图名称就是客户需求

### 正确做法
**表单名称必须与流程图中完全一致，禁止修改、简写或增删任何字**

## 案例三：编造不存在的表单

### 错误描述
**项目**: 进销存管理系统
**错误内容**: 在采购管理模块中添加了流程图中不存在的"供应商评估"表单

### 流程图实际表单（五、采购管理）
```
五、采购管理
├─ 供应商信息
├─ 预付款申请
├─ 采购订单
├─ 采购入库
├─ 采购退货
└─ 采购对账单
```

### 错误生成结果
```
五、采购管理
├─ 供应商评估  ← ❌ 编造！流程图中根本没有
├─ 预付款申请
├─ 采购订单
├─ 采购入库
├─ 采购退货
└─ 采购对账单
```

### 错误原因
1. **过度补充**: 认为"采购管理应该有供应商评估功能"
2. **凭经验添加**: 根据以往项目经验认为这个表单"应该有"
3. **没有严格核对**: 没有逐个核对流程图中的表单节点

### 正确做法
**只生成流程图中实际存在的表单，绝对禁止添加流程图之外的表单**

## 案例四：表单识别不完整（待确认）

### 问题描述
重新仔细查看流程图后，发现销售管理和采购管理模块的表单识别可能不完整。

### 需要重新识别的模块
- 四、销售管理 - 需要逐个确认所有带图标的节点
- 五、采购管理 - 需要逐个确认所有带图标的节点

---

## 错误根源总结

### 1. 核心问题：凭经验主义
- ❌ 凭经验判断表单应该在哪里
- ❌ 凭经验修改表单名称
- ❌ 凭经验添加"应该有"的表单
- ✅ 必须严格按照流程图，不加入个人判断

### 2. 核心问题：缺乏严格核对
- ❌ 没有建立表单清单与流程图逐一核对
- ❌ 没有检查表单归属模块
- ❌ 没有核对表单名称一致性
- ✅ 必须建立检查清单，逐项核对

### 3. 核心问题：图标识别不准确
- ❌ 没有逐个确认带图标的节点
- ❌ 可能遗漏或误判表单节点
- ✅ 必须逐个扫描，建立完整清单

## 预防措施

### 生成前必须完成的检查

#### 检查1：模块归属核对
```
对于每个表单，回答：
- 这个表单在流程图的哪个模块下？____
- 我把它放到了哪个模块？____
- 两者是否一致？是/否
```

#### 检查2：表单名称核对
```
对于每个表单，回答：
- 流程图中的名称：____
- 我生成的名称：____
- 两者是否完全一致？是/否
```

#### 检查3：表单数量核对
```
- 流程图中带📄或▶️图标的表单总数：____个
- 我生成的表单总数：____个
- 两者是否一致？是/否
```

#### 检查4：禁止添加核对
```
- 我是否添加了流程图中没有的表单？是/否
- 我是否修改了任何表单名称？是/否
- 我是否调整了任何表单归属？是/否
```

## 教训

1. **流程图是唯一的真理来源**，个人经验只能作为理解辅助，不能作为修改依据
2. **严格一对一映射**，流程图有什么就生成什么，不多不少
3. **名称必须完全一致**，不允许任何形式的修改
4. **模块归属必须严格对应**，不允许重新组织
5. **建立检查清单**，逐项核对，不凭记忆
