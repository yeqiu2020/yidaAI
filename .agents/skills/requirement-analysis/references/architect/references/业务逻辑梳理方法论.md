## 📖 概述

### 什么是业务逻辑梳理？

业务逻辑梳理是将**模糊的业务需求**转化为**清晰的系统架构**的过程。它不是记录所有的业务细节，而是提取业务的核心骨架，明确：

1. **要做哪些事情**（数据表单 + 核心数据 + 执行表单）
2. **按什么顺序做**（业务执行流程）
3. **表单之间如何连接**（数据引用和更新关系）

### 为什么需要业务逻辑梳理？

在宜搭低代码开发中，业务逻辑梳理是**第一步也是最关键的一步**：

- ✅ **避免返工**：先理清业务主线，再设计表单，减少后期修改
- ✅ **统一认知**：业务逻辑图是开发人员和业务人员的共同语言
- ✅ **指导开发**：清晰的逻辑图直接指导表单设计和自动化配置
- ✅ **便于维护**：文档化的业务逻辑方便后续系统维护和升级

### 核心思想

```
业务逻辑图 ≠ 流程图
业务逻辑图 ≠ 功能清单
业务逻辑图 = 业务骨架 + 执行顺序 + 表单关系
```

**不包含**：
- ❌ 审批节点（这是表单内的流程）
- ❌ 人员信息（这是权限配置）
- ❌ 计算公式（这是字段配置）
- ❌ 自动化规则（这是技术实现）

**只包含**：
- ✅ 数据表单（存储什么数据）
- ✅ 核心数据（跟踪业务状态）
- ✅ 执行表单（执行业务操作）
- ✅ 执行顺序（业务主线流程）
- ✅ 表单连接（数据如何流转）

## 🎯 核心模型：三层表单架构

### 表单分类

我们将表单分为三类：

#### 1. 数据表单（Data Forms）🟨 黄色

**定义**：存储基础信息的表单

**特点**：
- 数据相对静态，不频繁变更
- 被其他表单引用（查）
- 作为业务操作的基础

**编号规则**：1.xxx / 2.xxx / 3.xxx / 4.xxx

**示例**：
- 1.货品类别（分类信息）
- 2.供应商库（供应商信息）
- 3.仓库信息（仓库信息）
- 4.客户信息（客户信息）

**在逻辑图中的表示**：
- 形状：圆角矩形
- 颜色：黄色 (#fff3cd)
- 边框：橙色 (#ffc107)
- 边框粗细：1px

#### 2. 核心数据（Core Data）🟪 紫色

**定义**：跟踪业务状态的核心数据

**特点**：
- 动态变化，反映业务状态
- 被多个执行表单更新（增删改）
- 作为业务进展的"仪表盘"

**编号规则**：2.xxx

**示例**：
- 2.货品信息（货品主数据）
- 2.库存信息（实时库存数量）
- 2.客户状态（客户跟进状态）

**在逻辑图中的表示**：
- 形状：圆形（aspect=fixed）
- 颜色：紫色 (#e2d4f0)
- 边框：深紫色 (#9c27b0)
- 边框粗细：1px

#### 3. 执行表单（Execute Forms）🩷 粉色

**定义**：执行业务操作的表单

**特点**：
- 记录业务操作过程
- 触发数据变化
- 有明确的执行顺序

**编号规则**：3.xxx / 4.xxx

**示例**：
- 3.采购入库（入库操作）
- 3.销售出库（出库操作）
- 4.库存盘点（盘点操作）
- 4.库存调拨（调拨操作）

**在逻辑图中的表示**：
- 形状：圆角矩形
- 颜色：粉色 (#f8d7da)
- 边框：红色 (#dc3545)
- 边框粗细：1px

## 📊 业务逻辑图三要素

### 要素一：要做哪些事情

明确系统中的所有表单，分为数据表单、核心数据和执行表单。

**梳理方法**：
1. **识别数据表单**：问"需要管理哪些基础信息？"
   - 客户、产品、员工、仓库...
   
2. **识别核心数据**：问"需要跟踪哪些业务状态？"
   - 库存信息、客户状态、账户余额...
   
3. **识别执行表单**：问"需要记录哪些业务操作？"
   - 录入、跟进、订单、入库...

**示例**（进销存系统）：
```
数据表单：
- 1.货品类别
- 2.供应商库
- 3.仓库信息
- 4.客户信息

核心数据：
- 2.货品信息
- 2.库存信息

执行表单：
- 3.采购入库
- 3.销售出库
- 4.库存盘点
- 4.库存调拨
```

### 要素二：执行顺序（业务逻辑）

明确业务操作的先后顺序，形成主线流程。

**梳理方法**：
1. **问"业务从哪开始？"** → 第一个执行表单
2. **问"接下来做什么？"** → 第二个执行表单
3. **继续追问"然后呢？"** → 直到业务结束

**示例**：
```
采购入库 → 销售出库
库存盘点（并行）
库存调拨（并行）
```

**注意事项**：
- 只记录**主线流程**，不记录分支和异常
- 可以循环（如：客户跟进可以多次）
- 可以并行（如：多个执行表单同时进行）

### 要素三：表单连接关系

明确表单之间如何连接，数据如何流转。

**两种关系**：

#### 1. 引用关系（Reference）- 实线
**定义**：执行表单引用数据表单或核心数据的信息

**方向**：数据表单/核心数据 → 执行表单

**示例**：
- 1.货品类别 → 引用 → 2.货品信息
- 2.货品信息 → 引用 → 3.采购入库
- 2.库存信息 → 引用 → 3.销售出库

**在逻辑图中的表示**：
- 线型：实线
- 颜色：深灰色 (#333333)
- 粗细：1px
- 标签："引用"

#### 2. 更新关系（Update）- 虚线
**定义**：执行表单更新核心数据的状态

**方向**：执行表单 → 核心数据

**示例**：
- 3.采购入库 → 更新 → 2.库存信息（插入/增加库存数量）
- 3.销售出库 → 更新 → 2.库存信息（扣减库存数量）
- 4.库存盘点 → 更新 → 2.库存信息（更新库存数量）

**在逻辑图中的表示**：
- 线型：虚线（dashed=1）
- 颜色：灰色 (#666666)
- 粗细：1px
- 标签：操作类型（如"插入/增加库存数量"）

## 🎨 业务逻辑图设计规范

### 颜色规范

| 类型 | 填充色 | 边框色 | 用途 |
|-----|-------|-------|------|
| 数据表单 | #fff3cd（黄色） | #ffc107（橙色） | 存储基础信息 |
| 核心数据 | #e2d4f0（紫色） | #9c27b0（深紫色） | 跟踪业务状态 |
| 执行表单 | #f8d7da（粉色） | #dc3545（红色） | 执行业务操作 |

### 形状规范

| 类型 | 形状 | 尺寸 | 特殊属性 |
|-----|------|-----|---------|
| 数据表单 | 圆角矩形 | 100×50 | rounded=1 |
| 核心数据 | 圆形 | 70×70 | ellipse, aspect=fixed |
| 执行表单 | 圆角矩形 | 100×50 | rounded=1 |

### 连线规范

| 类型 | 线型 | 颜色 | 粗细 | 标签 |
|-----|------|-----|------|-----|
| 引用关系 | 实线 | #333333 | 1px | "引用" |
| 更新关系 | 虚线 | #666666 | 1px | 操作类型 |

### 布局规范

1. **数据表单**：分布在四周（左上、右上、右中、右下）
2. **核心数据**：居中（圆形，突出显示）
3. **执行表单**：分布在核心数据周围
4. **图例**：左下角，包含三类表单的说明

## 🔄 梳理流程（四步法）

### 第一步：识别业务场景

**目标**：了解业务背景，明确梳理范围

**关键问题**：
1. 您是什么行业？
2. 主要做什么业务？
3. 目前如何管理？有什么痛点？
4. 系统给哪些人使用？

**输出**：业务场景描述

**示例**：
```
行业：进销存管理
业务：管理货品采购、销售、库存
痛点：库存不清，采购销售脱节
用户：采购员、销售员、仓管员
```

### 第二步：识别表单

**目标**：识别所有的数据表单、核心数据和执行表单

**关键问题**：
1. 需要管理哪些基础信息？（数据表单）
2. 需要跟踪哪些业务状态？（核心数据）
3. 需要记录哪些业务操作？（执行表单）

**输出**：表单清单

**示例**：
```
数据表单：
✓ 1.货品类别
✓ 2.供应商库
✓ 3.仓库信息
✓ 4.客户信息

核心数据：
✓ 2.货品信息
✓ 2.库存信息

执行表单：
✓ 3.采购入库
✓ 3.销售出库
✓ 4.库存盘点
✓ 4.库存调拨
```

### 第三步：梳理执行顺序

**目标**：明确业务操作的先后顺序

**关键问题**：
1. 业务从哪开始？
2. 接下来做什么？
3. 然后呢？
4. 业务如何结束？

**输出**：执行顺序流程

**示例**：
```
采购入库 → 销售出库
库存盘点（并行）
库存调拨（并行）
```

### 第四步：梳理表单关系

**目标**：明确表单之间的引用和更新关系

**关键问题**：
1. 执行表单需要引用哪些数据表单？
2. 执行表单需要引用哪些核心数据？
3. 执行表单需要更新哪些核心数据？
4. 数据如何流转？

**输出**：关系清单

**示例**：
```
引用关系：
- 1.货品类别 → 2.货品信息
- 2.货品信息 → 3.采购入库
- 2.库存信息 → 3.销售出库

更新关系：
- 3.采购入库 → 2.库存信息（增加库存）
- 3.销售出库 → 2.库存信息（扣减库存）
```

## 💡 最佳实践

### DO（应该做）

✅ **聚焦核心业务**：只记录主线流程，不纠结细节  
✅ **使用标准规范**：严格按照颜色、形状、连线规范  
✅ **保持简洁清晰**：一个图不要放太多表单，必要时拆分  
✅ **与用户确认**：生成后给用户看，确认业务逻辑无误  
✅ **迭代优化**：根据反馈调整，不断完善

### DON'T（不应该做）

❌ **不要记录审批流程**：这是表单内的流程，不是业务主线  
❌ **不要记录计算公式**：这是字段级别的配置  
❌ **不要记录人员信息**：这是权限配置  
❌ **不要过度设计**：不要试图记录所有可能的场景  
❌ **不要一次到位**：分阶段梳理，先框架后细节

## 🎯 示例：进销存系统

### 业务场景

管理货品的采购、销售和库存，需要跟踪库存数量，支持盘点和调拨。

### 表单清单

**数据表单**：
- 1.货品类别
- 2.供应商库
- 3.仓库信息
- 4.客户信息

**核心数据**：
- 2.货品信息
- 2.库存信息

**执行表单**：
- 3.采购入库
- 3.销售出库
- 4.库存盘点
- 4.库存调拨

### 表单关系

**引用关系**：
- 1.货品类别 → 2.货品信息
- 2.货品信息 → 2.库存信息
- 2.供应商库 → 3.采购入库
- 3.仓库信息 → 3.采购入库
- 3.仓库信息 → 2.库存信息
- 3.仓库信息 → 3.销售出库
- 4.客户信息 → 3.销售出库
- 2.库存信息 → 3.销售出库
- 2.货品信息 → 3.采购入库
- 4.库存盘点 → 2.库存信息
- 2.库存信息 → 4.库存调拨（引用 x2）

**更新关系**：
- 3.采购入库 → 2.库存信息（插入/增加库存数量）
- 3.销售出库 → 2.库存信息（扣减库存数量）
- 4.库存盘点 → 2.库存信息（更新库存数量）
- 4.库存调拨 → 2.库存信息（扣减库存数量）
- 4.库存调拨 → 2.库存信息（增加库存数量）
