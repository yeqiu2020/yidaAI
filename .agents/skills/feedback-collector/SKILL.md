## 功能说明

收集用户反馈（Bug报告、功能建议、使用问题等），并将数据发送到叶秋建议收集系统。

**支持的反馈类型：**

- 🐛 **Bug报告** - 程序错误、异常行为
- 💡 **功能建议** - 新功能需求、改进建议
- 📋 **需求提交** - 用户想要实现的功能需求
- ❓ **使用问题** - 操作疑问、使用困难
- ⭐ **使用评价** - 好评、建议

**限制说明：**

- 每日最多发送 **3** 条建议
- 需要填写发送人姓名和手机号
- 接收人和接收地址固定不可修改

***

## 触发条件（必须遵守）

**⚠️ 重要：当用户输入包含以下任一关键词时，AI必须立即调用 feedback-collector skill，而不是直接回复或执行其他操作。**

### 触发关键词列表：

| 关键词       | 示例语句          |
| --------- | ------------- |
| 给叶秋发送一条建议 | "我想给叶秋发送一条建议" |
| 给叶秋发送一个问题 | "我要给叶秋发送一个问题" |
| 给叶秋提建议    | "我想给叶秋提个建议"   |
| 给叶秋反馈问题   | "我要给叶秋反馈一个问题" |
| 给叶秋发送一个需求 | "我要给叶秋发送一个需求" |
| 给叶秋提需求    | "我想给叶秋提个需求"   |

### 如何调用此Skill：

**当检测到用户输入包含上述关键词时，AI必须：**

1. **立即调用 Skill 工具**，加载 feedback-collector skill
2. **不要直接运行脚本命令**
3. **按照本文档的"执行流程"逐步执行**

**错误示例（不要这样做）：**

```
用户：给叶秋发送一个建议
AI：直接运行 node submit-feedback.js ...  ← 错误！没有先调用skill
```

**正确示例（应该这样做）：**

```
用户：给叶秋发送一个建议
AI：调用 Skill 工具 -> feedback-collector  ← 正确！先加载skill
     然后按照skill文档执行流程操作
```

## 执行流程

```
用户使用触发语句
    ↓
询问用户手机号和姓名（用于校验和记录）
    ↓
检查今日发送次数（每日限3条）
    ↓
询问反馈类型（Bug/建议/问题/评价）
    ↓
引导用户填写详细信息
    ↓
构建完整提示词并展示给用户确认
    ↓
用户确认后调用脚本发送
    ↓
发送成功，记录到本地存储
    ↓
反馈提交成功确认
```

## 详细步骤

> 📄 第1/1.5/2/6步的完整对话话术模板均见 [references/对话话术与数据格式.md](references/对话话术与数据格式.md)，执行时按模板输出。

### 第1步：收集用户身份信息

1. **首先检查本地是否有已保存的用户信息**：读取文件 `config/current-user.json`，如已有 `sender` 和 `phone`，展示账号信息（含平台网址 <https://www.yidatrain.com/>）并询问"是否使用此账号发送建议？"（回复"是"继续 / "否"更换账号）
2. **如果用户选择更换账号**：确认变更后，让用户输入新的姓名和手机号
3. **如果没有保存的用户信息**：告知用户需先在 **叶秋--宜搭AI开发工作流** 注册账号（注册地址 <https://www.yidatrain.com/>），并询问姓名和手机号；未注册用户无法发送建议

### 第1.5步：验证用户身份信息

用户提供姓名和手机号后，**立即进行验证**（向接收端发送验证请求，可复用发送接口，只验证不保存，接口示例见 [references/对话话术与数据格式.md](references/对话话术与数据格式.md)）：

- ✅ **验证通过** → 按话术确认身份，进入第2步
- ❌ **验证失败**（账号不存在 / 手机号不匹配 / 其他错误）→ 按对应话术提示"账号校验不通过，无法发送"，引导注册或重新提供信息

**保存用户信息**（仅验证通过后）：将姓名和手机号保存到 `config/current-user.json`（含 version / lastUpdated / sender / phone 字段）。

**如果用户今日已发送满3条**：提示"您今日已发送3条建议，达到每日上限，请明天再试"。

### 第2步：确认反馈类型

验证通过后，询问反馈类型（按话术模板列出 5 个选项）：1.🐛 Bug报告　2.💡 功能建议　3.📋 需求提交　4.❓ 使用问题　5.⭐ 使用评价

### 第3步：收集详细信息

根据反馈类型，询问对应的信息：

**通用信息（所有类型都需要）：**

- 反馈标题（一句话概括）
- 详细描述

**Bug报告额外信息：**

- 复现步骤（如何触发这个Bug）
- 期望结果（正常应该是什么）
- 实际结果（现在出现什么）

**功能建议额外信息：**

- 使用场景（在什么情况下需要）
- 期望功能（具体想要什么）
- 操作步骤（如果有具体流程）

**需求提交额外信息：**

- 需求背景（为什么需要这个功能）
- 需求描述（具体要实现什么）
- 期望效果（达到什么目标）
- 优先级（高/中/低）

**使用问题额外信息：**

- 操作步骤（你做了什么）
- 问题现象（出现了什么）
- 期望结果（希望达到什么效果）

***

【接收人】叶秋
【接收地址】https://www.yidatrain.com/
【发送人】[用户填写的姓名]
【发送人电话】[用户填写的手机号]
【发送时间】[当前时间]

【反馈类型】[Bug报告/功能建议/使用问题/使用评价]

***

### 第5步：调用脚本发送

用户确认后，调用脚本发送数据：

**注意：请根据实际项目路径调整命令**

```bash
yida-helper run feedback-collector/scripts/submit-feedback.js \
  --sender "[用户姓名]" \
  --phone "[用户手机号]" \
  --type "[bug/feature/requirement/question/review]" \
  --title "[标题]" \
  --description "[描述]" \
  --steps "[步骤]" \
  --expected "[期望结果]" \
  --actual "[实际结果]" \
  --context "[使用场景]"
```

***

### 第6步：反馈结果

- **发送成功** → 按话术告知"建议发送成功"，并展示今日发送进度 \[已发送条数]/3 条
- **发送失败** → 按话术告知"发送失败，请稍后重试"，建议已自动保存到本地，可稍后重新发送

## 数据格式

发送到服务器的数据包含：recipient / address / sender / phone / sendTime / feedbackType / title / description / reproduceSteps / expectedResult / actualResult / context / submittedAt / source / status 等字段。完整 JSON 格式见 [references/对话话术与数据格式.md](references/对话话术与数据格式.md)。

### 必填字段校验

| 字段        | 说明    | 校验规则                                   |
| --------- | ----- | -------------------------------------- |
| recipient | 接收人   | 必须为"叶秋"，不可修改                           |
| address   | 接收地址  | 必须为"<https://www.yidatrain.com/"，不可修改> |
| sender    | 发送人   | 必填，用户填写的姓名                             |
| phone     | 发送人电话 | 必填，11位手机号格式                            |
| sendTime  | 发送时间  | 自动生成，用于每日限制校验                          |

## 用户查询功能

当用户说"查看我的建议"、"我发送了什么建议"时：

1. 读取本地存储文件 `config/user-feedback-storage.json`
2. 根据用户手机号查询历史记录
3. 按展示模板输出（模板见 [references/对话话术与数据格式.md](references/对话话术与数据格式.md)）：今日已发送 \[X]/3 条 + 历史记录列表（时间/类型/标题/状态）

***

## 禁止事项

- ❌ **禁止自动提交** - 必须先让用户确认完整提示词
- ❌ **禁止修改接收人** - 接收人必须为"叶秋"
- ❌ **禁止修改接收地址** - 地址必须为"<https://www.yidatrain.com/>"
- ❌ **禁止超过每日限制** - 严格限制每日3条
- ❌ **禁止未注册用户发送** - 必须先注册验证
- ❌ **禁止收集敏感信息** - 不要收集密码、密钥等
- ❌ **禁止暴露配置** - Webhook URL等配置不显示给用户

## 脚本使用说明

### submit-feedback.js (v1.2.0)

**功能**：将反馈数据发送到叶秋建议收集系统

**参数表**：

| 参数 | 必填 | 说明 |
|------|:---:|------|
| `--sender` | 是 | 发送人姓名 |
| `--phone` | 是 | 发送人电话 |
| `--type` | 是 | 反馈类型（bug/feature/requirement/question/review） |
| `--title` | 是 | 标题 |
| `--description` | 是 | 详细描述 |
| `--steps` | 否 | 复现/操作步骤 |
| `--expected` | 否 | 期望结果 |
| `--actual` | 否 | 实际结果 |
| `--context` | 否 | 使用场景 |
| `--recipient` | 否 | 接收人（默认：叶秋） |
| `--address` | 否 | 接收地址（默认：<https://www.yidatrain.com/）> |

**使用示例**：

```bash
yida-helper run feedback-collector/scripts/submit-feedback.js \
  --sender "张三" \
  --phone "13800138000" \
  --type "feature" \
  --title "增加批量导入功能" \
  --description "希望能支持Excel批量导入数据"
```
