## 一、目录结构正误完整示例

**正确目录结构示例**（以进销存管理为例）：

```
进销存管理/                                   ← 项目根目录
├── 系统配置清单.md
├── 采购管理「分组」/                          ← 分组目录
│   └── 采购入库「流程表单」/                  ← 表单本身所在目录（业务规则放这里！）
│       ├── 采购入库「流程表单」.json           ← 表单 Schema
│       ├── 组件ID清单.md
│       └── 业务规则/                          ← ✅ 本技能生成，放在表单目录下
│           ├── 采购入库-增加库存.json
│           └── 采购入库-增加库存.md
└── 库存管理「分组」/
    └── 库存信息「普通表单」/
        ├── 库存信息「普通表单」.json
        └── ...
```

🔴 **错误示例**（严禁这样做）：

```
进销存管理/                                   ← 项目根目录
├── 采购入库/                                  ← ❌ 在根目录下新建以表单名命名的文件夹
│   └── 业务规则/                              ← ❌ 错误位置
│       └── 采购入库-增加库存.json
└── 采购管理「分组」/
    └── 采购入库「流程表单」/                  ← 表单实际所在目录被忽略
```

> ⚠️ **常见错误**：AI 生成业务规则时，直接在项目根目录下创建 `{表单名}/业务规则/`，而不是放在表单本身已存在的目录下。这会导致文件结构与项目其他资源（Schema、组件ID清单）分离，难以管理。务必先用 `Glob` 定位表单实际所在目录，再在其下创建 `业务规则/` 子文件夹。

## 二、禁止的 JSON 嵌套格式（历史错误做法）

```json
// ❌ 错误：包装了额外字段的嵌套格式，用户无法直接复制粘贴
{
  "ruleName": "采购入库-增加库存",
  "formula": {
    "text": "...",
    "marks": [...],
    "isCmData": true
  },
  "fieldMapping": [...]
}
```

JSON 文件必须是扁平的 `{text, marks, isCmData}` 三字段格式（见 SKILL.md 硬规则9与第四节）。
