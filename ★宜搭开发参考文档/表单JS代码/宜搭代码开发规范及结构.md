# 宜搭代码开发规范及结构

## 一、开发环境要求

### 1.1 JavaScript 语法规范
宜搭平台对 JavaScript 语法有严格要求，为确保代码兼容性，请遵循以下规范：

#### ⚠️ 禁止使用 ES6+ 语法（致命问题）
- **可选链操作符（?.）**：编译错误根源
- **模板字符串（反引号）**：使用传统字符串拼接
- **对象解构赋值**：使用传统属性访问方式
- **箭头函数**：使用传统 function 语法
- **const/let 声明**：统一使用 var 声明变量
- **Map 对象和 Array.from**：使用普通对象和 for...in 循环

#### ✅ 安全语法示例
```javascript
// ❌ 错误示例（ES6+ 语法）
const errorMsg = detailResult?.message || '获取失败';
console.log(`订单号: ${orderNo}`);
const { orderNo, detailList } = result;
selectedOrders.forEach(order => { ... });
const selectedOrders = this.$(fieldId).getValue();
const productMap = new Map();

// ✅ 正确示例（ES5 语法）
var errorMsg = (detailResult && detailResult.message) ? detailResult.message : '获取失败';
console.log('订单号: ' + orderNo);
var orderNo = result.orderNo;
var detailList = result.detailList;
for (var i = 0; i < selectedOrders.length; i++) {
  var order = selectedOrders[i];
  // ...
}
var selectedOrders = this.$(fieldId).getValue();
var productMap = {};
```

### 1.2 代码结构要求

#### 必须包含 didMount 函数
无论是否有初始化需求，都必须书写 `didMount()` 方法，并放在代码最前面：

```javascript
export function didMount() {
  // 初始化代码，即使为空也必须存在
  console.log('页面组件已挂载');
}
```

#### 配置参数管理
将代码中涉及的所有入参、ID 等值定义为变量，写在代码最前面，便于后期维护：

```javascript
// 配置参数区域（必须放在代码最前面）nvar FIELD_IDS = {
  ORDER_TABLE: 'orderTableField_xxx',
  PRODUCT_SELECT: 'productSelectField_xxx',
  SUBMIT_BUTTON: 'submitButton_xxx'
};

var API_CONFIG = {
  GET_ORDER_DETAIL: 'getOrderDetail',
  UPDATE_INVENTORY: 'updateInventory'
};

var CONSTANTS = {
  MAX_RETRY_TIMES: 3,
  PAGE_SIZE: 20,
  TIMEOUT: 30000
};
```

#### 函数导出规范
使用标准的 `export function` 语法，避免使用匿名函数：

```javascript
// ✅ 正确写法
export function handleSubmit() {
  // 函数体
}

export function validateForm() {
  // 函数体
}

// ❌ 错误写法
const handleSubmit = function() { ... };
var validateForm = function() { ... };
```

## 二、代码开发流程

### 2.1 开发前准备
1. **确认宜搭平台版本**：了解当前宜搭环境支持的 JavaScript 语法版本
2. **检查数据源配置**：确认远程数据源 API 配置正确，API 名称匹配
3. **组件 ID 验证**：确保所有引用的组件 ID 存在且正确

### 2.2 开发步骤

#### 第一步：基础框架搭建
```javascript
// 1. 配置参数定义
var CONFIG = {
  // 所有配置项
};

// 2. didMount 函数（必须）
export function didMount() {
  console.log('组件初始化完成');
}

// 3. 基础工具函数
export function showMessage(type, title, content) {
  this.utils.toast({
    type: type,
    title: title,
    content: content
  });
}
```

#### 第二步：功能函数开发
```javascript
// 业务功能函数
export function processBusinessLogic() {
  try {
    // 业务逻辑代码
  } catch (error) {
    console.error('业务处理错误:', error);
    showMessage.call(this, 'error', '处理失败', error.message);
  }
}
```

#### 第三步：事件绑定和联动
```javascript
// 组件事件处理
export function onFieldChange(fieldId, value) {
  console.log('字段值变更:', fieldId, value);
  // 联动逻辑处理
}
```

#### ⚠️ 重要：事件绑定方式
**宜搭中的事件绑定必须通过配置面板手动设置，不允许在代码中使用 `.on()` 绑定**

**错误做法（❌ 禁止）：**
```javascript
export function didMount() {
  // ❌ 错误：宜搭不支持这种绑定方式
  this.$('componentId').on('change', this.handleChange);
  this.$('componentId').on('click', this.handleClick);
}
```

**正确做法（✅ 推荐）：**
1. 在组件属性面板中配置事件
2. 在动作面板中创建对应的函数
3. 在组件属性中选择对应的函数

**配置步骤：**
1. 选中目标组件 → 打开属性面板
2. 找到事件配置（如 change、click 等）
3. 选择或创建对应的处理函数
4. 保存配置

**didMount 函数中不允许进行事件绑定，仅用于初始化操作：**
```javascript
export function didMount() {
  console.log('组件初始化完成');
  // ✅ 可以进行数据初始化、状态设置等
  // ❌ 不允许进行事件绑定
}
```

### 2.3 调试和测试

## 三、常见错误处理

### 3.1 编译错误排查
1. **检查浏览器控制台**：查看详细错误信息
2. **验证组件配置**：确认所有组件 ID 正确
3. **语法兼容性**：确保使用 ES5 语法
4. **数据源验证**：检查 API 配置和数据格式

### 3.2 运行时错误处理
```javascript
export function safeExecuteFunction() {
  try {
    // 可能出错的代码
    var result = this.$(FIELD_IDS.ORDER_TABLE).getValue();
    
    if (!result || result.length === 0) {
      console.warn('数据为空');
      return;
    }
    
    // 处理逻辑
    processData(result);
    
  } catch (error) {
    console.error('函数执行错误:', error);
    this.utils.toast({
      type: 'error',
      title: '执行失败',
      content: '请检查数据格式或联系管理员'
    });
  }
}
```

## 四、最佳实践

### 4.1 代码组织原则
1. **单一职责**：每个函数只负责一个具体功能
2. **错误处理**：所有异步操作都要有错误处理
3. **日志记录**：关键操作要有控制台日志
4. **用户反馈**：重要操作要有用户提示

### 4.2 性能优化
1. **避免重复查询**：缓存常用的查询结果
2. **批量处理**：尽量批量处理数据，减少循环次数
3. **异步处理**：耗时操作使用异步方式

### 4.3 维护性建议
1. **注释说明**：复杂逻辑要有详细注释
2. **版本管理**：重要修改要记录版本历史
3. **备份机制**：定期备份代码文件

## 六、跨表单数据查询专项规范

### 6.1 部门选择器值处理（强制）
**问题**：部门选择器 `getValue()` 返回数组对象，查询条件需要字符串值
**必须处理**：
```javascript
// ✅ 强制：提取部门value值
var department = this.$('departmentSelectField_xxx').getValue();
var departmentValue = '';
if (Array.isArray(department) && department.length > 0) {
  departmentValue = department[0].value || department[0];
}
searchConditions['department'] = departmentValue;  // 传入 "-1"
```

### 6.2 API返回数据结构（强制）
**问题**：跨表查询返回 `{formData: {字段ID: 值}}` 层级结构
**必须处理**：
```javascript
// ✅ 强制：从formData中提取字段
var formData = sourceData.formData || sourceData;
var employee = formData['employeeField_xxx'];
```

### 6.3 成员字段格式（强制）
**问题**：成员字段需要 `{emplId: "工号", name: "姓名"}` 格式才能显示
**必须处理**：
```javascript
// ✅ 强制：格式化成员字段
function formatEmployeeField(employee) {
  if (employee && typeof employee === 'object' && employee.emplId) {
    return employee;
  }
  if (Array.isArray(employee) && employee.length > 0) {
    return employee[0];
  }
  return employee;
}
rowData['employeeField_xxx'] = formatEmployeeField(employee);
```

### 6.4 跨表单查询代码生成检查清单
生成跨表单数据查询代码时，必须确认：
- [ ] 部门选择器是否提取了 `value` 属性？
- [ ] 是否从 `formData` 属性中提取字段值？
- [ ] 成员字段是否格式化为 `{emplId, name}` 对象？
- [ ] 是否添加了足够的调试日志？
- [ ] 是否处理了分页查询逻辑？

## 七、开发注意事项

### 7.1 环境依赖
- 确认宜搭平台支持的 JavaScript 语法版本
- 避免使用任何现代 JavaScript 特性
- 测试不同浏览器的兼容性

### 7.2 数据源配置
- 远程数据源 API 配置必须正确
- API 名称要与配置完全匹配

### 7.3 组件联动
- 组件 ID 必须准确无误
- 事件绑定要生效
- 联动逻辑要经过充分测试

### 7.4 代码生成自检
**每次生成代码后，必须对照检查清单确认：**
1. 是否使用了 ES5 语法？
2. 是否包含 didMount 函数？
3. 配置参数是否前置？
4. 错误处理是否完善？
5. 调试日志是否充足？
6. 如果是跨表单查询，是否处理了部门/成员字段格式？
