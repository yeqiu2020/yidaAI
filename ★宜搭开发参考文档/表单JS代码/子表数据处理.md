# 子表数据处理规范

## 一、基础限制

### (一) 被填充到子表
1. 子表数据最多 500 行，所以查询数据超过 500 行的也不需要再继续查询了。

### (二) 如果是从目标数据表获取多条数据填充到当前子表，需注意以下事项
1. currentPage 代表当前页，必须大于 0 默认 1
2. pageSize    每页记录数，必须大于 0 ，默认 10 ，最大值：100
3. 由于每次查询数据量的限制，需要进行分页查询，仔细研读文件【★宜搭开发参考文档\分页查询数据.md】

## 二、⚠️ 重要警告：子表死循环问题

### 问题描述
**在子表的 onChange 事件中调用 `setValue()` 方法会导致死循环，造成页面卡死、浏览器崩溃！**

### 死循环产生的原因
```
子表数据变化
    ↓
触发 onChange 事件
    ↓
执行校验/处理函数
    ↓
调用 subTable.setValue() 更新数据
    ↓
再次触发子表的 onChange 事件
    ↓
无限循环...
```

### 真实案例
```javascript
// ❌ 错误示例 - 会导致死循环
export function onSubTableChange(event) {
  var subTable = this.$('tableField_xxx');
  var data = subTable.getValue();
  
  // 处理数据...
  for (var i = 0; i < data.length; i++) {
    data[i].field_xxx = '新值';
  }
  
  // 这行代码会再次触发 onChange，导致死循环！
  subTable.setValue(data);
}
```

### 正确的解决方案

#### 方案一：使用全局锁（推荐）
```javascript
// 全局锁变量，防止循环触发
var isProcessing = false;

export function onSubTableChange(event) {
  // 如果正在处理中，直接返回
  if (isProcessing) {
    console.log('正在处理中，跳过本次调用');
    return;
  }
  
  try {
    isProcessing = true;  // 加锁
    
    var subTable = this.$('tableField_xxx');
    var data = subTable.getValue();
    
    // 处理数据...
    var hasChanges = false;
    for (var i = 0; i < data.length; i++) {
      if (data[i].field_xxx !== '新值') {
        data[i].field_xxx = '新值';
        hasChanges = true;
      }
    }
    
    // 只有数据有变化时才更新
    if (hasChanges) {
      subTable.setValue(data, { triggerChange: false });  // 不触发 onChange
    }
    
  } catch (error) {
    console.error('处理错误:', error);
  } finally {
    isProcessing = false;  // 释放锁（必须在 finally 中）
  }
}
```

#### 方案二：使用 triggerChange: false
```javascript
export function updateSubTable(event) {
  var subTable = this.$('tableField_xxx');
  var data = subTable.getValue();
  
  // 修改数据...
  
  // 使用 triggerChange: false 防止触发 onChange 事件
  subTable.setValue(data, { triggerChange: false });
}
```

### 代码检查清单
在编写子表相关代码时，必须确认以下事项：

- [ ] **全局锁**：是否添加了 `isProcessing` 等全局变量防止循环？
- [ ] **triggerChange**：`setValue()` 是否使用了 `{ triggerChange: false }` 选项？
- [ ] **释放锁**：是否在 `finally` 代码块中释放了锁？
- [ ] **变化判断**：是否有判断数据真正变化后才更新的逻辑？
- [ ] **异常处理**：是否有 try-catch 包裹业务逻辑？

### 常见触发死循环的场景

| 场景 | 风险等级 | 说明 |
|-----|---------|------|
| 子表 onChange 中调用 setValue | 🔴 高 | 最常见原因 |
| 子表字段 onChange 中修改子表数据 | 🔴 高 | 同样会触发循环 |
| didMount 中调用 setValue 且子表有默认值 | 🟡 中 | 可能触发循环 |
| 联动更新多个子表字段 | 🟡 中 | 多个 setValue 可能相互触发 |

### 调试技巧

如果怀疑出现死循环，可以添加以下调试代码：

```javascript
var callCount = 0;
var isProcessing = false;

export function onSubTableChange(event) {
  callCount++;
  console.log('onSubTableChange 被调用次数:', callCount);
  
  if (callCount > 100) {
    console.error('检测到可能的死循环，强制停止');
    return;
  }
  
  if (isProcessing) {
    console.log('正在处理中，跳过');
    return;
  }
  
  // ... 业务逻辑
}
```

## 三、子表数据操作最佳实践

### 1. 获取子表数据
```javascript
var subTable = this.$('tableField_xxx');
var data = subTable.getValue();  // 返回数组
```

### 2. 更新子表数据（安全方式）
```javascript
var isUpdating = false;

export function safeUpdateSubTable(event) {
  if (isUpdating) return;
  
  isUpdating = true;
  try {
    var subTable = this.$('tableField_xxx');
    var data = subTable.getValue();
    
    // 修改数据...
    
    // 安全更新：不触发 onChange
    subTable.setValue(data, { triggerChange: false });
  } finally {
    isUpdating = false;
  }
}
```

### 3. 清空子表
```javascript
var subTable = this.$('tableField_xxx');
subTable.setValue([]);  // 传入空数组
```
