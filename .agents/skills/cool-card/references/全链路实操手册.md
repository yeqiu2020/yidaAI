# 酷卡片全链路实操手册（2026-10-05 全链路实战验证版）

> 两次场景（交互卡片+置顶卡片）从零建到群内收到卡片，全程踩坑记录。
> **按本手册顺序操作，从零到卡片送达约 15 分钟。**

---

## 一、前置条件（缺一不可）

### 1.1 酷应用发布
在应用后台 `admin/appPublish` 页面：
- 找到「发布到自建酷应用中心」→ 点「上架」
- 弹窗确认 → 点「继续发布」
- 填写：酷应用名称（≤6字符）+ 简介 + 入口名称 + 机器人名称（可默认）
- 点「发 布」→ 成功后显示「发布成功，请到群内启用后才可正常使用」

### 1.2 群内启用酷应用（⚠️ 用户手动操作，API 无法替代）
钉钉客户端 → 进内部群 → 群设置 → 酷应用中心 → 找到应用 → 启用。
- **启用前**：卡片节点配置面板的群搜索框搜不到任何群（显示"无选项"）
- **启用后**：群搜索可搜到群名

### 1.3 会话要求
- API 提交的表单数据**没有群上下文**，置顶卡片实际发不到群
- 要让置顶卡片到群，需在**群快捷栏内发起表单提交**（非 API 造数）

## 二、两种卡片类型对比

| | 交互卡片 | 置顶卡片 |
|---|---|---|
| 官方模板 | 工单待处理/工单已完结/订餐列表/抽签列表 | 工单看板/订餐看板/抽签看板 |
| 发送范围 | 发送到人 + 发送到群 | **仅发送到群** |
| 必填项 | 收件人 userId（发送到人时） | 群可见范围* + 群置顶卡片有效期* |
| 送达位置 | 发到人→机器人私聊；发到群→群会话 | 群吊顶 |
| 卡片变量 | submitter/type/from/content/createDate | 提交人/产品名称/工单类型 |
| 卡片动作 | 立即处理/关闭工单 → 绑定手动触发流程 | 跳转链接 → 打开应用内页面 |

## 三、标准操作流程（API 路线）

### 步骤1：创建流程
用 `integration-create.js` 或 UI 创建。触发事件用 `create`（流程表单提交即触发）。

### 步骤2：放置卡片节点（浏览器）
1. 打开流程编辑器（用 §1 window.open 捕获拿 URL）
2. `selectNode(触发节点)` → 面板勾选触发事件 → 面板保存
3. `selectNode(触发节点)` → `onVisibleChange(true)` → 弹层 → React onClick 点「发送卡片」

### 步骤3：配置卡片节点（浏览器，面板内一气呵成）
**必须在面板关闭前完成全部配置，面板关闭=未保存配置丢失。**

1. 官方模板 tab → React onClick 点模板项的「使用」按钮（按钮隐藏，直接 React 调 onClick）
2. 映射：configRow 序列（见片段库 §5），叶子项正则匹配
3. 提交人变量：类型切「字段」→ 映射「创建人」字段（**不要用 literal 填人名**）
4. 发送范围：
   - 发送到群 checkbox → React onChange(true)
   - 群搜索框 → CDP click → CDP type 输入群名关键词 → CDP click 选中下拉中的群
   - 群可见范围 → 全员可见（默认）
   - 有效期 → CDP click 第一个输入框 → CDP type "24"
5. 提示语：找 `input[value="工单看板"]` → native setter 改文案
6. 面板底部「保存」

### 步骤4：保存/发布/启用
- 顶部「保存」→ 确认画布显示 `发送卡片: 工单看板`（非"请完善"）
- 顶部「发布」→ 确认 toast「发布成功」
- 回列表行开**第二个开关**（启用）

### 步骤5：造数触发
- data-tester 标准函数提交触发表单测试数据
- 流程表单走 startInstance，普通表单走 saveFormData

### 步骤6：验证
- 执行计数应 +N（列表页 alert「本月累计执行次数」）
- 运行日志：状态=执行成功
- **用户在钉钉群/私聊里确认卡片实际到达**
- ⚠️ "执行成功"≠卡片送达——酷应用未启用时也会"执行成功"但卡片不发

## 四、全 API 路线（card-flow-cli.js v2）

```bash
node .agents/skills/cool-card/scripts/card-flow-cli.js \
  --app APP_XXX --form FORM-XXX \
  --name "流程名" --events create \
  --map "type=订单状态,from=客户名称,content=备注,createDate=创建时间" \
  --send-to userId1,userId2 \
  --last-message "提示语" \
  --action-flow LPROC-按钮流程 \
  --publish
```

克隆源流程（默认 LPROC-T7966J91E1N9F0J0GQVVWABXTX142KLJ7DPUMQQ）的存储态。
v1 仅支持与源同表单（销售订单）。跨表单克隆需 v2。

### API 端点合约
| 端点 | 方法 | 用途 |
|------|------|------|
| getProcess.json?processCode&isLogic=true | GET | 拉设计态 {schema, globalSetting} |
| createLogicflow.json | POST | 建流程（name/type/formUuid）|
| saveProcess.json | POST | 保存（json+viewJson 双参数）|
| publishProcessById.json | POST | 发布（processId+processVersion）|
| pageProcessVersion.json | GET | 查 processId/version |
| getProcessById.json | GET | 按 ID 拉指定版本 |

## 六、常见翻车点速查

| 症状 | 根因 | 修复 |
|------|------|------|
| 面板保存后画布仍"请完善" | 配置不完整（必填项缺）或保存静默失败 | 回读画布确认；重开面板逐项检查 |
| 群搜索无选项 | 酷应用未在群内启用 | 用户在钉钉客户端群设置→酷应用中心→启用 |
| 卡片发到了机器人私聊而非群 | 发送范围勾的是"发送到人" | 改勾"发送到群"并选群 |
| "执行成功"但没收到卡片 | 酷应用未启用时卡片静默不发 | 启用酷应用后重新提交测试数据 |
| 置顶卡片内容区"系统异常" | 置顶看板渲染需要数据上下文（群内提交才有） | 群快捷栏提交可正常渲染 |
| 面板关闭后配置全丢 | 会话过期/页面刷新导致未保存配置丢失 | 配置完立即保存；会话过期后重建 |
| 页面内 POST 静默拒绝（空200）| baxia 反爬签名 | POST 走 node 侧 api-client |
| 卡片设计器整页空白 | 视口 ≥1400px | 降到 818x710 重新 goto |
