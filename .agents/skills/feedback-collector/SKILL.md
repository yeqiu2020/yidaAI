# 用户反馈收集器（叶秋建议系统）

版本：v1.2.3

***

## 功能说明

收集用户反馈（Bug报告、功能建议、使用问题等），并将数据发送到叶秋建议收集系统。

**支持的反馈类型：**

- 🐛 **Bug报告** - 程序错误、异常行为
- 💡 **功能建议** - 新功能需求、改进建议
- 📋 **需求提交** - 用户想要实现的功能需求
- ❓ **使用问题** - 操作疑问、使用困难
- ⭐ **使用评价** - 好评、建议

**限制说明：**

- 每日最多发送 **3** 条建议
- 需要填写发送人姓名和手机号
- 接收人和接收地址固定不可修改

***

## 触发条件（必须遵守）

**⚠️ 重要：当用户输入包含以下任一关键词时，AI必须立即调用 feedback-collector skill，而不是直接回复或执行其他操作。**

### 触发关键词列表：

| 关键词       | 示例语句          |
| --------- | ------------- |
| 给叶秋发送一条建议 | "我想给叶秋发送一条建议" |
| 给叶秋发送一个问题 | "我要给叶秋发送一个问题" |
| 给叶秋提建议    | "我想给叶秋提个建议"   |
| 给叶秋反馈问题   | "我要给叶秋反馈一个问题" |
| 给叶秋发送一个需求 | "我要给叶秋发送一个需求" |
| 给叶秋提需求    | "我想给叶秋提个需求"   |

### 如何调用此Skill：

**当检测到用户输入包含上述关键词时，AI必须：**

1. **立即调用 Skill 工具**，加载 feedback-collector skill
2. **不要直接运行脚本命令**
3. **按照本文档的"执行流程"逐步执行**

**错误示例（不要这样做）：**

```
用户：给叶秋发送一个建议
AI：直接运行 node submit-feedback.js ...  ← 错误！没有先调用skill
```

**正确示例（应该这样做）：**

```
用户：给叶秋发送一个建议
AI：调用 Skill 工具 -> feedback-collector  ← 正确！先加载skill
     然后按照skill文档执行流程操作
```

## 执行流程

```
用户使用触发语句
    ↓
询问用户手机号和姓名（用于校验和记录）
    ↓
检查今日发送次数（每日限3条）
    ↓
询问反馈类型（Bug/建议/问题/评价）
    ↓
引导用户填写详细信息
    ↓
构建完整提示词并展示给用户确认
    ↓
用户确认后调用脚本发送
    ↓
发送成功，记录到本地存储
    ↓
反馈提交成功确认
```

### 第3步：收集详细信息

根据反馈类型，询问对应的信息：

**通用信息（所有类型都需要）：**

- 反馈标题（一句话概括）
- 详细描述

**Bug报告额外信息：**

- 复现步骤（如何触发这个Bug）
- 期望结果（正常应该是什么）
- 实际结果（现在出现什么）

**功能建议额外信息：**

- 使用场景（在什么情况下需要）
- 期望功能（具体想要什么）
- 操作步骤（如果有具体流程）

**需求提交额外信息：**

- 需求背景（为什么需要这个功能）
- 需求描述（具体要实现什么）
- 期望效果（达到什么目标）
- 优先级（高/中/低）

**使用问题额外信息：**

- 操作步骤（你做了什么）
- 问题现象（出现了什么）
- 期望结果（希望达到什么效果）

## 禁止事项

- ❌ **禁止自动提交** - 必须先让用户确认完整提示词
- ❌ **禁止修改接收人** - 接收人必须为"叶秋"
- ❌ **禁止修改接收地址** - 地址必须为"<https://www.yidatrain.com/>"
- ❌ **禁止超过每日限制** - 严格限制每日3条
- ❌ **禁止未注册用户发送** - 必须先注册验证
- ❌ **禁止收集敏感信息** - 不要收集密码、密钥等
- ❌ **禁止暴露配置** - Webhook URL等配置不显示给用户
