# Skill 定义与内容规范

> 版本：1.0.0  
> 创建日期：2026-02-13  
> 本文档说明：定义 Skill 的本质、职责边界和内容规范

---

## 一、Skill 的本质定义

### 1.1 什么是 Skill

**Skill = 可复用的执行能力包**

根据 AI Agent 领域的标准定义：
- Skill 是把"知道怎么干活"从临时 Prompt 变成**永久保存、随时调用的知识资产**
- Skill 是**执行层面的标准化流程**，不是知识库
- Skill 包含**角色定义、行为准则、输出格式**

### 1.2 Skill 的核心特征

| 特征 | 说明 |
|------|------|
| **执行导向** | 告诉 AI "怎么做"，不是"是什么" |
| **标准化** | 每次执行都遵循相同流程 |
| **可触发** | 通过关键词或条件自动调用 |
| **稳定** | 内容相对稳定，不频繁变动 |

### 1.3 Skill vs 文档的区别

| 维度 | Skill | 文档 |
|------|-------|------|
| **目的** | 告诉 AI **怎么执行** | 告诉用户 **知识细节** |
| **内容** | 流程、规范、检查清单 | 原理、案例、最佳实践 |
| **使用时机** | 每次触发 Skill 时自动加载 | 需要查阅时主动阅读 |
| **更新频率** | 稳定，少变动 | 持续迭代，丰富案例 |
| **详细程度** | 精简，只保留核心 | 详细，包含完整信息 |

## 二、Skill 内容规范

### 2.1 Skill 应该包含的内容

#### 1. 元信息（YAML Front Matter）

**标准格式：**
```yaml
---
name: "skill-name"
description: "简短描述 Skill 的功能和使用场景"
---
```

**规范要求：**

| 字段 | 类型 | 必需 | 规范说明 |
|------|------|------|----------|
| `name` | string | ✅ | Skill 的唯一标识，使用小写字母和连字符，如 `formula-generator` |
| `description` | string | ✅ | 单行描述，说明 Skill 的功能和触发条件 |

**description 编写规范：**
- **单行格式**：必须使用单行，不换行
- **触发关键词**：必须包含触发此 Skill 的关键词列表
- **功能说明**：简要说明 Skill 的核心功能
- **示例**：
  ```yaml
  description: 当用户说"测试表单"、"宜搭测试"、"数据提交测试"时触发此skill。宜搭数据测试专家 - 用于自动化测试宜搭表单的数据提交、公式计算、校验规则、业务规则自动化和流程审批功能。支持API和浏览器两种提交模式，可生成测试数据并输出详细测试报告。关键词：宜搭测试、表单测试、公式验证、流程测试、模拟数据、生成数据
  ```

**常见错误：**
- ❌ `description:` 后面缺少空格
- ❌ 使用 YAML 多行标记（如 `|` 或 `>`）
- ❌ 内容换行书写
- ❌ description 内容过短，缺少触发关键词

#### 2. 角色定义
- 定义 AI 的角色身份
- 明确专业领域和职责范围

#### 3. 执行流程
- **必须展示**的标准化流程
- 步骤清晰，可检查

#### 4. 输出规范
- 必须生成什么内容
- 格式要求
- 文件保存规范

#### 5. 禁止事项
- 绝对不能做的事情
- 红线清单

#### 6. 检查清单
- 执行前确认项
- 执行后确认项

#### 7. 快速参考（极简版）
- 最常用的公式模板
- 简化的速查表
- 详细的案例引用外部文档

### 2.2 Skill 不应该包含的内容

❌ **详细的知识讲解**
- 不应该解释"为什么"
- 不应该包含详细的原理说明
- 应该引用外部文档

❌ **完整的案例分析**
- 不应该包含详细的案例步骤
- 不应该包含大量的代码示例
- 应该引用【案例库.md】

❌ **最佳实践原则**
- 不应该包含设计原则
- 不应该包含优化建议
- 应该引用【最佳实践.md】

❌ **错误案例的详细分析**
- 不应该解释错误原因
- 不应该提供调试方法
- 应该引用【错误预防与调试.md】

## 三、Skill 与文档的协作关系

### 3.1 引用规范

Skill 中引用文档使用以下格式：
```markdown
详细内容请参考【文档名.md】
```

### 3.2 职责边界图

```
用户提需求
    ↓
触发 Skill
    ↓
Skill 加载（执行规范）
    ├── 角色定义
    ├── 执行流程（四步强制流程）
    ├── 输出规范
    ├── 禁止事项
    └── 快速参考（极简）
    ↓
执行过程中需要详细知识
    ↓
查阅对应文档
    ├── 【格式规范.md】→ JSON格式、marks计算
    ├── 【位置计算指南.md】→ 详细计算方法
    ├── 【错误预防与调试.md】→ 错误案例分析
    ├── 【最佳实践.md】→ 设计原则
    └── 【案例库.md】→ 完整实战案例
    ↓
生成结果
    ↓
保存到文件
```

## 四、内容迁移检查清单

### 4.1 从 Skill 迁移到文档的内容

| Skill 中的内容 | 应该迁移到 | 原因 |
|---------------|-----------|------|
| 详细的子表处理方案 | 【案例库.md】 | 是完整的案例 |
| 错误案例分析 | 【错误预防与调试.md】 | 是知识讲解 |
| 最佳实践原则 | 【最佳实践.md】 | 是设计原则 |
| 详细的函数说明 | 【格式规范.md】 | 是格式规范 |
| marks计算详细步骤 | 【位置计算指南.md】 | 是计算方法 |

### 4.2 Skill 中保留的内容

| 内容 | 保留原因 |
|------|---------|
| 四步强制流程 | 执行核心 |
| 输出要求 | 执行规范 |
| 禁止事项 | 执行红线 |
| 检查清单 | 执行确认 |
| 常用公式速查（极简） | 快速参考 |
