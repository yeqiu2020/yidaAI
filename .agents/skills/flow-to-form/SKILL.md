## 🚨 生成规则（每次调用时必须严格遵守）

1. **严格按照流程图里的内容生成表单，不能多也不能少，表单名字也不能改**
   - 只生成流程图中实际存在的表单（带📄或▶️图标的节点）
   - 表单名称必须与流程图中完全一致，禁止修改
   - 禁止根据主题进行泛化补充，即使你认为"这个系统应该还有XXX表单"，只要流程图中没有，就不能添加
   - 流程图中有几个表单，字段清单中就有几个表单，数量必须完全一致

2. **严格按照流程图主线顺序生成模块，不得打乱顺序**
   - **优先按照流程图中的中文大写序号排序**：模块上有"一、二、三..."或"(一)(二)(三)..."等中文序号时，严格按序号顺序生成
   - **🚨 识别流程图的排列方式（蛇形/S形顺序）**：流程图通常蛇形排列——第一行从左到右，第二行从右到左，以此类推。**必须按实际视觉布局的蛇形路径读取，禁止简单地"从左到右、从上到下"**（详细示例见 [references/常见问题与解决方案.md](references/常见问题与解决方案.md) 问题4）
   - 如果没有中文序号，则按照流程图中最粗的线条（主线）顺序排列模块，从中心节点开始，按顺时针或从左到右识别
   - 模块顺序必须与流程图视觉呈现的顺序一致

   **中文大写序号排序规则**：
   | 序号类型 | 示例 | 排序依据 |
   |---------|------|---------|
   | 中文数字 | 一、二、三、四、五、六、七、八、九、十 | 按照中文数字顺序 |
   | 中文括号 | (一)(二)(三) | 按照括号内数字顺序 |
   | 阿拉伯数字 | 1. 2. 3. | 按照数字大小 |

   **注意**：如果同时存在多级序号（如"一、"下有"(一)"），先按一级序号排序，再按二级序号排序

3. **严格按照流程图的模块分组生成，禁止自定义分组**
   - 必须严格按照流程图现成的模块分组（如"一、基础信息"、"二、库存管理"等）
   - **禁止**根据"表单功能和属性"进行自定义分组；表单不得跨模块移动或重新归类
   - 模块数量和名称必须与流程图完全一致；若流程图没有明确分组（极少数情况），每个表单独立成一节

4. **流程图只记录关键字段，将表单内的关键字段原样生成到表单内，并按常规情况进行字段拓展添加**
   - 提取流程图中"关键字段"节点下的字段，原样保留
   - 在流程图字段基础上，根据业务逻辑合理拓展必要的字段
   - **所有字段必须标注宜搭组件类型**，不允许出现无类型标注的字段
   - 通过关联表单被填充的字段统一标注为【单行文本】，填充规则写在关联字段说明中（`关联-->目标表单；填充：当前字段=源字段`）

5. **其他内容都生成到规则清单内，规则清单可以进行拓展**
   - 状态流转、业务规则、自动化规则、消息提醒、聚合表、报表等全部放在规则清单
   - 规则清单可以根据业务常识进行合理拓展

## 🚨 核心概念辨析（必须严格遵守）

### 基础档案 vs 业务数据

**这是最容易混淆的概念，必须严格区分！**（详细案例见 [references/概念混淆案例分析.md](references/概念混淆案例分析.md)）

| 对比维度 | 基础档案（普通表单） | 业务数据（流程表单/业务记录） |
|---------|---------------------|------------------------------|
| **本质** | 静态主数据 | 动态业务记录 |
| **数据特点** | 相对稳定，变更少 | 频繁变动，随业务实时更新 |
| **典型示例** | 产品信息、客户信息、供应商信息、仓库信息、员工信息 | 采购订单、销售订单、入库单、出库单、库存记录、收款记录 |
| **包含字段** | 描述性属性（名称、规格、型号、联系方式等） | 交易数据（数量、金额、日期、状态等） |
| **更新方式** | 人工维护，直接修改 | 通过业务流程自动生成和更新 |

### 常见概念混淆组合

| 基础档案（❌ 不应包含库存/财务字段） | 业务数据（✅ 应独立管理） | 混淆后果 |
|-----------------------------------|------------------------|---------|
| **产品信息** | 库存信息/库存记录 | 无法管理多仓库库存，库存计算混乱 |
| **客户信息** | 客户账户/应收记录 | 财务数据与基础档案耦合，难以扩展 |
| **供应商信息** | 供应商账户/应付记录 | 同上 |
| **仓库信息** | 库存明细/库位记录 | 无法追踪具体库存分布 |
| **员工信息** | 考勤记录/薪资记录 | 人事档案与业务数据混淆 |

### 概念辨析检查清单（生成字段前必须完成）

对于每个基础档案表单（产品/客户/供应商/仓库/员工等），必须回答：

```
☐ 1. 这个表单是否包含"数量"、"金额"、"余额"、"库存"类字段？
    - 如果有 → ❌ 错误！正确做法：通过聚合表计算，或创建独立的业务表单

☐ 2. 这个表单是否有字段表示"当前状态"且会频繁变更？
    - 需确认：是描述性状态（如产品启用/停用）还是业务状态（如在库/借出）
    - 业务状态不应该在基础档案中

☐ 3. 这个表单是否有字段需要通过其他表单汇总计算？
    - 如果有 → ❌ 错误！基础档案不应该存储计算字段，通过聚合表或公式实时计算

☐ 4. 一个基础档案记录是否可能对应多个业务记录？
    - 如果是 → 基础档案中不应该包含业务数据
    - 示例：一个产品可以存放在多个仓库 → 产品信息不应该有"当前库存"字段

☐ 5. 流程图中是否有独立的业务模块来管理这类数据？
    - 如果有 → 严格按照流程图生成独立表单，不合并到基础档案
```

错误/正确的字段示例（产品信息 vs 库存信息）详见 [references/常见问题与解决方案.md](references/常见问题与解决方案.md) 问题2。

### 业务规则生成原则

**🚨 重要：业务规则不应该更新基础档案的业务数据字段**

- ❌ 错误：`采购入库 → 更新产品信息.当前库存`（更新了基础档案）
- ✅ 方案A：通过聚合表计算库存（推荐），如 `当前库存 = SUM(入库数量) - SUM(出库数量) ± SUM(盘点差异)`
- ✅ 方案B：更新独立的库存信息表（如果流程图中有）
- ✅ 方案C：记录业务流水（入库记录等），库存通过聚合表实时计算

完整示例见 [references/常见问题与解决方案.md](references/常见问题与解决方案.md) 问题2。

## 何时使用此 Skill

当用户上传业务流程图、思维导图或系统架构图时，使用本 Skill 自动解析并生成：
1. **表单字段清单** - 用于生成宜搭 JSON 表单配置
2. **业务规则清单** - 用于指导后续手动开发（公式、关联表单、业务规则、自动化规则、消息提醒、聚合表、报表等）

## 输入要求

用户需提供：
- 业务流程图/思维导图截图（PNG/JPG 格式）
- 系统名称（如：仪表管理系统、出入库管理系统等）
- 版本号（可选，默认 1.0.0）

## 输出规范

### 输出文件结构

```
{用户指定目录}/
├── 字段清单.md      # 表单字段定义
└── 规则清单.md      # 业务规则定义
```

**命名规则**：文件直接命名为 `字段清单.md` 和 `规则清单.md`，不加系统名称前缀；输出路径使用用户指定的目录。

> 📄 完整 Markdown 模板（含字段清单/规则清单全量格式）见 [references/输出格式规范.md](references/输出格式规范.md)；完整输出样例见 [references/输出示例-仪表管理.md](references/输出示例-仪表管理.md)。

### 字段清单速查表

**字段说明格式规范**（只有以下4类字段需要填写字段说明，其他字段留空或填"-"）：

| 字段类型 | 字段说明格式 | 示例 |
|---------|-------------|------|
| **流水号** | `自动生成，前缀：XXX，示例：XXXyyyyMMdd001` | 自动生成，前缀：CP，示例：CP20260702001 |
| **关联表单** | `关联-->目标表单名称`（如有填充规则，用 `；填充：当前字段=源字段` 追加） | 关联-->产品信息；填充：规格型号=规格型号，单位=单位 |
| **数值** | `X位小数，单位：XXX` | 2位小数，单位：元 |
| **下拉单选/多选** | `选项值1/选项值2/选项值3` | 启用/停用 |

> 注：被填充字段的说明列填写自身属性，不再写填充信息。填充规则统一写在关联字段说明中。旧格式 `填充-->XXX.XXX` 仍被兼容。公式计算字段填写 `公式计算，计算逻辑`。

**字段状态**（普通=宜搭NORMAL / 只读=READONLY / 隐藏=HIDDEN）自动判定规则：
- **只读**：创建人、创建时间、被填充字段、公式计算字段
- **普通**：流水号、其他所有字段
- **⚠️ 重要**：流水号字段状态统一为"普通"（不是"只读"），便于测试时手动输入编号

**是否必填**：所有字段默认**非必填**（便于前期测试数据）；流水号、创建人、创建时间等系统字段**永不必填**。

**⚠️ 重要说明**：宜搭流程表单会自动记录审批相关信息（审批人、审批时间、审批意见等）和单据状态，**不需要在表单字段中添加审批相关字段**。

**格式硬性要求**：
1. 使用 Markdown 标准语法（`##`/`###` 标题），**禁止**使用缩进（4个空格）——缩进会被解析为代码块产生灰色背景框
2. 所有字段必须使用表格展示：字段名称、字段类型、字段状态、是否必填、字段说明五列齐全
3. 每个表单后必须标注「普通表单」或「流程表单」；流程表单分主表和子表分别列出
4. **所有字段必须标注宜搭组件类型**（可用类型：单行文本、多行文本、数值、日期、日期时间、下拉单选、下拉多选、关联表单、成员、部门、附件、图片、流水号）
5. **只列出流程图中实际存在的表单，禁止编造**

### 规则清单速查表

**组织方式**：以表单为主体分组，每个表单的所有规则集中在一个章节下；模块层级与字段清单对应；聚合表、报表、数据联动规则、审批流程等全局规则放附录。

**规则类型标识**：

| 规则类型 | 标识符号 | 说明 | 记录内容 |
|---------|---------|------|---------|
| 关键字段更新 | 🔄 | 关键字段值更新规则 | 记录关键字段（如状态字段）的更新逻辑，以及该更新对其他表单的影响 |
| 公式规则 | 🔢 | 表单内字段计算公式 | 只记录字段之间的计算公式，不记录自动生成、选项值等非计算类内容 |
| 业务规则 | 📋 | 跨表单数据更新规则 | 当前表单操作完成后，对目标表单的数据进行增、删、改操作 |
| 自动化规则 | 🤖 | 定时/条件触发的自动化任务 | 包括：①目标表单为流程表单时的数据更新；②定时触发的任务；③条件触发的自动化操作 |

**⚠️ 不记录的内容**：
1. ❌ 流水号自动生成规则
2. ❌ 下拉选项的定义
3. ❌ 关联表单的基础配置
4. ❌ 审批流程配置（审批节点、抄送规则等）
5. ❌ 简单的填充规则（已在关联字段说明中标注）

**⚠️ 业务规则生成规范（重要！）**：
1. **禁止更新基础档案的业务数据字段**（❌ 采购入库→更新产品信息.当前库存；✅ 更新库存信息表或生成入库记录+聚合表计算）
2. **基础档案只允许更新描述性字段**（✅ 产品状态/客户等级；❌ 当前库存/预付款余额）
3. **库存/财务数据管理方式**：独立业务表单 / 聚合表实时计算（推荐） / 业务流水记录+公式计算

## 解析流程图的方法

### 步骤 1：识别模块结构

1. 识别图中的主要模块（通常用不同颜色或边框区分），每个模块对应一个业务功能单元
2. 记录模块间的关联关系（箭头指向）
3. **按照流程图主线顺序排列模块**：优先识别中文大写序号（一级：一、二、三...；二级：(一)(二)(三)；三级：1. 2. 3. 或 ① ② ③，逐级排序）；无序号时按最粗线条（主线）顺序，从中心节点顺时针或从左到右；不得根据个人理解重新排序

### 步骤 2：识别表单类型（重要 - 必须严格执行）

**🚨 这是最容易出错的环节，必须逐个检查，禁止凭经验判断！**

#### 图标识别标准

| 表单类型 | 图标颜色 | 图标形状 | 用途说明 |
|---------|---------|---------|---------|
| **普通表单** | 🔵 蓝色/灰色 | 📄 文档图标 | 基础数据维护、档案管理 |
| **流程表单** | 🟢 绿色 | ▶️ 播放图标（带三角形） | 业务审批、需要工作流 |

#### 标准识别流程

```
步骤1：逐个扫描所有表单节点
步骤2：记录每个表单的图标特征（颜色：蓝/灰=普通，绿=流程；形状：文档=普通，播放三角=流程）
步骤3：建立表单类型清单 | 表单名称 | 图标颜色 | 判定结果 |
步骤4：交叉验证（统计普通/流程表单数量，检查遗漏或误判）
步骤5：生成字段前最终确认（逐个比对表单名称和类型，确保与流程图完全一致）
```

#### ⚠️ 重要规则（严格执行）

1. **只生成流程图中实际存在的表单，绝对禁止添加流程图之外的表单**
2. 只有带图标的节点才是表单；不要编造流程图中不存在的表单
3. 每个表单必须在清单中标注类型：「普通表单」或「流程表单」；表单名称必须与流程图中完全一致
4. **禁止根据主题进行泛化补充**；**严格一对一映射**：流程图有几个表单，字段清单就有几个表单
5. **图标识别要点**：仔细观察每个节点的图标样式，**禁止根据业务类型推测表单类型（如"订单"不一定是流程表单，必须看图标）**

#### 🚨 防遗漏检查机制（必须严格执行）

**步骤A：建立模块-表单映射表**（每个模块列出 `表单名称 - 图标类型`）

**步骤B：逐个模块扫描检查**
1. 从上到下扫描垂直排列的模块；按蛇形排列的实际方向从左到右/从右到左扫描
2. 边界检查：特别注意每个模块的第一个和最后一个表单
3. 数量核对：统计每个模块的表单数量，与流程图实际数量对比

**步骤C：交叉验证清单**

| 验证项 | 操作方法 | 通过标准 |
|-------|---------|---------|
| 数量验证 | **只统计带📄或▶️图标的节点** | 与生成清单数量完全一致 |
| 名称验证 | 逐个比对表单名称 | 100%匹配，无增删改 |
| 顺序验证 | 按流程图视觉顺序检查 | 与流程图呈现顺序一致 |
| 类型验证 | 检查每个表单的图标类型 | 普通/流程表单判定正确 |

**⚠️ 重要提醒**：流程图中包含多种节点类型（字段、流程、规则说明等），**只有带📄（文档图标）或▶️（播放图标）的节点才是表单**，其他节点不计入表单数量统计。

**步骤D：生成前最终确认**
1. 流程图中共有多少个带📄或▶️图标的表单节点？____个
2. 我已识别的表单数量是多少？____个；两者数量是否一致？是/否
3. 字段节点、流程节点、规则说明节点是否被错误识别为表单？是/否
4. 是否有任何表单我还不确定？是/否
5. 只有全部通过才可以生成，否则必须重新检查流程图

> 常见遗漏场景及预防措施详见 [references/常见问题与解决方案.md](references/常见问题与解决方案.md) 问题3；逐项书面自检模板见 [references/生成检查清单.md](references/生成检查清单.md)。

#### 流程表单字段说明

**⚠️ 重要**：宜搭流程表单会自动记录审批相关信息（审批人、审批时间、审批意见）和流程状态（草稿/进行中/已完成等），**不需要在表单字段中添加这些系统字段**，只需关注业务字段。

### 步骤 3：提取表单字段

1. 识别表单下的"关键字段"节点，提取字段名称，原样保留
2. 识别子表：带有【子表】前缀的节点
3. 识别选项字段：字段下有子节点的为下拉选项，选项值以下拉选项形式标注
4. 在流程图字段基础上，根据业务逻辑合理拓展必要的字段
5. 字段下的说明文字不提取到字段清单，整合到规则清单
6. **🚨 概念辨析检查（必须执行）**：对每个基础档案表单，完成上文【概念辨析检查清单】，确认不含"数量/金额/余额/库存"类业务数据字段、不含汇总计算字段；若流程图中有独立业务模块管理这类数据，严格按流程图生成独立表单

### 步骤 4：识别状态流转

1. 找出所有状态字段（通常包含"状态"、"阶段"等关键词）
2. 列出所有状态值（字段下的子节点）
3. 记录状态之间的流转路径

### 步骤 5：识别业务规则

1. 找出"自动生成"、"同步"、"更新"、"自动提醒"等关键词
2. 记录触发条件和执行动作；识别关联表单操作
3. 将字段说明文字整合为业务规则；**规则清单可以进行拓展**，补充合理的业务规则
4. **🚨 业务规则生成检查（必须执行）**：
   - 目标表单是基础档案时，只允许更新描述性属性（如产品状态、客户等级）
   - ❌ 禁止更新基础档案的业务数据字段（如当前库存、预付款余额）
   - 优先考虑替代方案：聚合表计算（推荐）> 更新独立业务表单 > 记录业务流水

### 步骤 6：识别子表结构

1. 找出【子表】前缀的节点，提取子表名称
2. 提取子表字段（子表下的子节点）

| 日期、时间 | 日期/日期时间 | 如：创建日期、审批时间 |
| 数量、金额、价格 | 数字 | 如：采购数量、订单金额 |

## 执行指令

当用户上传流程图后，按以下步骤执行：

1. **分析图片内容（关键步骤 - 必须严格执行）**
   - 识别图中的所有模块和节点，提取文字信息，理解模块间关系
   - **🚨 防遗漏：逐个模块建立表单清单**（从上到下、按实际排列方向扫描，建立模块-表单映射表，如 `销售管理 ├─ 销售报价 - ▶️流程表单 ...`，注意每个模块的第一个表单最容易遗漏）
   - **逐个检查每个表单节点的图标类型**（🚨 禁止凭经验判断）：绿色背景+三角形=流程表单；蓝色/灰色文档图标=普通表单
   - **建立表单类型识别表**（必须书面记录）：`| 序号 | 表单名称 | 图标颜色 | 图标形状 | 判定类型 |`
   - 统计表单总数、普通表单数量和流程表单数量，确保不遗漏也不添加
   - **按照流程图主线顺序记录模块**（优先中文大写序号，其次最粗线条，顺时针或从左到右）
   - **🚨 强制自检（必须完成，不可跳过）**：
     - ☐ 生成的表单列表与流程图完全一致，数量相同
     - ☐ 模块顺序与流程图主线顺序一致
     - ☐ 表单类型（普通/流程）与图标一致，已逐个确认图标颜色
     - ☐ 已建立表单类型识别表
     - ☐ 已对每个模块进行从上到下/从左到右的完整扫描，检查了第一个和最后一个表单
     - ☐ 流程图中带📄或▶️图标的表单总数：___个，已识别表单数：___个，两者一致
     - ☐ 未将字段节点、流程节点、规则说明节点错误识别为表单

2. **生成字段清单（严格遵循）**
   - **只包含步骤1中列出的表单，表单名称与流程图完全一致**
   - 提取"关键字段"节点下的字段原样保留，并根据业务逻辑合理拓展
   - 识别主表和子表，标注关联关系
   - **标注字段类型（强制要求）**：每个字段都必须标注宜搭组件类型，参考【字段类型推断规则】；常用默认：名称类→【单行文本】、地址/描述→【多行文本】、电话→【单行文本】、规格型号→【单行文本】、供应商/客户→【单行文本】
   - **🚨 概念辨析检查（必须执行）**：对每个基础档案表单完成【概念辨析检查清单】，确保不含业务数据字段（库存、金额、余额等）
   - **自检**：检查是否有流程图之外的表单被添加、表单名称是否正确；**逐个检查每个字段是否都有组件类型标注**；**检查基础档案是否包含业务数据字段，如有必须移除或调整**

3. **生成规则清单**
   - 识别业务规则关键词、状态流转逻辑、自动化场景、审批流程
   - **🚨 业务规则生成检查（必须执行）**：确认业务规则不更新基础档案的业务数据字段；库存/财务数据通过聚合表或独立业务表单管理
   - **规则清单可以进行拓展**，补充合理的业务规则

4. **输出文件**
   - 生成 `字段清单.md` 和 `规则清单.md`（直接命名，不加前缀），在文件末尾添加文件链接
   - **最终确认**：表单数量和名称与流程图完全一致；基础档案不含业务数据字段；业务规则不直接更新基础档案的业务数据

## 注意事项

1. **字段确认标记**：图中字段不明确标注 `[待确认]`；字段类型不确定标注 `[类型待确认]`
2. **规则完整性**：尽量覆盖图中所有可见的业务逻辑；隐含规则根据业务常识补充并标注 `[推测]`
3. **版本管理**：每次更新时递增版本号，在更新说明中记录变更内容
4. **宜搭兼容性**：字段命名符合宜搭规范（避免特殊字符）；关联表单引用使用正确的表单名称；下拉选项使用 `/` 分隔
