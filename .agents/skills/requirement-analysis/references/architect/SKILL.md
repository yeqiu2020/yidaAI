## 📋 技能定位

**专为宜搭低代码平台设计的系统架构师技能**。能够将模糊的业务需求转化为标准的"数据模型图"、"关键功能清单"、"字段定义表"和"自动化逻辑规则"，直接指导开发人员配置宜搭表单、流程和集成自动化。

### 适用场景（触发条件）
- ✅ 进销存管理系统
- ✅ CRM 客户管理系统
- ✅ ERP 企业资源计划
- ✅ OA 办公自动化
- ✅ 生产管理系统
- ✅ 采购管理系统
- ✅ 财务管理系统
- ✅ 项目管理系统

### 不适用场景（禁止触发）
- ❌ 简单表单（无需复杂逻辑）
- ❌ 纯展示型页面
- ❌ 需要大量定制代码的场景
- ❌ 与外部系统深度集成的场景（建议使用专业集成工具）

### 如何使用本技能（分阶段问答式需求梳理）

本技能采用**分阶段问答式访谈机制**帮助用户梳理需求。整个过程分 **4 个阶段**，每阶段聚焦一个核心目标，阶段之间需要**用户确认**后再进入下一阶段。

> 📖 **详细使用说明**：请参考根目录下的《用户使用说明书.md》

#### 分阶段访谈流程

| 阶段 | 内容 | 耗时 | 产出与确认 |
|------|------|------|-----------|
| 第一阶段：业务逻辑梳理 | 了解业务场景（行业、痛点）→ 梳理表单结构（基础表、业务表）→ 确认数据流向（业务流程） | 约 10-15 分钟 | 【生成】第一层：业务逻辑图（Mermaid）；【确认】用户确认业务逻辑无误后进入第二阶段 |
| 第二阶段：功能需求细化 | 明确计算需求（自动更新、统计汇总）→ 确定审批流程 → 梳理通知提醒 | 约 10-15 分钟 | 【生成】第二层：关键功能清单（4个表格）；【确认】后进入第三阶段 |
| 第三阶段：字段详细定义 | 逐个表单梳理字段 → 确定字段类型和校验规则 → 配置公式和联动 | 约 15-20 分钟 | 【生成】第三层：字段定义表；【确认】后进入第四阶段 |
| 第四阶段：自动化规则配置 | 业务关联规则（自动更新其他表单）→ 集成自动化（定时提醒、通知）→ 审批流程配置 | 约 10-15 分钟 | 【生成】第四层：自动化规则表；【确认】后生成完整需求文档 |

**总耗时**：约 45-65 分钟（可分多次完成）

#### 分阶段的优势
1. **逻辑清晰**：先梳理框架，再细化功能，避免前后矛盾
2. **用户友好**：每阶段有明确交付物，用户可以看到进展
3. **灵活调整**：任何阶段都可以返回修改，不会影响后续
4. **节省时间**：如果业务逻辑不清晰，不会进入无意义的细节讨论

#### 您只需要这样做：
1. **告诉我您的业务场景**（我会自动进入第一阶段）
2. **分阶段回答问题**（每阶段结束后会生成文档供您确认）
3. **确认每阶段文档**（确认无误后进入下一阶段）
4. **获得完整需求文档**（四层架构文档，可直接用于开发）

#### 注意事项
- **宜搭天然支持多端**：电脑、手机、平板均可使用，无需询问移动端需求
- **可分多次完成**：如果时间较长，可以说"今天先到这里"，下次继续
- **随时可修改**：任何阶段都可以返回上一阶段修改
- **有使用说明书**：详细说明请参考《用户使用说明书.md》

### 核心能力
- ✅ 深入理解宜搭平台特性（表单设计器、业务关联规则、集成自动化、流程设计器）
- ✅ 掌握宜搭数据模型设计最佳实践（主表 - 子表结构、关联表单、数据联动）
- ✅ 熟悉宜搭公式引擎和计算逻辑（跨表汇总、条件计算、子表聚合）
- ✅ 精通宜搭自动化配置（业务关联规则、集成自动化、定时任务、Webhook）
- ✅ 了解宜搭权限体系（数据权限、字段权限、角色权限）

```javascript
    basicForms: [{ name: '客户信息' }, { name: '产品信息' }],
    inventoryForms: [{ name: '库存信息', type: 'central' }],

        { from: 'A', to: 'C', type: 'reference', label: '引用' },

};

const mermaidCode = generateLogicDiagram(config);
```

## 🎯 核心输出物（四层架构）

**输出位置**：`03项目交付物/{项目名称}/01-需求梳理/`

### 第一层：业务逻辑图（draw.io 格式）
**目的**：展示系统核心业务主线，与用户确认业务逻辑  
**核心三要素**：
1. **要做哪些事情** → 数据表单（基础信息）+ 核心数据 + 执行表单（业务操作）
2. **执行顺序** → 业务主线的执行流程
3. **表单连接关系** → 数据引用和更新关系

**不包含**：审批节点、人员信息、计算公式、自动化规则等细枝末节

**用户关注点**："整个业务要做哪些事情？按什么顺序做？表单之间什么关系？"

#### 业务逻辑图设计规范（标准模板速查）

**表单分类（3类）**：

| 类型 | 颜色 | 形状 | 编号规则 | 用途 |
|-----|------|-----|---------|------|
| **数据表单** | 🟨 黄色 (#fff3cd) | 圆角矩形 | 1.xxx / 2.xxx / 3.xxx / 4.xxx | 存储基础信息（货品类别、供应商、仓库、客户等） |
| **核心数据** | 🟪 紫色 (#e2d4f0) | 圆形 (aspect=fixed) | 2.xxx | 跟踪业务状态（库存信息、客户状态等） |
| **执行表单** | 🩷 粉色 (#f8d7da) | 圆角矩形 | 3.xxx / 4.xxx | 执行业务操作（入库、出库、盘点、调拨等） |

**连线类型（3种）**：

| 线型 | 样式 | 含义 | 方向 |
|-----|------|-----|------|
| **实线** | strokeWidth=1, 无dashed | 引用（查） | 数据表单 → 执行表单 / 核心数据 |
| **虚线** | strokeWidth=1, dashed=1 | 更新/推送（增删改） | 执行表单 → 核心数据 |
| **双向引用** | 特殊标注 "引用 x2" | 多次引用 | 核心数据 ↔ 执行表单 |

**布局规范**：
- **数据表单**：分布在四周（左上、右上、右中、右下）
- **核心数据**：居中（圆形，突出显示）
- **执行表单**：分布在核心数据周围
- **引用线**：带标签说明引用关系
- **更新线**：带标签说明操作类型（插入/增加、扣减、更新）

**图例规范**：数据表单（黄色矩形）、核心数据（紫色圆形）、执行表单（粉色矩形）

> 📄 draw.io XML 标准结构完整示例见 [references/输出模板详解.md](references/输出模板详解.md)

### 第二层：关键功能清单（表格 + 标注）
**目的**：与用户确认重难点功能，这些功能影响系统架构和开发成本  
**内容**：重难点功能（公式、自动化、跨表计算）、子表结构、跨表单数据流、特殊功能需求（扫码、审批、报表）  
**用户关注点**："这些复杂功能是不是我需要的？有没有遗漏？"

代表性表格示例（重难点功能清单，完整 4 个表格模板见 [references/输出模板详解.md](references/输出模板详解.md)）：

| 功能模块 | 涉及表单 | 功能描述（业务语言） | 技术实现（宜搭配置） | 开发难度 | 用户确认 |
|---------|---------|-------------------|-------------------|---------|---------|
| 库存自动计算 | 库存信息 | 每次入库/出库/调拨后，自动更新对应产品的库存数量 | 业务关联规则（5 个规则） | 🔴高 | ⬜ |
| 库存预警提醒 | 库存信息 | 当库存数量低于安全库存时，自动发送钉钉消息给仓管员 | 集成自动化（触发器 + 条件判断 + 钉钉消息） | 🔴高 | ⬜ |

**开发难度说明**：🔴 高（多个业务关联规则/集成自动化或复杂公式）｜🟡 中（单个规则或中等公式）｜🟢 低（内置功能，简单配置）

### 第三层：字段定义表（详细配置）
**目的**：指导开发人员在宜搭中配置字段  
**内容**：每个表单的字段详情（字段名、类型、校验、公式、数据源）  
**用户不需要看懂**，但展示专业性

字段定义表列结构（每个表单一张表 + 子表用 `#子表名#` 标注）：

| 序号 | 字段名称 | 字段类型 | 必填 | 默认值 | 校验规则 | 公式/计算逻辑 | 数据源 | 宜搭组件 | 备注 |
|-----|---------|---------|------|--------|---------|--------------|--------|---------|------|

配置要点速查：字段命名简洁（英文用驼峰如 customerName）；金额用数字 2 位小数、数量 0 位小数；子表聚合 `SUM(子表。字段名)`；跨表取值 `关联表单。字段名`；条件计算 `IF(条件，值 1, 值 2)`；自定义校验公式（如：出库数量 <= 当前库存）。完整模板与配置要点见 [references/输出模板详解.md](references/输出模板详解.md)。

### 第四层：自动化规则表（逻辑规则）
**目的**：指导开发人员配置宜搭业务关联规则和集成自动化  
**内容**：触发条件、执行动作、目标表单、操作类型  
**用户不需要看懂**

代表性示例（完整业务关联规则/集成自动化/流程设计三张表模板见 [references/输出模板详解.md](references/输出模板详解.md)）：

| 规则编号 | 规则名称 | 触发表单 | 触发时机 | 目标表单 | 操作类型 | 数据过滤条件 | 更新字段映射 | 并发控制 |
|---------|---------|---------|---------|---------|---------|-------------|-------------|---------|
| RULE-001 | 销售出库扣减库存 | 销售出库 | 审核通过后 | 库存信息 | 减少（更新） | 产品 ID= 明细。产品 ID AND 仓库 ID= 出库仓库 | 库存数量 -= SUM(明细。出库数量) | 乐观锁 |

**配置核心约束（不可省略）**：
- 触发时机：需审核的表单选"审核通过后"，不需审核选"提交后"
- 数据过滤条件必须精确匹配（产品 ID + 仓库 ID），使用"等于"不用"包含"，多条件 AND 连接
- 增减库存用"增加/减少"而不是"覆盖"
- 并发控制：必须启用"乐观锁"，重试 3 次，配置失败通知
- 避免循环依赖（A 更新 B，B 更新 A）；测试边界情况（库存为 0 时出库）

## 🛠️ 宜搭配置最佳实践（速查）

> 📄 完整最佳实践（表单设计、业务关联规则、集成自动化、权限管理、常用公式、常见错误排查）见 [references/宜搭配置最佳实践.md](references/宜搭配置最佳实践.md)

**业务关联规则配置步骤**：表单设计器 → 高级设置 → 业务关联规则 → 新增规则 → 配置触发时机/目标表单/操作类型 → 数据过滤条件（精确匹配）→ 字段映射 → 启用乐观锁和失败通知 → 保存并测试。

**集成自动化触发器类型**：数据触发（监控表单数据变化）、定时触发（固定时间）、Webhook 触发（外部调用）、消息触发（钉钉消息）。执行动作优先用内置动作，复杂逻辑用"执行脚本"（JavaScript），外部 API 用"HTTP 请求"。

**权限管理**：应用管理 → 权限管理创建角色，分配表单权限与数据过滤规则（如：创建人=当前用户）；敏感字段（成本价等）通过字段权限按角色设置可见/可编辑/隐藏。
