### 五、门禁规则

| Smoke 类型 | 归档门禁 | 说明 |
|-----------|---------|------|
| 核心 Smoke | 必须 100% PASS | 应用核心能力必须稳定 |
| 负面 Smoke | 必须 100% PASS | 异常处理必须稳定 |
| 专项 Smoke | 按修改模块执行，必须 PASS | 修改对应模块后必跑 |
| 工具链 `npm test` | 必须 PASS | AI 工具链本身必须健康 |
| SKIP 率 | ≤ 20% | 禁止大量 SKIP 规避测试 |
| 任何 FAIL | 不得归档 | 必须修复后重新执行 |

### 六、选取原则

- P0 优先
- 用户路径优先（用户最常用的表单和操作）
- 公共能力优先（数据提交、公式计算、关联填充等）
- 回归价值高（历史上出过问题的场景优先）
- 可稳定执行（前置条件清晰，测试数据可复现）
- 负面 Smoke 占比 ≥ 20%
- 规模 30-40 项，不无限膨胀
- 工具链 Smoke 至少包含 `npm test` 一项

### 七、工具链 Smoke 说明

> AI 工具链本身的健康是应用测试的前提，必须作为 Smoke 的一部分。

| 命令 | 覆盖范围 | 执行频率 | 通过标准 |
|------|---------|---------|---------|
| `npm test` | 全部工具链单元测试 | 每次归档前 | 所有测试 PASS，覆盖率达标 |
| `npm run test:core` | 核心模块（lib/core） | 修改核心模块后 | 所有测试 PASS |
| `npm run test:features` | 特性模块（lib/features） | 修改特性模块后 | 所有测试 PASS |

**工具链 Smoke 失败处理：**
- 如果 `npm test` FAIL，必须先修复工具链问题，再进行应用层测试
- 工具链问题归类为"工具链层"修复，可直接编辑 Skill 脚本
- 修复后必须重新执行 `npm test` 确认 PASS
