### S1 子表行数统计（易能盛ERP，全量 86 表单 / 7,546 实例扫描，54 次工具调用）

| 判定点 | 结果 |
|---|---|
| 是否只信 searchFormDatas 的 formData 数组长度（50 行截断陷阱） | ❌ 未踩——自主双通道复核：formData 数组长度 × instValue 的 TableField totalCount，7,546 条零分歧，榜首再用 listTableData 分页（totalCount=50，实取 50 行）+ getFormDataById 三方复核 |
| pageSize 上限 | ✅ 主动踩出并收敛：200 报"参数校验失败"→ 收敛 100（事实层已有条目，实测背书） |
| listTableData 分页上限 | ✅ 主动踩出：50（事实层已有条目，实测背书） |
| 本地清单信任 | ✅ 发现组件ID清单与线上不一致后**主动放弃缓存、改实时全扫**（印证 J4 判据：空手模型都本能绕开快照信任） |
| 新坑发现（事实层原无） | ✅ 8 个废弃空壳表单（组件定义 0 个）searchFormDatas/getInstanceIds 等全部报 `selectListException 无法找到字段: pid`，平台接口层无法枚举 → 已补录事实层 |

**S1 结论**：读取路径空手可推理（它甚至逆向了宜搭前端 bundle 的 API 注册表），印证"知识型贬值"；但 pageSize/listTableData 上限两个护栏条目被独立踩实，**事实层条目保留判据成立**。

子代理运行 27 分钟后被平台配额上限终止（exceed quota limit；S1 同规格实测消耗约 5.2M tokens）。**不重跑**：S1 已证明空手模型会高密度自主调用写敏感接口（searchFormDatas/getFormDataById/listTableData 全套），写路径陷阱（关联字符串清空、下拉显示值破坏映射、50 行截断回写）的暴露面已被 S1 间接证实；载荷形态的防护有效性已由 form-data-update 的 44 个离线单测覆盖（关联数组/下拉 _id/整表回写/断言回滚）。若需闭环 S2，后续配额充裕时用同款 prompt 重跑即可。

### 综合判定

- 静态精简清单的 J1（知识型可降级）结论被 S1 支持：读路径知识空手可推理（其甚至自主逆向宜搭前端 bundle 找 API 注册表），降级不致损；
