# 概念混淆案例分析

> 版本: 1.0.0
> 创建日期: 2026-03-11
> 更新说明: 初始版本 - 记录从流程图生成表单时常见的概念混淆案例

---

## 概述

本文档记录了从业务流程图生成宜搭表单时，最容易出现的概念混淆案例。这些案例都源于对业务数据的理解偏差，导致生成的表单结构不合理，影响后续系统使用。

**使用方式**：在每次生成表单字段前，对照本文档检查是否存在类似的概念混淆问题。

## 一、基础档案 vs 业务数据混淆

### 1.1 产品信息与库存信息混淆

#### ❌ 错误案例

**场景**：进销存管理系统，流程图中有"基础信息"模块包含"产品信息"表单。

**错误做法**：
```
产品信息表（错误）：
├─ 产品编号【流水号】
├─ 产品名称【单行文本】
├─ 规格型号【单行文本】
├─ 当前库存【数值】← ❌ 错误！
├─ 安全库存【数值】← ❌ 错误！
├─ 存放仓库【关联表单】← ❌ 错误！
├─ 在库数量【数值】← ❌ 错误！
└─ ...
```

**错误原因**：
1. 产品信息是**基础档案**，应该只包含产品的静态属性
2. 库存数据是**业务数据**，会随采购、销售、盘点等业务实时变动
3. 一个产品可能存放在多个仓库，"当前库存"字段无法支持多仓库管理
4. 安全库存是库存管理策略，不应该与产品信息耦合

#### ✅ 正确做法

**方案A：产品信息为纯基础档案（推荐）**
```
产品信息表（正确）：
├─ 产品编号【流水号】
├─ 产品名称【单行文本】
├─ 产品类别【下拉单选】
├─ 规格型号【单行文本】
├─ 单位【下拉单选】
├─ 参考采购价【数值】
├─ 参考销售价【数值】
├─ 产品状态【下拉单选：启用/停用】
└─ ...

库存信息表（如果流程图中有独立模块）：
├─ 库存编号【流水号】
├─ 仓库【关联表单-->仓库信息】
├─ 产品【关联表单-->产品信息】
├─ 当前库存【数值】
├─ 安全库存【数值】
└─ ...
```

**方案B：通过聚合表计算库存（如果流程图中没有库存模块）**
```
产品信息表：只包含基础属性字段

聚合表：产品库存统计
- 数据源：采购入库、销售出库、库存盘点、库存调拨
- 计算逻辑：当前库存 = SUM(入库数量) - SUM(出库数量) ± SUM(盘点差异)
- 分组字段：产品信息、仓库信息
```

#### 📋 业务规则对比

**❌ 错误规则**：
```
规则：采购入库更新产品库存
- 触发条件：采购入库审批通过
- 目标表单：产品信息 ← ❌ 错误！
- 操作内容：当前库存 = 当前库存 + 入库数量
```

**✅ 正确规则**：
```
规则1：采购入库更新库存信息（如果有独立库存表）
- 触发条件：采购入库审批通过
- 目标表单：库存信息 ← ✅ 正确！
- 操作内容：当前库存 = 当前库存 + 入库数量

规则2：产品库存统计（通过聚合表）
- 聚合表名称：产品库存统计
- 数据源：采购入库、销售出库、库存盘点
- 计算逻辑：实时计算各产品在各仓库的库存
```

### 1.2 客户信息与财务信息混淆

#### ❌ 错误案例

**场景**：CRM或销售管理系统，流程图中有"客户管理"模块。

**错误做法**：
```
客户信息表（错误）：
├─ 客户编号【流水号】
├─ 客户名称【单行文本】
├─ 联系人【单行文本】
├─ 联系电话【单行文本】
├─ 预付款余额【数值】← ❌ 错误！
├─ 已用额度【数值】← ❌ 错误！
├─ 应收金额【数值】← ❌ 错误！
├─ 最近下单日期【日期】← ❌ 错误！
└─ ...
```

**错误原因**：
1. 客户信息是**基础档案**，应该只包含客户的静态信息
2. 预付款、额度、应收金额都是**财务业务数据**，会随交易实时变动
3. 最近下单日期应该通过订单数据查询，不应该存储在客户档案中

#### ✅ 正确做法

```
客户信息表（正确）：
├─ 客户编号【流水号】
├─ 客户名称【单行文本】
├─ 客户类型【下拉单选：企业/个人】
├─ 客户等级【下拉单选：A/B/C级】
├─ 联系人【单行文本】
├─ 联系电话【单行文本】
├─ 联系地址【多行文本】
├─ 客户状态【下拉单选：启用/停用】
└─ ...

客户账户表（如果流程图中有财务管理模块）：
├─ 账户编号【流水号】
├─ 客户【关联表单-->客户信息】
├─ 预付款余额【数值】
├─ 信用额度【数值】
├─ 已用额度【数值】
├─ 应收金额【数值】
└─ ...
```

#### 📋 业务规则对比

**❌ 错误规则**：
```
规则：收款更新客户余额
- 触发条件：收款单审批通过
- 目标表单：客户信息 ← ❌ 错误！
- 操作内容：预付款余额 = 预付款余额 + 收款金额
```

**✅ 正确规则**：
```
规则：收款更新客户账户
- 触发条件：收款单审批通过
- 目标表单：客户账户 ← ✅ 正确！
- 操作内容：预付款余额 = 预付款余额 + 收款金额

聚合表：客户应收统计
- 数据源：销售订单、收款记录
- 计算逻辑：应收金额 = SUM(订单金额) - SUM(收款金额)
```

#### ❌ 错误案例

**场景**：采购管理系统，流程图中有"供应商管理"模块。

**错误做法**：
```
供应商信息表（错误）：

├─ 联系电话【单行文本】
├─ 应付金额【数值】← ❌ 错误！
├─ 已付金额【数值】← ❌ 错误！
├─ 未付金额【数值】← ❌ 错误！
└─ ...
```

**错误原因**：与"客户信息"混淆类似，应付金额属于财务业务数据。

#### ✅ 正确做法

```
供应商信息表（正确）：
├─ 供应商编号【流水号】
├─ 供应商名称【单行文本】

├─ 联系人【单行文本】
├─ 联系电话【单行文本】
├─ 合作状态【下拉单选：合作中/暂停/终止】
└─ ...

应付账款通过聚合表计算：
- 数据源：采购订单、付款记录
- 计算逻辑：应付金额 = SUM(采购金额) - SUM(付款金额)
```

员工信息表（错误）：

## 二、如何判断基础档案 vs 业务数据

### 2.1 判断标准

| 判断维度 | 基础档案 | 业务数据 |
|---------|---------|---------|
| **数据稳定性** | 相对稳定，变更频率低 | 频繁变动，随业务实时更新 |
| **数据性质** | 描述性属性 | 交易性记录 |
| **更新方式** | 人工直接修改 | 通过业务流程自动生成 |
| **一对多关系** | 一个档案对应多条业务记录 | 一条业务记录对应一个档案 |
| **时间维度** | 无时间属性 | 有时间属性（日期、月份等） |

### 2.2 快速检查清单

对于每个表单，回答以下问题：

```
☐ 1. 这个表单是否包含"数量"、"金额"、"余额"类字段？
    - 是 → 可能是业务数据，需要进一步确认
    - 否 → 可能是基础档案

☐ 2. 这个表单的数据是否会随业务操作自动更新？
    - 是 → 业务数据
    - 否 → 基础档案

☐ 3. 一个记录是否可能对应多条业务记录？
    - 是 → 不应该在基础档案中存储汇总数据
    - 否 → 可以继续

☐ 4. 这个表单是否有时间维度（如月份、日期）？
    - 是 → 业务数据
    - 否 → 基础档案

☐ 5. 流程图中是否有独立的业务模块管理这类数据？
    - 是 → 严格按照流程图生成独立表单
    - 否 → 考虑是否需要建议补充
```

## 三、常见概念混淆组合速查表

| 基础档案（❌ 不应包含业务字段） | 业务数据（✅ 应独立管理） | 混淆后果 |
|------------------------------|------------------------|---------|
| **产品信息** | 库存信息/库存记录 | 无法管理多仓库库存 |
| **客户信息** | 客户账户/应收记录 | 财务数据与档案耦合 |
| **供应商信息** | 供应商账户/应付记录 | 同上 |
| **仓库信息** | 库存明细/库位记录 | 无法追踪具体库存分布 |
| **员工信息** | 考勤记录/薪资记录 | 人事档案与业务数据混淆 |
| **资产信息** | 资产使用记录/维修记录 | 无法追踪资产历史 |
| **项目信息** | 项目进度/成本记录 | 项目档案与执行数据混淆 |
| **合同信息** | 合同执行记录/收款记录 | 合同档案与执行数据混淆 |

## 四、业务规则生成原则

### 4.1 禁止的操作

❌ **禁止更新基础档案的业务数据字段**：
- 采购入库 → 更新产品信息.当前库存
- 收款 → 更新客户信息.预付款余额
- 付款 → 更新供应商信息.应付金额
- 考勤登记 → 更新员工信息.本月出勤天数

### 4.2 推荐的操作

✅ **通过聚合表计算**：
- 产品库存 = SUM(入库) - SUM(出库) ± SUM(盘点差异)
- 客户应收 = SUM(订单金额) - SUM(收款金额)
- 供应商应付 = SUM(采购金额) - SUM(付款金额)

✅ **更新独立的业务表单**：
- 采购入库 → 更新库存信息.当前库存
- 收款 → 更新客户账户.预付款余额
- 考勤登记 → 新增考勤记录

✅ **记录业务流水**：
- 所有业务操作都生成独立的业务记录
- 通过关联查询获取汇总数据

## 五、案例分析总结

### 5.1 根本原因

1. **凭经验判断**：认为"产品表应该有库存字段"
2. **混淆概念**：不理解基础档案和业务数据的区别
3. **简化思维**：试图将所有数据放在一个表中
4. **忽视业务逻辑**：没有考虑多仓库、多期间等复杂场景

### 5.2 预防措施

1. **严格区分概念**：基础档案 = 静态属性，业务数据 = 动态交易
2. **使用检查清单**：生成字段前完成概念辨析检查
3. **参考本文档**：对照常见混淆组合进行验证
4. **考虑扩展性**：设计时考虑多仓库、多期间等场景

### 5.3 修正方法

如果发现已经混淆：

1. **识别业务数据字段**：找出基础档案中的业务数据字段
2. **创建独立业务表单**：将业务数据迁移到独立的业务表单
3. **使用聚合表替代**：通过聚合表实时计算汇总数据
4. **更新业务规则**：修改规则，使其更新正确的目标表单
5. **数据迁移**：将历史数据从基础档案迁移到业务表单
